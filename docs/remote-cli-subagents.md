# 远程 CLI 的子智能体列表入口

远程 CLI 委派现在可以出现在所属主会话顶部现有的「子智能体」下拉列表中，不增加独立卡片或第二个计数入口。

## 使用

1. 在主会话通过 `remote_agent_create`（或「协作开发」Skill）启动远程 CLI。
2. 顶部子智能体列表合并显示原生子智能体和该会话拥有的远程 CLI。
3. 点击远程条目，查看只读远程对话窗口：历史消息、工具调用、运行结果与待处理请求；窗口持续更新并支持加载较早记录。
4. 关闭详情即可回到主会话。继续任务、停止或处理权限仍使用原有远程代理工具或插件的会话管理页面。

## 设计边界

- 复用 DSH 原生列表组件，通过公开 Slot 注册机制覆盖同一个 `subagent-catalog` 条目。不是 DOM 注入，也不是新造的另一套顶部菜单。
- 原生条目的普通打开及侧栏打开仍调用原有动作。远程条目使用独立的前端展示 ID，只在视图内合并，不写入原生会话存储，不创建虚假 Agent，不触发本机模型。
- 远程详情是只读窗口，不是原生可继续输入的子会话。列表里的只读/一次性展示不限制远程工具继续向真实 CLI 发送后续任务。
- 当前合并范围是主会话直接委派的远程 CLI；原生子会话内部再次委派的远程任务暂不递归汇总。
- 关联来自创建时保存的 `owner.sessionId`，不是目录或标题匹配。没有关联记录的旧任务不会擅自认领到当前会话；可从插件原有会话管理入口查看。
- 不伪造 Token 或耗时；远程摘要尚未提供可靠的完整统计，因此该入口暂不展示这些指标。`idle` 表示空闲，不自动等同于审核通过或任务成功。
- 归档后的所属委派仍可查看保存历史；离线错误保留并显示。轮询只针对当前主会话，避免打开一个会话就连接所有已保存主机。
- 读取详情不发送提示、不重新启动 CLI，也不修改 `Task.chat`。已有 relay 的恢复只重连已存在的执行。

## 兼容性与部署

此接入依赖 DSH 原生顶部列表及公开 Slot 的 `entries`、`subscribe` 和同 ID 优先级覆盖功能。原生组件未加载时等待；不以另一个伪菜单替代。插件卸载时恢复原有贡献。

更新包含服务端的会话归属查询及客户端列表入口。需构建并安装完整插件；仅刷新旧服务端的页面不能新增接口。没有开发构建 watcher 时，不承诺自动热更新。安装后按宿主提示重新加载插件或重启应用，再刷新现有 GUI。

## 验证

单元/组件测试覆盖所属会话隔离、同 ID 去重、原生导航保留、远程展示 ID 不进入原生 API、列表注册清理、异步旧响应保护、只读详情及离线恢复。人工验收可复用只读演练，不需要修改项目文件或付费启动真实开发任务：观察已有委派即可。
