## Remote Agents 0.2.138 — 「所选 CLI 在此远程项目中不可用」会说明原因

用户在 DSH 对话里看到 “本轮运行失败 The selected CLI is not ready in this remote project”，看不出是 CLI 没装、没登录还是别的问题。

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.137 → **0.2.138** | **报错写明原因：**发消息前插件会在目标机器的项目目录里试启动所选 CLI。检查失败时，原来只报这一句，检查拿到的原因（怎么登录、"returned no models"、CLI 自己的报错）被丢掉了，CLI 不在登录 shell 的 PATH 里也是同一句。现在会接上 CLI 给的原因；找不到 CLI 时直接说找不到哪个命令（“claude was not found on this machine…”）。在插件页面里显示中文，在 DSH 对话里仍是英文原文。<br>**修好后下一条就能发：**原来检查失败的结果也会保留 30 秒，登录或装好 CLI 后马上再发还是同样报错。现在只保留检查成功的结果。 |

## Remote Agents 0.2.137 — 一轮结束那一刻读了不再变回未读，点停止后马上发的消息不再丢

修复 0.2.136 记录里「未解决」的两个问题。都只影响开启「与其他 DSH 共享会话和工作区」的机器。

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.136 → **0.2.137** | **一轮刚结束就读：** 驱动 CLI 的 DSH 每 500 毫秒向其他 DSH 报一次状态，而这一轮最后几条记录要约 100 毫秒后才另外写到主机上，所以有时「空闲」先到。旧代码上 12 次轮次结束里有 3 次是这样。这时读到的只是一轮的一部分，剩下的记录一到，所有 DSH 上这一轮又变回未读，页面也不会再报一次已读。现在驱动的 DSH 要等这一轮的记录都写到主机上才报「空闲」（主机一直不收时最多等 3 秒）；其他 DSH 记已读时，如果这一轮的结束还没到，最多等 5 秒。<br>**点停止后马上发消息：** 原因不在停止。新会话的历史比会话记录先开始写到主机，在这段时间里发消息（停止后马上发很容易碰上），插件会把缺失的记录当成空历史，按主机上的副本重建会话，还没写上去的内容就被清掉了：刚发的消息和被停止那一轮的结束。找不到这条消息就报 “Remote message delivery was not recorded”，重建时断开 CLI 就报 “Remote CLI connection closed”。现在记录缺失时插件记住自己已经写了多少；主机上的历史比预期多时，先比对多出来的是不是自己的，是就继续写，只有确实是另一个 DSH 写的才重建。 |

源码与版本提交：`c699a3b`；市场包：`8d2e1421ccae6204f52919f88dc2a781fa0f4cf3`；市场索引：`70c4ee9`。
