# 插件发布记录 — 2026-11-12

## Autofix 0.1.3 — 验收之后可以删除修复用的工作区，删除前先确认

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Autofix | 0.1.2 → **0.1.3** | 以前每个修复的 worktree、工作区和对话在验收之后一直留在 DSH 里，要自己到侧边栏归档。现在修复合并（或推送）完成后，点了「通过验收」的那张卡片会问「删除这个修复的工作区吗？」，点「确认删除」才删，选「先留着」则什么都不动。已完成的任务在卡片和看板上都留着「删除工作区」按钮，点了同样先确认。删除时 worktree 被删除、对话被归档、工作区从侧边栏消失，任务仍留在看板的「已完成」里；分支已合并进远端基线分支的一并删除，只推送过的分支保留。工作区里还有没提交的文件或没推送的提交时拒绝删除并说明原因；仓库自己的 teardown 命令失败时也不删。由另一台 DSH 执行的修复同样可以在卡片上删除，执行的那台需要同为 0.1.3。 |

源码与版本提交：`1e34eb169a6b5d43450531a7211fc8decd93e395`；市场包：`336f0b0434fe154d862998bc803b3fac8a46aaad`；市场索引：`a2b60f5e1188b85a12c6fc2f332ef30a67874e57`。

### 验证

- Autofix 类型检查、构建通过，39 项测试全部通过（原 31 项加 8 项）。新增的测试覆盖：合并模式下删除工作区并删除分支、只推送模式下保留分支、有未提交文件时拒绝且什么都不动、未验收的修复不能删；归档服务返回未提交 / 未推送 / 无法判断时的拒绝文案、归档失败和中途停止、旧版 Remote Terminals 的提示；经由另一台 DSH 的转交请求；卡片的渲染测试（验收完成后自动出现确认、「先留着」不发请求、确认后才发请求、删除中和删除后的显示）。
- 用本机仓库对接真实的 worktree 归档服务（Remote Terminals 的 `WorktreeService`）各跑一遍合并和只推送两种模式：验收后归档检查为 0 个未提交、0 个未推送；留下一个文件时被拒绝；清掉后文件夹删除、工作区注销、对话归档、仓库的 teardown 命令执行，分支只在合并模式下删除。
- 发布预演只列出这一个插件；市场包里的编译产物包含本次改动。

### 未验证

- 真实 DSH 页面里的卡片外观和点击、SSH 远程机器上的 worktree、桌面应用；没有安装到任何一台机器上。

### 安装

升级 Autofix，然后重启 DSH。需要已安装 Remote Terminals（删除走它的归档）。固定版本地址：

```text
git+https://github.com/lalaze/dsh-plugins.git#336f0b0434fe154d862998bc803b3fac8a46aaad&path:/packages/autofix
```


## Model flow 0.1.11、Autofix 0.1.4 — /flow 可以在独立的 worktree 里运行，和自动修复共用流程和进度卡片

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Model flow | 0.1.10 → **0.1.11** | `/flow` 多了运行位置：命令里加 `wt=on` / `wt=off`，设置里多一项「输入 /flow 时在哪里运行」（当前对话 / 独立的 worktree）；`wt=on` 时可以再加 `repo=`、`branch=`。在当前对话里运行的方式不变。选独立 worktree 时，这条命令交给自动修复，变成一个任务。服务 `modelFlow` 升到版本 2：发起流程的插件可以给流程起一个标记，运行中可以问流程走到哪一步、取某一步的完整结果。新增客户端服务 `modelFlowCard`：把流程卡片本身提供给其他插件，可以替换顶部文字、在进度条末尾加流程之后的步骤、在卡片上下加内容，并让插件自己画带它标记的流程卡片。 |
| Autofix | 0.1.3 → **0.1.4** | 「要做的功能」和缺陷走同一条路：`/flow wt=on <要做什么>` 建出功能任务（编号 `F<n>`，分支 `feat/<n>`，提交信息 `feat: …`，给模型的话按「任务」而不是「缺陷」写），可以带这条命令里选的模型和轮数，转交给另一台 DSH 执行时也带着。任务卡片改用流程自己的卡片来画：和 `/flow` 一样的进度条和步骤，末尾多出「检查」和「验收」两段，报告下面是「通过验收 / 打回」。任务对话里原来有两张卡片（流程的、自动修复的），现在最新一次流程的卡片就是任务的卡片，更早的流程卡片留作那一轮的记录。看板和顶部按钮从「缺陷」改叫「任务」。从 `/fix` 或 `/flow` 开始的新对话会以输入的内容命名，不再是「未命名」。修正 0.1.3 的一个问题：仓库本身不在侧边栏工作区列表里时，删除工作区不会删掉已合并的分支。 |

源码与版本提交：`fe9bdcf`；市场包：`6b3be58725b0fb1e02a3dc460de0bc3313c53009`；市场索引：`2e185af`。

### 升级时要做的事

- 两个插件一起升级，然后重启 DSH，新效果才完整。只升其中一个时各自退回原来的行为：新 Autofix 配旧 Model flow，任务照常运行，卡片还是原来的两张；新 Model flow 配旧 Autofix，`wt=on` 会提示需要 dsh-autofix 0.1.4。
- 要用 `wt=on` 的仓库先加到「设置 → 自动修复 → 仓库」里。
- 另一台 DSH 负责执行时，那台也要升到 Autofix 0.1.4，功能任务的类型、模型和轮数才会带过去。

### 验证

- Autofix 类型检查、构建通过，48 项测试全部通过；Model flow 74 项全部通过。新增的测试覆盖：命令行里的 `wt`、`repo`、`branch`；设置项的保存；交给自动修复时带的内容、没有自动修复时的提示；流程的标记和进度；功能任务的措辞、分支名、提交信息；带卡片的流程不再另出卡片、流程没能启动时仍然出卡片；转交给另一台 DSH 时带的类型、模型和轮数；卡片在各个阶段的头部、进度段和按钮（渲染测试）；扩展的注册和撤销。
- 在一个真实的 DSH 0.2.2-rc.1 网页环境里用真实模型（经 SSH 的远程 Claude Code）实际操作：
  - 设置页切换运行位置并保存。
  - 输入 `/flow wt=on …`，以及设置成默认 worktree 后直接输入 `/flow …`，都建出功能任务，实现、审核、检查、提交后停在等验收；输入命令的对话里的卡片实时显示进度。
  - 任务对话里只有一张卡片；在这张卡片上验收，合并提交为 `merge task F4: …`，卡片随后自己询问是否删除工作区，确认后工作区、对话和已合并的分支都删除（worktree 在 SSH 机器上）。
  - 打回后跑第二轮，任务对话里是两张卡片：上一轮的记录，和带着任务的当前卡片。
  - 看板上新任务用流程卡片，升级前的旧任务仍是原来的样子。
  - `wt=off` 的普通流程卡片和以前一样，不建任务。
- 发布预演只列出这两个插件；市场包里的编译产物包含本次改动。

### 未验证

- 桌面应用；把功能任务转交给另一台 DSH 执行（只有单元测试）；新 Autofix 配旧 Model flow 在真实页面里的样子；窄屏；真实模型下检查失败后自动打回的那一轮。没有安装到任何一台机器上。

### 已知限制

- `wt=on` 要求仓库已经在自动修复的设置里；worktree 方式只能附带图片；少数拒绝提示对功能任务仍然写的是「缺陷」。

### 安装

升级 Model flow 和 Autofix，然后重启 DSH。固定版本地址：

```text
git+https://github.com/lalaze/dsh-plugins.git#6b3be58725b0fb1e02a3dc460de0bc3313c53009&path:/packages/autofix
```


## Model flow 0.1.12、Remote Terminals 0.1.5、Workspace Tags 0.3.2 — 可以在 DSH 0.2.2-rc.2 上使用

DSH 0.2.2-rc.2 改了三处这些插件用到的接口。旧版插件装在 rc.2 上会出下面的问题；新版在 rc.2 和更早的 DSH 上都能用。

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Model flow | 0.1.11 → **0.1.12** | 在 rc.2 上 `/flow` 一启动就失败，报 `host.subagents.list is not a function`，自动修复的任务也跟着失败。rc.2 把子代理改成了「具名子代理」：`subagents.list()` 被删除，启动子代理时任务内容直接放在参数上，不再放在 `request` 里。现在改用各版本都有的 `getProvider`，任务内容按两种写法都传。 |
| Remote Terminals | 0.1.4 → **0.1.5** | 在 rc.2 上终端打不开，报「终端错误：Cannot read properties of undefined (reading 'throwIfAborted')」：TUI 对话如此；侧边栏的终端走同一段代码，本地终端也一样。rc.2 把启动终端的内部方法从 `spawn(agent, owner, request, signal)` 改成了 `spawn(agent, owner, id, prepare, signal)`，选择 shell 挪到了新的 `userLaunch`。插件原来只转交四个参数，丢掉了 `signal`。现在原样转交所有参数；在 rc.2 上终端编号加到 `prepare` 返回的环境变量里，旧路径的启动器在 `userLaunch` 里换成当前的。 |
| Workspace Tags | 0.3.1 → **0.3.2** | 在 rc.2 上「标签…」面板弹到窗口左上角。rc.2 的菜单组件删除了 `getAnchorRect`，改用 CSS 锚点定位，现在同时传 `anchorPoint`，面板回到点击的位置。 |

源码与版本提交：`7ebe0be`；市场包：`78dbd3af73a61296d628df6bd9f90ec0d91d32a3`；市场索引：`7e5c960`。

### 升级时要做的事

- 先升级这三个插件，再升级 DSH 到 0.2.2-rc.2，然后重启 DSH。顺序反过来的话，升级 DSH 之后到升级插件之前，终端和 `/flow` 不能用。
- DSH 的发布说明要求共享会话的各个 DSH 进程一起升级到 rc.2。

### 验证

- Model flow 74 项、Remote Terminals 171 项（新增 1 项，按 rc.2 的方法签名模拟启动终端）、Workspace Tags 385 项测试全部通过，类型检查和构建通过。
- 发布后把这三个版本从市场装进真实的 DSH 网页环境，用真实模型（经 SSH 的远程 Claude Code）实际操作，rc.2 和 rc.1 各一遍：
  - `/flow wt=on …` 建出任务，实现、审核、提交后停在等验收。
  - 在远程工作区里开 Claude Code 的 TUI 对话，终端正常出现。
  - 直接和远程 Claude 对话一轮，带一次工具审批。
  - 在右侧栏新建终端，命令在远程机器的 worktree 目录里执行。
- 「标签…」面板的位置在 rc.2 和 rc.1 上各量了一遍，右键和行上的「⋯」两种打开方式都在点击位置旁边。
- 发布前用同样的改动在 rc.2 上还跑过：验收合并、删除工作区、Git 页签和文件标记、各插件的设置页、从侧边栏归档对话。

### 未验证

- 桌面应用、手机；没有安装到任何一台机器上。
- rc.2 上的共享 MCP 调用、AgentTeams 成员、用量面板的数字（这次没有改动它们，也没有实际跑）。
- rc.2 上的本地（非远程）侧边栏终端没有单独打开过，依据是它和已测的终端走同一段代码。

### 已知限制

- Workspace Tags 的侧边栏仍是 DSH 0.2.2-rc.1 的副本。在 rc.2 上，新会话页的工作区选择器弹在按钮旁边而不是下方（可以用）；rc.2 对侧边栏的改动（插件入口和会话列表共用滚动区、归档后的提示等）还没有带上。要解决需要把副本同步到 rc.2，届时该版本只能装在 rc.2 及以上。

```text
git+https://github.com/lalaze/dsh-plugins.git#78dbd3af73a61296d628df6bd9f90ec0d91d32a3&path:/packages/remote-terminals
git+https://github.com/lalaze/dsh-plugins.git#78dbd3af73a61296d628df6bd9f90ec0d91d32a3&path:/packages/workspace-tags
```
