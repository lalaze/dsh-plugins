# 插件发布记录 — 2026-11-12

## Autofix 0.1.3 — 验收之后可以删除修复用的工作区，删除前先确认

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Autofix | 0.1.2 → **0.1.3** | 以前每个修复的 worktree、工作区和对话在验收之后一直留在 DSH 里，要自己到侧边栏归档。现在修复合并（或推送）完成后，点了「通过验收」的那张卡片会问「删除这个修复的工作区吗？」，点「确认删除」才删，选「先留着」则什么都不动。已完成的任务在卡片和看板上都留着「删除工作区」按钮，点了同样先确认。删除时 worktree 被删除、对话被归档、工作区从侧边栏消失，任务仍留在看板的「已完成」里；分支已合并进远端基线分支的一并删除，只推送过的分支保留。工作区里还有没提交的文件或没推送的提交时拒绝删除并说明原因；仓库自己的 teardown 命令失败时也不删。由另一台 DSH 执行的修复同样可以在卡片上删除，执行的那台需要同为 0.1.3。 |

源码与版本提交：`1e34eb169a6b5d43450531a7211fc8decd93e395`；市场包：`336f0b0434fe154d862998bc803b3fac8a46aaad`；市场索引：`a2b60f5e1188b85a12c6fc2f332ef30a67874e57`。

### 验证

- Autofix 类型检查、构建通过，39 项测试全部通过（原 31 项加 8 项）。新增的测试覆盖：合并模式下删除工作区并删除分支、只推送模式下保留分支、有未提交文件时拒绝且什么都不动、未验收的修复不能删；归档服务返回未提交 / 未推送 / 无法判断时的拒绝文案、归档失败和中途停止、旧版 Remote Terminals 的提示；经由另一台 DSH 的转交请求；卡片的渲染测试（验收完成后自动出现确认、「先留着」不发请求、确认后才发请求、删除中和删除后的显示）。
- 用本机仓库对接真实的 worktree 归档服务（Remote Terminals 的 `WorktreeService`）各跑一遍合并和只推送两种模式：验收后归档检查为 0 个未提交、0 个未推送；留下一个文件时被拒绝；清掉后文件夹删除、工作区注销、对话归档、仓库的 teardown 命令执行，分支只在合并模式下删除。
- 发布预演只列出这一个插件；市场包里的编译产物包含本次改动。

### 未验证

- 真实 DSH 页面里的卡片外观和点击、SSH 远程机器上的 worktree、桌面应用；没有安装到任何一台机器上。

### 安装

升级 Autofix，然后重启 DSH。需要已安装 Remote Terminals（删除走它的归档）。固定版本地址：

```text
git+https://github.com/lalaze/dsh-plugins.git#336f0b0434fe154d862998bc803b3fac8a46aaad&path:/packages/autofix
```
