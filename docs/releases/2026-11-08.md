# 插件发布记录 — 2026-11-08

## `/flow` 改成一张卡片，报告固定显示

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Model Flow | 0.1.4 → **0.1.5** | 用户反馈 7 行重复的 `flow ·` 太难看，桌面版上结束报告也没有展开。现在一个流程在对话里只有一张卡片：运行时列出每一步的模型、用时和正在跑的那一步的最新动作，右边是“停止”；结束后标题行显示结果（第几轮通过、打回几次、共用多久），步骤收起，报告固定显示在下面，不能折叠。点标题可以重新展开步骤，点某一步看完整结果，“打开”照旧。通过是绿色，打回是橙色，失败是红色；只有一台机器时不显示机器名。输入的 `/flow` 那一行不再显示。DSH 在流程中途停止时，卡片显示“DSH 关闭时中断了”，并保留已完成的步骤。以前跑过的流程仍按原来的一行一行显示，只是最后的报告同样改为固定显示。 |

原因：之前每一步各是一行命令结果，每行都带同样的 `flow ·` 前缀，状态全是灰色，“打开”跟着文字长短错位，开头一行又因为太长被截断。报告行在桌面版上默认展开的状态丢了：内容在，点开能看到。网页版上重跑了五种情况都正常（刚结束、重新打开对话、发后续消息、DSH 完全重启、正文带绝对路径链接），桌面版具体原因没有找到，所以报告不再能折叠，也就不会再被收起。

实现：每个流程是一条由插件自己执行、一直等到流程结束才返回的命令，返回的文字第一行是结局（DSH 没装这个插件时也能看懂），后面是报告，末尾的元数据里有所有步骤（每步结果最多 16000 字）。运行中客户端每秒取一次卡片状态，不带各步结果，展开某一步时再单独取。运行中的卡片存在 `storages/dsh-model-flow/cards.json`，最多 50 个，流程结束后也保留结局，DSH 被强杀时卡片仍能说明走到哪一步。元数据里的 U+2028/U+2029 会被转义，否则末尾那一行匹配不上。

源码提交：`00dd26a`；市场包：`8b3b09e4a49b348bd1442efd24c1fdf17a4a8e3c`；市场索引：`fc9d185`。main 和 market 均已推送。公开索引返回 HTTP 200，dsh-model-flow 为 0.1.5，固定提交下的 `package.json` 返回 200，其他插件版本没有变化。

发布前验证：`dsh-model-flow` 的类型检查、60 项测试和构建通过（新增：卡片文字往返含 U+2028、各语言的卡片用词、打回次数、运行中卡片不带步骤结果、强杀后卡片保留步骤、输入的 `/flow` 处理期间被识别为开始行）。`pnpm release:market` 只发布了 dsh-model-flow 0.1.5；Workspace Tags 的旧版内容差异提示沿用之前已记录的情况。在隔离的 DSH 0.2.2-rc.1 网页版（无头 Chromium，SSH 到本机的远程工作区）上用真实的 Claude Code Haiku 跑过：带一次打回的流程、三轮都没通过的流程、中途点“停止”（1 秒后变成“已停止”，没有残留进程）、运行中的最新动作、390 像素宽度和深色主题。

发布后用 `dsh plugin --profile teams add` 从市场固定提交装进隔离的 `DSH_HOME`，安装的文件与市场包逐一一致。在这份安装上：之前的卡片显示结局和报告，旧流程的一行一行仍正常且报告固定显示，新跑的流程运行中逐步列出步骤（标题从“第 1 轮实现中”到“第 1 轮审核中”），结束为“第 1 轮审核通过 · 21 秒”，对话里只有卡片一行可见，报告在卡片下面，浏览器控制台没有错误。测试 DSH、它的中继和 SSH 连接都已停止，测试目录已删除。

**未验证：** 桌面版（这次的起因就在桌面版），壁纸下的效果，Codex 或 Opus 做步骤时的卡片，以及 Mac mini hub（没有装 Model Flow）。

**生效方式：** 在桌面版更新插件后重新加载客户端。正在运行的旧版流程不会变成卡片。

## `/flow` 改成真正的进度卡片

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Model Flow | 0.1.5 → **0.1.6** | 用户在桌面版上看到 0.1.5 的卡片“怪怪的”：模型名被挤成一个字母，用时和“打开”散得很开，整体也只是几行字。现在是一张有边框、圆角和半透明磨砂底的卡片：头部是状态圆标、当前在做什么（例如“Haiku 5.5 正在实现 · 打回 1 次 · 最多审核 3 轮”）、时钟和“停止”；进度条按最多轮数排满计划和每一轮的实现、审核，打回橙色、通过绿色、正在跑的一格流动，提前通过时用不到的轮次变成虚线；时间线用连线串起每一步，正在跑的一步高亮并显示最新动作，打回的一步下面直接显示审核意见的第一句；结束后步骤收起成“查看 N 个步骤”，报告放在卡片里。窄屏时模型名换到步骤名下面。 |

原因：0.1.5 的“最新动作”一行横跨各列又不换行，浏览器按它的长度分配列宽，模型列被压到 0。这种横跨的行现在用 `contain: inline-size`，不再参与列宽计算。另外修了两处：模型在两段输出之间“最新动作”会变空，卡片高度来回跳，现在保留上一句直到有新内容；时钟原来舍掉零头，和“共 X 秒”差一秒，现在一样四舍五入。卡片数据多了 `planned`（有没有计划步骤）和每步的 `note`（打回、失败、无结论时结果的第一行），0.1.5 留下的卡片缺这两项时从步骤和结果推出来。

源码提交：`c4d3e8b`；市场包：`2845f80255cbfe987722c620afc2360b34ad8520`；市场索引：`8a9a64c`。main 和 market 均已推送，公开索引返回 HTTP 200，dsh-model-flow 为 0.1.6。

发布前验证：`dsh-model-flow` 的类型检查、61 项测试和构建通过（新增时钟、卡片标题和说明用词、`planned` 和打回步骤的 `note`）。第一次完整检查有 1 项失败，之后连续 5 次全过，失败的测试名没有抓到，当时负载约 5，判断为依赖时间的测试超时。在隔离的 DSH 0.2.2-rc.1 网页版（中文界面，SSH 到本机的远程工作区）上用真实的 Claude Code Haiku 跑过：带一次打回的流程（运行中、第 2 轮、通过、展开步骤、展开一步的结果）、直接通过的流程、中途停止（卡片变成“已停止 · 停在第 1 轮实现”）、深色主题和 390 像素宽度，控制台没有错误；修好闪动后同一步内“最新动作”不再消失，只在换步骤时变化一次。

发布后：市场包里的 `lib/client.js` 和服务端入口与测试过的构建逐字节一致；用 `dsh plugin --profile teams add` 从市场固定提交装进隔离的 `DSH_HOME`，26 个文件与市场包一致。测试 DSH、中继、SSH 连接和测试目录都已清理。

**未验证：** 桌面版，壁纸下磨砂底的效果（测试环境里没能把 DSH 的背景层换成壁纸）。

**生效方式：** 在桌面版更新插件后重新加载客户端。0.1.5 跑出的卡片会直接用新样式显示。
