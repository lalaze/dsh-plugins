## 自动修复 0.1.5、远程智能体 0.2.143 — 有了互联，不再在 DSH 之间转交

用户改用互联直接打开每台机器自己的 DSH 之后，问模型分工、远程工作区和 TAPD 的代码要不要跟着改。查下来：模型分工和 TAPD 不用改；自动修复的「接收其他 DSH 转交的缺陷」已经用不上，hub 上这个开关开着，但它服务的仓库路由指向迁移时删掉的旧 SSH 工作区，一直在报「This folder is not a DSH workspace」；Air 上的路由也指向已删掉的工作区，设置页却不提示。

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| 自动修复 | 0.1.4 → **0.1.5** | **删掉 DSH 之间的转交：**去掉设置里的「接收其他 DSH 转交的缺陷」开关和状态列表、经由仓库所在机器 `~/.dsh-autofix` 的交接文件、对话卡片跟随另一台 DSH 任务的部分。没有仓库时 `/fix` 提示在这台添加，或者切换到仓库所在机器的 DSH 在那边输入 `/fix`。以前转交出去的任务，卡片显示任务已删除；旧设置里的 `relay` 读入时忽略。<br>**失效的仓库：**设置页加载项目时，服务端逐条检查仓库的文件夹还是不是这台 DSH 的工作区（只在本机查，不连 SSH）；不是了，或者它所在的机器已从远程智能体里删除，就在仓库卡片上标「工作区已不在」，展开后写明怎么处理。插件没在运行等判断不了的情况不标。 |
| 远程智能体 | 0.2.142 → **0.2.143** | **删掉共享撤回：**0.2.139 起，升级后的 DSH 第一次连上机器时会把自己共享过的会话标为已撤回，免得 0.2.138 的 DSH 接管它们的 CLI。四台机器都已在 0.2.142，这一步去掉：连上机器时不再写 `~/.dsh-remote-agents/shared-v1`，状态里的 `instance`、`sharedWithdrawals` 读入时忽略、下次保存时去掉。丢弃 0.2.138 留下的会话副本的迁移保留。 |

## 远程终端 0.1.14 — GPU 恢复后 TUI 文字完整重画；换宽度后的历史重建更稳

用户反馈两件事：手机上一个 TUI 对话大部分文字不见（没有英文数字和分隔线，汉字只剩一部分，总是同一批字），以及对话里宽窄混在一起。

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| 远程终端 | 0.1.13 → **0.1.14** | **文字缺失：**所有 WebGL 绘制的 TUI 共用 xterm 的一套字形缓存（画布）。浏览器丢掉图形上下文（Android 回收后台页面的显卡资源）后画布被清空，xterm 恢复时在还有别的终端使用的情况下取回同一套缓存，缓存仍记着之前画过的字，于是这些字一直空白、只有新出现的字正常。现在任一 WebGL 画布或字形画布恢复时，为所有 WebGL TUI 清空缓存重画；上下文丢失后再次启用 WebGL 时也重画一次。<br>**历史重建：**按新宽度重打历史的 Claude Code 副本，首字节等待从 1.5 秒改为最多 10 秒（Mac mini 上实测 0.8–2.2 秒），副本无输出时在对话安静后重试一次；屏幕与副本逐行对不上时（自动模式下只有运行中的会话才显示的「⎿ Allowed by auto mode」「⎿ (timeout 2m)」等行），改为按顺序宽松比对。 |

源码与版本提交：`c377e12`；市场包：`f294252a886ec849ce8bc93fcae722939a7e904a`；市场索引：`a829aeb`。

- 复现：真实 Chrome（Metal GPU）里两个 xterm 6.0.0 + addon-webgl 0.19 终端写入中文，杀掉该 Chrome 的 GPU 进程，恢复后旧字全部空白、新字正常，与手机截图一致；只有一个终端时能自行恢复。加上修复后两个终端文字完整。字形画布的 2D 上下文比 WebGL 早约 0.6 秒恢复。
