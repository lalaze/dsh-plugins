## 远程终端 0.1.14 — GPU 恢复后 TUI 文字完整重画；换宽度后的历史重建更稳

用户反馈两件事：手机上一个 TUI 对话大部分文字不见（没有英文数字和分隔线，汉字只剩一部分，总是同一批字），以及对话里宽窄混在一起。

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| 远程终端 | 0.1.13 → **0.1.14** | **文字缺失：**所有 WebGL 绘制的 TUI 共用 xterm 的一套字形缓存（画布）。浏览器丢掉图形上下文（Android 回收后台页面的显卡资源）后画布被清空，xterm 恢复时在还有别的终端使用的情况下取回同一套缓存，缓存仍记着之前画过的字，于是这些字一直空白、只有新出现的字正常。现在任一 WebGL 画布或字形画布恢复时，为所有 WebGL TUI 清空缓存重画；上下文丢失后再次启用 WebGL 时也重画一次。<br>**历史重建：**按新宽度重打历史的 Claude Code 副本，首字节等待从 1.5 秒改为最多 10 秒（Mac mini 上实测 0.8–2.2 秒），副本无输出时在对话安静后重试一次；屏幕与副本逐行对不上时（自动模式下只有运行中的会话才显示的「⎿ Allowed by auto mode」「⎿ (timeout 2m)」等行），改为按顺序宽松比对。 |

源码与版本提交：`c377e12`；市场包：`f294252a886ec849ce8bc93fcae722939a7e904a`；市场索引：`a829aeb`。

### 验证

- 复现：真实 Chrome（Metal GPU）里两个 xterm 6.0.0 + addon-webgl 0.19 终端写入中文，杀掉该 Chrome 的 GPU 进程，恢复后旧字全部空白、新字正常，与手机截图一致；只有一个终端时能自行恢复。加上修复后两个终端文字完整。字形画布的 2D 上下文比 WebGL 早约 0.6 秒恢复。
- Mac mini 上的保持器日志：两个 0.1.13 保持器 4 次换宽度里，2 次「副本什么都没输出」（无重试），1 次重试后成功，1 次两次都对不上；其余 32 个 TUI 保持器仍是 0.1.13 以前的版本，根本不重建。
- 远程终端 224 项测试（新增：GPU 恢复后全部重画、字形画布恢复、丢失后重新启用、停用后不再监听；副本慢启动与无输出重试；宽松比对及其反例），类型检查、构建通过。新增的比对测试在旧算法下失败。
- 市场包的 `lib` 与通过检查的构建逐字节相同。
- 未验证：真实 DSH 页面与真手机上的 GPU 恢复；01:06 那次比对失败的屏幕（发生在一轮进行中）无法重现，宽松比对是根据实测的行差异做的。

### 安装

```text
git+https://github.com/lalaze/dsh-plugins.git#f294252a886ec849ce8bc93fcae722939a7e904a&path:/packages/remote-terminals
```

升级后刷新显示 TUI 的页面（包括手机）即可用上绘制修复；历史重建的改动只对升级后启动的 Claude Code 生效，已在运行的 TUI 对话需归档再恢复。
