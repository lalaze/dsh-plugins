## Remote Agents 0.2.121 — Codex 用量不再在重新连接后多算

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.120 → **0.2.121** | DSH 重新连上仍在运行的 Codex 后，那一轮不再把整个线程的累计用量记成本轮。 |

修复提交：`a969714`；版本提交：`db67450`。市场包：`edfa3a9463af0f47947a2f6840766a718d23be82`；市场索引：`1dc9b3b6d6f82aae75bac0745fb9cf79ee7e3465`。main 与 market 已原子推送，远端 SHA 已核对。

### 起因

使用量面板当天显示 gpt-6.1-sol 1.04 亿、gpt-6-astra 约 79M，而 mac-mini 与 code 两台主机上 Codex 自己的会话日志合计约 0.66 亿和 0.19 亿。任务事件日志里的 `usage` 条目显示，重新连接后那一轮记下的是线程累计值：zeGame2 第 2 轮实际 12.2M、记 17,615,603；dsh-plugins 任务第 2 轮实际 16.2M、记 20,101,900（MacBook Air 的 DSH 在这一轮进行中重新连上）。原因是本轮起点只存在 `CliSession` 内存里，`restore()` 新建的会话没有起点，`codexTurnUsage(total, undefined)` 就把整个线程算成一轮。

### 修复

- 每轮开始时记下线程累计值，连同 Codex 轮次 ID 存进任务状态（`codexTurnStart`）；同一 DSH 在一轮中途重新连上时读回。
- 不知道起点时，用这一轮第一条 `thread/tokenUsage/updated` 的 `total - last` 作为起点（Codex 0.166 每条都带 `last` 与 `turnId`；当天 72 + 12 个 relay 日志中没有例外）。另一个 DSH 中途接手时，接手前的请求不计入。
- 仍不知道起点时不记录这一轮，不再记整个线程。

### 验证

- 新增 relay 测试：修复前在两轮之间重新连上时记 440（应为 220）；修复后通过。去掉读回保存起点的代码后，一轮中途重新连上的断言失败（220 对 440），说明这部分被覆盖。
- `pnpm --filter dsh-remote-agents run check` 在独立工作树中退出 0：656 项测试中 655 通过、1 项既有跳过、0 失败，类型检查与构建通过。
- 预演只列出 `dsh-remote-agents 0.2.121`；Workspace Tags 0.3.0 的既有内容差异提示照旧跳过。
- [公开市场索引](https://raw.githubusercontent.com/lalaze/dsh-plugins/market/index.json)与[固定包清单](https://raw.githubusercontent.com/lalaze/dsh-plugins/edfa3a9463af0f47947a2f6840766a718d23be82/packages/remote-agents/package.json)均返回 HTTP 200，版本为 0.2.121。市场包的 `lib/server/agents/runtime.js`、`usage.js`、`core/domain.d.ts` 与 `client.js` 与通过检查的本地构建逐字节一致；包清单不含 scripts 或 devDependencies。
