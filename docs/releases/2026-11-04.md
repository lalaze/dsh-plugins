## 远程智能体设置页更顺手

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.78 → **0.2.79** | 只改设置界面，功能不变。远程机器列表以前每台机器都一直摊开共享开关和一排 6 个 CLI 勾选，几台机器就拉得很长。现在每台机器默认折叠成一行：显示名字、连接、状态、是否共享和模型数，并用一行小字概括启用了哪些 CLI；点左侧箭头展开才显示共享开关和各 CLI 的勾选，错误信息始终可见。每台机器的 测试连接、刷新模型、移除 收进右侧的 ⋯ 菜单，不再一排三个按钮，移除照旧带二次确认。有机器时"添加机器"表单收起成一个按钮，需要时再展开（没有机器时仍直接显示表单）。团队预设里的成员和任务也改成可折叠卡片：编辑已保存的预设时默认只看摘要（成员显示"名字 → CLI 模型"，任务显示"id → 负责人"），新建预设或新加的成员/任务自动展开。菜单沿用会话选项菜单的点击外部或 Esc 关闭 |

## 从终端直接开始 Claude Code 对话

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.79 → **0.2.80** | 原生终端的 Shell 菜单新增 **Remote Claude**：选它会通过 SSH 在当前远程工作区启动交互式 `claude`，退出后留在远程 shell。对话仍走 `claude -p`，这一项只是多一个入口，不经过中继。会话不显示在 DSH 对话里，也用不到 DSH 共享的 MCP 服务和技能，之后在远程目录运行 `claude --resume` 继续。在菜单选中后，在远程对话之间切换时「新建终端」继续打开它；离开远程对话还原用户自己的 shell，再回来时恢复为 **Remote workspace**。不在远程工作区时只打开本地 shell，不会在 DSH 所在机器上启动 Claude。 |

验证：新增测试覆盖启动器的 SSH 命令、不在远程工作区时的回退、卸载时移除两个启动器，以及 shell 偏好的记住与还原（含 Windows 的 `.cmd` 路径字符串）。类型检查与构建通过。用启动器的 SSH 参数真实连到本机（zsh），并在本地用 bash 跑同一条命令：`claude` 在工作区目录启动，信任确认正常弹出，退出后回到可用的 shell，再退出时终端关闭。单元测试 427 项中 406 项通过、4 项失败、16 项取消：取消的是已知的中继用例；`command output split inside a character` 与 `a forward whose socket the host lost` 在未改动的 main 上同样失败；`a shared workspace is offered` 只在全量运行时失败，单独运行通过；`reattached CLIs get the forward back` 间歇失败（带改动单独跑 2 次中失败 1 次，未改动的 main 跑 1 次通过），本次改动未涉及共享代码，但这几次重跑不足以完全排除关联。未实测：DSH 里实际点击菜单（两项同时出现是从 DSH 按可执行文件名去重的代码推断的）、SSH 上越过信任确认进入主界面（主界面只在本地 tmux 里跑过）、Windows 上运行 `.cmd` 启动器。

## TUI 对话：左侧选中一行，主区域就是 Claude Code

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.80 → **0.2.81** | 用户想要“终端在左边展示，对话区域直接是 TUI，选中这个就是对应 TUI”。在远程工作区新建对话，点输入框左下角的 **用 TUI 开始**：这个对话仍是真正的 DSH 会话，所以在工作区列表里是一行；它的「对话」标签页换成交互式 Claude Code，输入框隐藏。实现要点：DSH 只在收到 `turn/start` 后才认为会话非空，服务端写入一个空的轮次；聊天视图的 slot 条目按 git-view 的接管方式原地替换，所以不多出标签页，其他对话不受影响；终端直接复用 DSH 右侧栏的终端组件，不另带 xterm；启动器用 `DSH_SESSION_ID` 算出固定的 Claude 会话 ID，已保存过就 `--resume`，否则 `--session-id`。归档时关闭对应终端，结束它的 Claude。对话内容只在远程的 Claude Code 里，DSH 的对话记录、搜索和手机端看不到。另外修复：DSH 不把 `DSH_HOME` 传给终端，非默认目录下启动器找不到远程工作区；现在安装时写入启动器。 |

验证：新增测试覆盖 TUI 启动的校验与空轮次、启动器的固定会话与恢复命令、归档关闭终端。在隔离的 DSH 0.2.1-rc.5 网页版（Chromium，SSH 到本机）实测：新建两个 TUI 并来回切换，各显示各的内容；普通对话不受影响；刷新页面后内容还在；重启 DSH 后再选中接回历史；选中一行可直接打字；`/exit` 回到远程 shell，再退出出现「新建终端」，点击后回到 Claude；右侧「新建终端」记住的 shell 不变；归档后几秒内 Claude 结束，撤销归档后再选中重新启动。打好的 0.2.81 包在同一环境再验证一次：TUI 启动、输入框隐藏、可直接打字、归档结束 Claude。只含本次改动的干净 worktree 中，单元测试 431 项通过 413 项、失败 1 项、取消 16 项、跳过 1 项：取消的是已知的中继用例，失败的 `a forward whose socket the host lost` 在未改动的 main 上同样失败。未实测：DSH 桌面版、用户当前的 DSH 版本、与 dsh-workspace-tags 的侧栏副本同时使用、手机端、深色主题、空闲约 2 小时被回收后重新打开（走的是与重启相同的恢复路径）。依赖 DSH 内部实现（替换聊天视图条目、复用未公开的终端组件、手写轮次事件），DSH 升级后可能需要跟进。SSH 断开或 DSH 退出时正在跑的一轮会中断。
