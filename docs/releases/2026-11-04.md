## 停止回复后不再冒出“断开期间的输出”

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.85 → **0.2.86** | 用户截图：点停止后再发消息，回复开头出现 `Output from the previous response, completed while DSH was disconnected:`，后面只有一条分隔线，而 DSH 并没有断开。原因有两层：停止时这一轮被记成“还没送达完”，中断记录又总写在保存位置之后，所以下一条消息总能发现“新内容”；判断时也不区分这些记录是否可见（用户这次是 `delivery`、`usage`、`turn_end`、`interrupted`，全都不显示）。现在停止后如果 CLI 还连着且已空闲，就把这一轮记为已结束；标题只在有文字、思考、工具调用、错误或模型切换要显示时才出现；重新打开对话时的同步如果什么也没漏，回复写 “The remote CLI produced no further output.”，不再是空回复。判断不能只看 `stop` 有没有报错：CLI 连接不在时 `stop` 直接返回，CLI 还在跑，这时保留追赶。同时修复两个同类问题：消息发出后、第一次读取前就停止，这一轮下次会显示成 `1 turn sent elsewhere`；已经显示过的 CLI 错误会带着这句标题再显示一遍。取舍：停止那一刻还没读到的文字不再补到下一条回复，仍可在打开会话中查看。 |

验证：Workspace Tags 的 303 项界面测试和 19 项单元测试全部通过，并在隔离的 DSH 0.2.1-rc.5 网页版（无头 Chromium，假模型）跑通运行、结束、点开、切走、发下一步。Remote Agents 新增 10 项测试；全量 514 项中通过 493 项、失败 1 项、取消 19 项，这些都不是新增的：在干净的 main 上同样失败或取消。在隔离的 DSH 里用真实的 Claude Code 和 Codex 实测：Claude Code 跑了运行、走开后完成、打开后保留、权限确认和提问显示为等待、运行中刷新页面不误报完成；Codex 跑了运行到结束。

实测中修掉的问题：Codex 一轮结束发的是 `state=done`，没处理时会一直显示运行中；Codex 启动时会短暂报告工作中，这时切走会被当成完成，所以启动后 8 秒内不算；队长的 DSH 轮次结束会报告已停止，所以忙碌时每 5 秒重复一次。
