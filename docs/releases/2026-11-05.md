## 切回 TUI 不再加载

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.96 → **0.2.97** | 用户反馈切回 TUI 都要加载一下，感觉卡。以前每次切回都销毁并重建终端：先走一次到远程机器的 SSH 准备，显示“正在启动”（0.2.93 为团队工具加的，其实只有启动 CLI 前才需要）；再新建 xterm、重新连接，等整屏内容传回来，这段就是只有光标的空白。现在最近用过的 6 个终端切走后不销毁，元素在对话区和页面里一个隐藏的位置之间移动，继续接收输出；同一次连接里每个对话只准备一次。超过 6 个时最久没用的关掉，重新打开还会短暂空白，但不走 SSH。DSH 重启或连接断开后，第一次切回仍会短暂显示“正在启动”。文件在切走之后才传完的，路径会立刻填进它所在对话的输入框，不再等切回。 |

验证：Remote Agents 新增 5 项测试；全量 552 项中通过 531 项、失败 1 项、取消 19 项，失败和取消的项目与干净的 main（f8af916）完全相同。在隔离的 DSH 0.2.1-rc.5 网页版（无头 Chromium，SSH 到本机）测两个 TUI 来回切换：到画面稳定的中位数从 165 ms 降到 40 ms，看不到内容的时间从 117 ms 降到 0。真实网络上 SSH 这一步本来更慢，省下多少没有测。用真实的 Claude Code（Haiku）实测通过：切回后不点击直接打字、隐藏时继续输出且不抢焦点、滚动位置、隐藏时改窗口大小和主题、轨迹标签页和普通对话之间来回、快速连续切换、第七个挤掉最久没用的、第二个页面抢走输入后切回能拿回来、拖文件后马上切走、`/team`、`/exit` 后 `exit 3` 再新建终端、归档隐藏的和正在显示的、撤销归档、页面开着时重启 DSH、只断连接、刷新页面。

开销（同样的环境）：保留的终端从 2 个增加到 6 个，JS 堆多 3.2 MB，不含屏幕缓冲区；隐藏的 CLI 持续输出时主线程每秒约 96 ms，0.2.96 约 68 ms，各只测了一次。

实测中修掉的问题：页面开着时重启 DSH，隐藏的终端切回后按键全部丢失。DSH 只为侧栏标签保留终端连接，打开另一个终端时会释放其他连接占位，隐藏的终端正在重连就会失败，停在要手动点“重新连接”的状态，而旧屏幕还显示着，看起来一切正常。现在切回时会自动重连。

**未验证：** 桌面版；Codex 只在数量上限的测试里打开过一行，没有测切换和打字。已知限制：隐藏的终端在连接恢复时会重新接管输入，如果同时开着两个页面，正在另一个页面打字可能被抢走；依赖 DSH 内部结构（`shell.overlay` 插槽、终端组件的 `visible` 和 `connect`），DSH 升级后可能要跟着改。Mac mini 上的手机端 DSH 没有更新。

## 关掉 DSH 也不断：远程终端和 TUI 常驻远程机器

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.95 → **0.2.96** | 用户反馈 TUI 和自己开的远程终端都很卡、会断线，希望关掉本机 DSH 再打开都保持住。以前 CLI 和 shell 跑在 DSH 启动的 `ssh` 下面，这条连接一断就跟着结束，正在跑的一轮也丢了。现在它们跑在远程机器的常驻进程里，DSH 只是连上去看：断线自动重连，电脑休眠唤醒后立刻重连；重开 DSH 后 TUI 接回同一个进程，侧栏的终端标签也会自己回来；屏幕和滚动记录由常驻进程里的无头 xterm 保留。没有用 tmux：它会接管滚轮和选字，还会吞掉 Codex 的状态信号；常驻进程把 CLI 的字节原样转发。Node 开不了 PTY，macOS 的 `script` 又拒绝非终端的 stdin，所以用几行 Python 持有 PTY。关闭标签、`exit`、归档 TUI 才结束；没人回来的 7 天后结束。远程机器没有 Python 3 或 Node.js 22 时退回普通连接，并在终端里提示。同时关掉这些连接上 OpenSSH 的按键节奏保护（`ObscureKeystrokeTiming`）：回环上每个按键 327 字节对 36 字节，回显 p95 27.6 ms 对 1.6 ms；代价是网络上的观察者能从包的时间看出打字节奏，和 OpenSSH 9.5 之前一样。 |

卡顿的实测：从 Mac mini 到用户的 MacBook 丢包 2.3%、往返最高约 100 ms，同一时刻到另外两台机器都是 0% 丢包。80 次探测里 77 次走 peer-relay（中位 32 ms），2 次直连（20 ms），1 次回退到洛杉矶的 DERP（1.45 秒）。丢包是插件解决不了的，这次只是减少了它的影响，所以不能说已经不卡。桌面版自身的渲染有没有拖慢也没有测。此前“滚动不走网络”的判断是错的：Claude Code 的滚动是它自己绘制的，滚轮也要走一个来回。

验证：Remote Agents 新增 24 项测试；全量 547 项中通过 526 项、失败 1 项、取消 19 项，和之前干净的 main（be96e20）对比没有新增失败，都是已有的 relay 测试问题。在隔离的 DSH 0.2.1-rc.5 网页版（无头 Chromium，SSH 到本机）用这个最终构建实测通过：真实的 Claude Code（Haiku）回复写到 40 时停掉 DSH，回来时已写到 2007，还是同一个进程，之后写完；侧栏终端经过刷新、重启、杀掉 ssh、调整大小和关闭标签；归档只结束自己的常驻进程。rebase 之前的构建上还测过：真实的 Codex（GPT-6-Luna）在重启后写完并继续对话，重启后团队工具仍能调用，`/exit` 后留在同一个常驻进程，`exit 3` 显示退出码，新建终端恢复对话。真实的 Linux 主机上手动验证了接回和退出。回显没有变慢（回环 p50 7.0 ms 对 7.9 ms），空闲时常驻进程约占 27 MB 内存，CPU 为 0。

实测中修掉的问题：`tuiEnd` 漏加进接口白名单，归档时常驻进程不结束；Python 自己忽略 SIGPIPE，这个设置会带进 shell，让管道报错而不是结束；没人连着时 CLI 问终端（比如光标位置）得不到回答，Codex 会超时，改由常驻进程代答；序列化不恢复隐藏光标和 SGR 鼠标模式，Claude Code 重连后光标位置不对、滚轮失效，改由常驻进程自己记录；不再读取的客户端不能卡住 CLI，5 秒后断开它，下次连接拿到完整屏幕。

**未验证：** 桌面版；Windows 客户端。已知限制：`docker` 这台机器的 PATH 上没有 Node，只能用普通连接；DSH 重启后左侧这一行要点开才知道状态，CLI 其实一直在跑；已经开着的终端要到下次打开才生效；依赖 DSH 内部结构（`terminalController.spawn`/`close`、`webTerminals.view`），DSH 升级后可能要跟着改，改了会退回以前的行为。Mac mini 上的手机端 DSH 没有更新。

| Mobile | 0.3.4 → **0.3.5** | 手机的实时草稿改为按块处理，和 DSH 聊天一致，否则上面的状态行会一条条叠起来。要和 Remote Agents 0.2.95 一起更新。 |

验证：在隔离的 DSH 0.2.1-rc.5 网页版（无头 Chromium，SSH 到本机）用真实的 Claude Code（Opus 5.5）实测通过：写了正文和还没写正文时显示状态行、运行中按停止、运行中刷新页面、重启后重新打开已保存的会话，保存的记录里都没有状态行；xhigh 强度下写在思考块里的进度说明会实时显示。用户反馈那一轮的真实日志回放也正常。Remote Agents 新增 9 项测试，全量 523 项中通过 501 项、失败 2 项、取消 19 项；干净的 HEAD 上是 514 项中通过 492 项、失败 2 项、取消 19 项，只差一个偶发用例：这边多失败的 `sessions recorded before sharing…` 单独跑时两边都通过，那边多失败的是 `a tag change here triggers a sync on its own`。Mobile 新增 1 项，全量 27 项通过。

实测中修掉的问题：还没写正文就先跑工具时，占位块原本存成空的 reasoning，但 `dsh-llm-deepseek` 会把它原样发出去，换模型时可能出错，所以改存空的 text。

**未验证：** 桌面版。已知限制：工具卡片仍要等回复结束才能展开；Claude 还在生成工具参数时没有状态行（写文件这段中位数约 17.5 秒，最长 345 秒）；运行中的图片仍只显示文件名，原因未查；部分长对话轮开头最多有约 81 秒没有输出（第 90 百分位），原因未查；还没写正文就先跑工具的回复，跑完后正文上方多约 16 像素空白。
