# 2026-11-19 发布记录

## 远程终端 0.1.20 — Antigravity 的 TUI 会跟随你正在看的设备改变大小

用户在电脑上打开一个在手机上用过的 Antigravity TUI 对话（「Mobile Web App Keyboard Color」），说「tui 样式不对」：窗口中间只显示窄窄一列，内容按大约 41 列折行。实测这个对话的 holder 有两个客户端，都来自 hub 的 DSH：电脑页面 120×54，手机页面 41×43，agy 的 PTY 是 41×43，也就是画面还在手机手里。0.1.10 起画面靠焦点报告（ESC[I）跟随你转向的设备，但页面只在 CLI 开启了焦点报告（`?1004h`）时才发；Claude Code 和 Codex 会开启，Antigravity 1.5.12 从不开启，所以只有在电脑上打字才能把画面要回来。

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| 远程终端 | 0.1.19 → **0.1.20** | **页面不管 CLI 是否开启焦点报告都认领画面：**`claimScreen` 只在「终端有焦点且 CLI 开启了焦点报告」（xterm 自己已经报告过）时不发，其余情况都发 ESC[I + ESC[O；`useScreenClaim` 另外在终端获得焦点（host 上的 `focusin`）时认领，因为 xterm 不会替没开焦点报告的 CLI 报告。**连接进程不把焦点报告转给没要的 CLI：**`holder-protocol.ts` 新增 `FocusReports`（从输出里跟踪 `?1004h/l` 和 RIS，保留 32 字符尾巴应对被拆开的序列；加入时 holder 的快照以 RIS 开头、带着 `?1004h`）和 `onlyFocusReports`；attach 客户端在 CLI 没开启时丢弃只含焦点报告的输入。认领规则（`screenClaim`、`FOCUS_SETTLE_MS`）和 holder 守护进程都没变。 |

源码与版本提交：`6024248`；市场包：`7e3a241474c8e74195d34594c41c288f6012ed2c`；市场索引：`3ff4a26`。不需要重启；每台设备刷新页面后生效。

### 验证

- 远程终端类型检查、241 项测试、构建通过；市场包 `lib` 与本地测过的构建逐字节相同。新增测试：`FocusReports` 跟踪（拆开的序列、和其他模式写在一起、`?10040h` 不算、RIS 复位、快照）；真实 holder 上一个从不开启焦点报告的 CLI：手机加入后电脑发 ESC[I ESC[O 把画面要回 120×40，CLI 一个字节也没收到，随后打的字照常收到；CLI 开启焦点报告后 ESC[I 照常送达。去掉丢弃那一行后这项测试失败。页面侧（jsdom）：没开焦点报告时有焦点也认领、点进终端认领，开了焦点报告时点进终端交给 xterm。
- 在独立的 PTY 里跑 agy 1.5.12（打开一个旧的测试对话，没有发消息）：收到 ESC[I、ESC[O 没有任何输出，输入行不变；宽度从 41 改成 120 时 agy 清屏并按新宽度把整个对话重画一遍，所以不需要像 Claude Code 那样重建历史。zsh 和 bash 收到它们只响两声提示音，不输入任何字符。
- 未验证：真实 DSH 页面、真手机、桌面 app。

### 兼容

升级前已经打开终端的 TUI，attach 客户端还是旧的：它照样把 ESC[I 认作认领、要回画面，只是把这几个字节也转给 CLI（Antigravity 忽略，shell 响一声），直到 DSH 重新打开这个终端。所以装好后刷新页面即可，不必重开对话。
