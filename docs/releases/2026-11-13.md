# 2026-11-13 发布记录

## Game Assets 0.2.0、0.2.1 — 用自选的生图接口重绘或生成素材

以前「素材」标签页的「重绘」只是把一段请求填进对话输入框，只有 Codex（自带生图工具）能接着画出来。现在插件自己调用生图接口，换成任何对话、任何模型都能用。

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Game Assets | 0.1.3 → **0.2.0** | 新增「生图来源」：在插件设置页或生成对话框里添加，支持 OpenAI 兼容接口（`/images/generations`、带参考图时 `/images/edits`，OpenAI 官方或中转服务）和 Gemini（`generateContent`）。图片详情里的「重绘…」、选中图片后的「生成…」（最多 4 张参考图）、工具栏的「生成新图片…」。生成结果先在对话框里与原图对比，已缩放到原图的像素尺寸；保存时可以「另存为新文件」，或「替换原图」（原图先退役，可恢复，新图沿用原路径，代码引用和标签不变）。远程工作区同样可用。 |
| Game Assets | 0.2.0 → **0.2.1** | 在 DSH 里素材视图和输入框共用高度，生成后「另存为新文件」「替换原图」两个按钮被挤到对话框下方，要滚动才看得到。现在按钮固定在对话框底部，矮屏上预览图也会缩小。 |

源码与版本提交：`776d0b9`（0.2.0）、`0f4f4de`（0.2.1）；市场包：`a8067eb`（0.2.0）、`85e48bc61f87dfe4b25cd5d69f184d7cffd1cd21`（0.2.1）；市场索引：`c5f6a76`。

### 使用前要做的事

- 在插件设置页的「生图来源」里添加至少一个来源：名称、地址（OpenAI 兼容填到 `/v1`）、模型、API 密钥。
- 密钥只保存在运行 DSH 的电脑上（`storages/dsh-game-assets/image-sources.json`，只有所有者可读），页面只显示最后四位。生图请求也从这台电脑发出，远程工作区也一样。
- 如果这台电脑要经代理才能访问 OpenAI 或 Google，DSH 需要带 `NODE_USE_ENV_PROXY=1` 启动，Node.js 的 `fetch` 才会使用 `HTTPS_PROXY`；也可以直接填中转服务的地址。

### 验证

- 80 项测试全部通过（新增 15 项：两类接口的请求格式、密钥不出现在页面和报错里、不覆盖文件、替换后原图可恢复、远程上传与校验、对话框和设置页的交互），类型检查和构建通过。
- 用本地假生图接口（OpenAI 兼容和 Gemini 两种路由）在浏览器里跑通：32×32 精灵图「保留像素锐利」缩放并替换原图，320×180 背景图平滑缩放、裁切铺满并另存，Gemini 无参考图生成并保存，手机宽度下无横向滚动。
- 发布后把市场上的 0.2.0 和 0.2.1 装进全新的 DSH 0.2.2-rc.2 网页环境：插件设置页添加来源（密钥文件权限 0600），游戏工作区的会话里出现「素材」标签页，重绘后替换原图（新图 32×32，原图移到 `_retired/` 并记录），0.2.1 上另存为新文件，按钮在对话框内可见。

### 未验证

- 没有调用过真实的 OpenAI 或 Gemini 接口，也没有试过具体的中转服务；请求格式按两家当前文档和测试里的假接口确认。
- 桌面应用、手机、远程工作区里的真实保存（远程上传只在测试里模拟了 Remote Agents）；没有安装到任何一台机器上。

### 已知限制

- GIF 和 SVG 不能作为参考图，也不能被替换（可以另存为 PNG）。
- 生成结果由浏览器缩放；Safari 不能导出 WebP，保存到 `.webp` 时会提示改存 `.png`。
- Gemini 生成的图片没有透明背景。

### 安装

```text
git+https://github.com/lalaze/dsh-plugins.git#85e48bc61f87dfe4b25cd5d69f184d7cffd1cd21&path:/packages/game-assets
```

## Game Assets 0.3.0 — Codex 作为生图来源；项目里的 agent 也能生图

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Game Assets | 0.2.1 → **0.3.0** | 新增 **Codex** 来源：在工作区所在的机器上运行已登录的 `codex exec`，用 Codex 自带的生图工具，不需要地址和密钥（消耗那个 ChatGPT 账号的 Codex 额度）。新建来源默认就是 Codex。生成对话框新增「项目里的 agent」：把选中的来源记录到项目后，项目里会有 `.game-assets/`（来源信息、生图脚本 `generate-image.cjs` 和说明），`AGENTS.md`、`CLAUDE.md` 里会加一段用法说明，任何 agent 都可以运行 `node .game-assets/generate-image.cjs --prompt … --out …` 生图。 |

源码与版本提交：`b740f96`；市场包：`8636ebb3187ee5cd0a71548460be07220c78c1c7`；市场索引：`4cf733a`。

### 使用前要做的事

- 用 Codex 来源前，在工作区所在的机器上运行一次 `codex login`。本地工作区是 DSH 所在的电脑，远程工作区是那台远程机器。
- 项目记录的是 OpenAI 兼容或 Gemini 来源时，密钥会保存到项目所在机器的 `~/.dsh-game-assets/keys.json`（仅本人可读），远程工作区经 Remote Agents 的上传通道传过去，不会写进项目，也不会出现在命令行里。在别的机器上可以用 `DSH_IMAGE_API_KEY` 环境变量提供密钥。
- 在设置里修改来源后，项目里的记录不会自动更新，需要在对话框里点「重新写入」。

### 验证

- 92 项测试全部通过（新增 12 项：用假的 Codex 命令行验证调用参数、提示词、登录 shell 和各类失败提示；项目文件的写入、替换和移除，包括 `CLAUDE.md` 链接到 `AGENTS.md` 的情况；项目脚本在 Codex 和接口两种来源下的运行；远程工作区上传密钥和脚本；对话框和设置页的交互），类型检查和构建通过。
- 把本次打出的包装进全新的 DSH 0.2.2-rc.2 网页环境：新建来源表单默认是 Codex、只有名称和模型；把 Codex 记录到项目后写出 `.game-assets/` 三个文件，已有的 `AGENTS.md` 保留原内容并在末尾加了说明段，`CLAUDE.md` 新建；从项目中移除后 `AGENTS.md` 恢复原样，新建的文件都删掉；对话框调用这台 Mac 上真实的 Codex，正确显示了登录失效的提示；在项目里像 agent 一样运行脚本，用假 Codex 生成并保存成功。

### 未验证

- 登录正常的 Codex 真正出图（测试机器上的 Codex 登录已失效）；远程工作区里的 Codex（只在测试里模拟了远程机器）；桌面应用、手机；没有安装到任何一台机器上。

### 安装

```text
git+https://github.com/lalaze/dsh-plugins.git#8636ebb3187ee5cd0a71548460be07220c78c1c7&path:/packages/game-assets
```
