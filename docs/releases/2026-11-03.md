| 插件 | 市场旧版 → 本次版本 | 内容 |

验证：`dsh-mobile` 23 项测试通过，类型检查与构建通过；Playwright 的 12 项交互检查通过，浅色与深色截图检查了新图标。已部署到 `dsh.lalaze.com`，公网返回的清单颜色已是深色。未实测：真机上导航栏变深（取决于 Chrome 何时更新已安装的应用）。

## 基于项目新建工作区（Git worktree）

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.72 → **0.2.73** | 「添加工作区」新增「基于项目」标签页，和 Paseo 新建 worktree 工作区一样：从工作区里的某个 Git 项目（本机或已保存的远程机器）新建分支（选起点分支，名字可留空自动生成，如 `swift-otter`）或检出已有分支（只在远程的分支会建立跟踪），插件在仓库之外创建 Git 工作树——本机放在 `~/.dsh/worktrees/<仓库>-<hash>/<分支>`，远程放在 `~/.dsh-remote-agents/worktrees/...`——以「项目 · 分支」为名加入 DSH，排在项目后面并继承它的 Workspace Tags 标签，然后打开。起点为远程分支时先拉取（最多 15 秒），新分支不跟踪起点，避免误推到 main。仓库里提交的 `.dsh/worktree.json` 可列出初始化与清理命令（`setup`、`teardown`，环境变量 `DSH_SOURCE_CHECKOUT_PATH`、`DSH_WORKTREE_PATH`、`DSH_BRANCH_NAME`），输出实时显示，可关窗后台继续；失败时可重试、跳过或删除这个工作树。不读取 `paseo.json`。同一页列出项目的工作树，可打开或归档：归档前提示未提交文件和未推送提交，然后归档其中的会话、停止在里面运行的远程 CLI、运行清理命令、删除工作树并从 DSH 移除；分支默认保留，只有已合并到默认分支时才可勾选一并删除。远程机器只需要 Git 和 POSIX shell，不需要 Node.js。没有保存机器时，只要有 Git 项目，「添加工作区」也会打开这个对话框 |

验证：新增 9 项测试，用真实 Git 仓库覆盖新建与检出远程分支、子文件夹工作区、初始化命令的重试/跳过/删除、归档检查与归档（含删除已合并分支）、经 SSH 端 shell 程序的远程流程，以及停止远程初始化命令时一并结束其子进程。经真实 SSH 在没有 Node.js 的 `docker` 主机临时目录里跑通创建、初始化、归档检查、清理命令和删除已合并分支，结束后主机恢复原状。全量测试 398 项，失败与取消的用例与未改动的 main 相同（中继套件被成批取消、端口转发一项）；类型检查与构建通过。界面在预览环境中用真实 Git 仓库截图检查了深浅色、分支选择、进度、失败处理和归档确认；原有界面测试中添加工作区的检查全部通过（编辑器 Ctrl+S 保存一步在 main 上同样失败）。未实测：DSH 桌面版中的效果（图形界面进程里初始化命令的 PATH、DSH 接管新工作区、标签继承）。

## 按状态分组时可拖动会话排序

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Workspace Tags | 0.2.0 → **0.2.1** | 按状态分组时，“等待你处理”“已完成”“运行中”三个分区里的会话现在可以拖动排序，以前这三个分区禁止拖动，只能切回“按工作区”分组再拖。放下后保存该工作区的会话顺序（与在“按工作区”分组下拖动一样，会把排序方式切换为“手动排序”），在各种分组下和重启后都保持不变；顺序按浏览器分别保存。拖动只在出发的那一份工作区里有效：同一工作区可能同时出现在多个标签分区，或同时出现在“等待你处理”和“已完成”里，会话不会落到另一份里，另一份里也不再显示插入标记（标签分区原有此问题）。分区只显示部分会话时，未显示的会话位置不变 |

验证：新增 2 项测试（状态分区内拖动并保存顺序、只显示部分会话时隐藏会话位置不变、不能跨分区放下；标签分区内拖动不落到同一工作区的另一份），在改动前的代码上这 2 项失败；`dsh-workspace-tags` 18 项 node 测试和 299 项 vitest 通过，类型检查与构建通过。未实测：在 DSH 桌面版中实际拖动（拖放沿用 DSH 原有逻辑，“空闲”和标签分区在真实 DSH 中本就可拖）。
