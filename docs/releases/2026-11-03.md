## 手机端改得更适合手机使用

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Mobile | 0.2.0 → **0.3.0** | 只改手机应用，插件服务端未动。手机的返回手势先关闭打开的面板或图片，再离开当前页面；面板也可下拉关闭。工具调用每次一行，写明做了什么、对什么做的（运行命令、读写或编辑哪个文件、搜索什么），连续的合并为一组，点开看详情：命令及输出、编辑的红绿差异、计划清单，失败标红；后台任务同样显示。待批准（附完整命令）和提问固定在输入框上方，按钮整行加大，选项是大卡片。发出的消息立即显示，未发的草稿按会话保存、应用被系统关闭后仍在。对话在新内容、图片加载或键盘弹出时保持在底部，向上滚动自动加载更早的消息且位置不跳，有“回到最新”按钮，下方有新消息时带蓝点。会话列表：标题改为 DeepSeek Harness，搜索收进放大镜，“显示已归档/子智能体/工作区外”改为显示选项面板里的开关，下拉刷新，长按会话重命名或归档，等待处理的会话在标题下写明在等什么，打开会话再返回时保持滚动位置、搜索和展开状态。新建会话：工作区卡片加最近用过的工作区，配对多台电脑时可选在哪台运行。另有离线横条（可重试）、可关闭的错误提示、加载骨架、代码块复制、全屏看图、页面切换动画；按钮和行不小于 44px，输入框 16px（iPhone 不再放大），换行键不再显示“发送” |

验证：`dsh-mobile` 23 项测试通过，类型检查与构建通过。手机界面在模拟的电脑与中继上用 Playwright（390×844 手机视口、触摸）跑了 21 项交互检查，全部通过：返回手势关闭面板（包括面板切换面板）、工具详情、回到最新、立即显示与替换、草稿保留、列表滚动位置、长按（及其抬起后的点击不误关面板）、下拉刷新、提问提交、新建会话后返回到列表、窗口变矮仍停在底部、加载更早消息不跳位、离线横条；浅色与深色均截图检查。手机应用已部署到 `dsh.lalaze.com`。未实测：真机（Android、iPhone）、真实 DSH 数据下的工具调用样式。

## 手机端修复：深色底栏与图标

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Mobile | 0.3.0 → **0.3.1** | 只改手机应用。安装到 Android 主屏后，深色模式下输入框下方的系统导航栏是白色的：Android 用应用清单的颜色画这条栏（Android 14 及以前用 `theme_color`，15 起透出 `background_color`），而清单只能写一个颜色，原来两者都是白色；现改为深色主题的底色，页面顶部状态栏仍跟随手机的深浅色设置（代价是浅色模式下底栏也是深色）。清单地址不变，已安装的应用经 Chrome 每天一次的清单检查自动更新。全部界面图标换成 Lucide（与 Paseo 相同的图标集），原来手画的图标风格不一、设置齿轮不对称；`scripts/vendor-lucide.mjs` 把用到的 40 个图标拷进应用，不增加运行时依赖，许可证见 `THIRD_PARTY_NOTICES.md` |

验证：`dsh-mobile` 23 项测试通过，类型检查与构建通过；Playwright 的 12 项交互检查通过，浅色与深色截图检查了新图标。已部署到 `dsh.lalaze.com`，公网返回的清单颜色已是深色。未实测：真机上导航栏变深（取决于 Chrome 何时更新已安装的应用）。

## 远程 CLI 看过和生成的图片显示在对话里

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.70 → **0.2.71** | 远程 Claude 或 Codex 用工具看过或生成的图片，现在显示在回复里它用到这张图的位置，同一次回复中每张图只显示一次：Claude 截的屏和用 Read 打开的图片、Codex 用 `view_image` 看的图片、Codex 生成的图片，以及 MCP 工具返回的截图。以前这些图只交给了模型，对话里一张也看不到。实际遇到的情况：一段 Claude 会话说着“看它的写法：”读了 36 张截图和素材图，DSH 里一张都没显示。CLI 输出里带有图片本身的（Claude、MCP、生成的图片），副本取自输出、存进 DSH 所在机器的 `chat-images/`，图片数据不写进共享历史；Codex 的 `view_image` 只报告路径，显示回复时从远程机器读取这个文件（不超过 20 MB、按文件头确认是图片）。跟随共享会话的其他 DSH 同样按路径读取，只存在于 CLI 输出中的图片（如 MCP 截图）只在驱动该回合的 DSH 上显示。更新前的图片不会补上，ACP CLI 暂不支持 |

验证：新增 5 项测试（Claude 与 Codex 的图片记录、对话中显示与去重、按路径读取远程图片、绝对路径读取的大小与符号链接限制），用 Claude 中继日志里的真实读图结果回放、用 Codex 0.164 实际跑 `view_image` 和生图各一轮核对输出格式；经真实 SSH 读取 `/tmp` 下的截图和 Codex 生成的图片，与原文件逐字节一致。在只含本次改动的干净工作区中，全量测试 360 项通过，失败与取消的用例和未改动的 main 相同（中继套件在全量运行时被成批取消、端口转发一项在 main 上同样失败）；类型检查与构建通过。未实测：在真实 DSH 界面中的显示效果。

## 智能体团队可以用远程 CLI 当成员

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.71 → **0.2.72** | 配合 NanmiCoder 的 `dsh-agent-teams`（0.1.28），团队成员可以用远程 CLI（Claude Code、Codex 等）当模型，队长仍是 DSH 模型。以前这样做必定失败：队长分配的任务带着 AgentTeams 自己的消息来源，被当作 DSH 注入的上下文跳过，CLI 反复执行第一个任务；CLI 拿不到团队工具；它请求的授权在成员会话里一律被拒，Codex 随之取消整个回合。现在任务和协调消息作为提示发给 CLI，新 CLI 会话开头说明一次团队工具的用法；四个成员工具经 MCP 桥以 `dsh-agent-teams` 提供给 CLI，在 DSH 里以该成员身份执行，队长工具不给，也不需要打开 MCP 共享。审批策略为 `never` 的委派子会话视为无人值守：沙箱即其权限，Codex 以 `approvalPolicy: never` 启动，Claude Code 在“工作区内修改”时用自带沙箱运行命令，其余授权请求直接拒绝（选 Codex 的 decline 而非 cancel），CLI 继续工作并报告。`remote_workspace` 让这类 DSH 模型成员直接修改工作区文件，远程命令仍需审批。普通对话里拒绝 Codex 的单个请求也改选 decline，不再结束回合 |

仓库里的“协作开发” skill（`skills/delegated-dev`）已删除，按模型分工改用 `dsh-agent-teams`。

验证：新增 15 项测试（成员识别与消息来源、成员说明、无人值守权限与拒绝方式、成员工具经桥列出与调用、Codex `never` 与 Claude 沙箱参数）。在独立的 DSH 配置（0.2.1-rc.5，本地 Qwen 当队长，SSH 到本机当远程机器）实测：Codex 成员领任务、实现、跑测试并汇报；Qwen、Claude Code（haiku）与 Codex 三人团队分别完成新文件、改函数加测试和审核，交付后 6 项测试通过；合并 0.2.71 图片改动后用 Codex 成员复测通过。全量测试 389 项，失败与取消的用例都是改动前就失败的中继和端口转发用例；类型检查通过。另先单独验证了 Claude Code 2.1 的 `--settings` 沙箱在 `-p` 模式下自动运行命令。未实测：DeepSeek 当队长或成员、Linux 主机上的 Claude 沙箱、DSH 网页里的团队面板。
