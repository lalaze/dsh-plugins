## Remote Agents 0.2.124 — TUI 对话默认用 WebGL 绘制

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.123 → **0.2.124** | TUI 对话的终端默认用 WebGL 绘制，右下角开关仍可关闭并会记住；旧版本存下的"关"不再算作选择（旧版拨任一开关都会顺带存下它）；浏览器用不了 WebGL 或中途失效时仍用网页自带的渲染。背景模糊、侧栏终端、holder 和 SSH 都没有改动。 |

源码与版本提交：`145018248acf61a1add2bdf1741ad006c3daee47`；市场包：`628820c9bd073351089f689184da076f6874279b`；市场索引：`508b3e2bb6f9ddb967403b2383b8b814b21f0be8`。main 与 market 已原子推送，远端分支 SHA 已核对。

### 依据

隔离环境：DSH 0.2.2-rc.1（只读借用中枢的运行时，独立 home 和端口）、真 Chrome（Apple M4 GPU，2 倍缩放）、经 SSH 连本机、真实 Claude Code 2.1.321 停在输入框、终端 113x50，每轮 60 个按键。

| 渲染方式 | 按键到 xterm 绘制后的下一帧（中位数，两轮） | p90 | 每键占用页面主线程 |
| --- | --- | --- | --- |
| 网页自带（DOM） | 43.4 / 44.4 ms | 约 51 ms | 约 11.5 ms |
| WebGL | 26.9 / 25.5 ms | 37–49 ms | 约 2 ms |

- 原因：Claude Code 每回显一个按键都会把光标移到屏幕顶再移回来，xterm 把所有行标为已变，DOM 渲染每键重建 50 行，耗时主要是这些行的样式计算。DOM 下按键后回包还会被 Chrome 推迟到下一帧之后才处理（首个回包中位数 9–10 ms，WebGL 下 1.5–1.8 ms）。
- 关闭背景模糊对延迟没有影响（DOM 45.8 ms，WebGL 25.7 ms），所以默认不变。
- 已排除：DSH 0.2.2 的光标对比度监听（单独关掉后总耗时不变，只是样式计算换了时机）。
- 主线程数字来自带跟踪和 CPU 采样的运行，已减去同条件空闲时的开销（每 120 ms 约 8.5 ms）。

### 验证

- 干净工作树执行 `pnpm --filter dsh-remote-agents run check` 退出 0：787 项测试，763 通过、24 跳过（均为需要显式环境变量的真实运行时测试）、0 失败；类型检查和构建通过。
- 用发布的同一份构建在隔离环境实测：没有存档时为 WebGL（26.4 ms）；旧版存档 `{"webgl":false,"blur":true}` 时为 WebGL（27.8 ms）；本版关掉后的存档（带 `version: 2`）保持 DOM。机器当时负载较高（load 11–16），同条件重跑 DOM 48.8 ms、WebGL 26.6 ms。
- 发布预演只列出本插件；Workspace Tags 0.3.0 的既有同版本内容差异继续跳过。市场变更路径仅为 remote-agents 的 6 个文件和索引；`lib/terminal-holder.mjs` 与 0.2.123 逐字节相同，已运行的终端 holder 不受影响。
- [公开市场索引](https://raw.githubusercontent.com/lalaze/dsh-plugins/market/index.json) 已返回 0.2.124 及上述市场包提交；固定版本清单返回 HTTP 200；公开 `lib/client.js` 与隔离环境里实测的构建逐字节一致，SHA-256：`0e07574508fa9a7bbf346048e70f849af6a9792f2c34ec2387d167040bbf5f4a`。

## Remote Agents 0.2.126 — 不再在 SSH 主机上留下 CodeBuddy 进程

| 插件 | 市场旧版 → 本次版本 | 内容 |
| --- | --- | --- |
| Remote Agents | 0.2.125 → **0.2.126** | 列模型、查用量和不经 relay 的会话直接通过 SSH 启动 CLI。断开时远端只读到输入结束，`codebuddy --acp` 不退出，每次检查都在主机上留下一个进程。现在这类启动由一个很小的 Node 守护进程带着 CLI：输入结束后等 2 秒，再 TERM，5 秒后 KILL；CLI 自己退出时退出码照常传回。relay 连接和其他命令不变；主机没有 Node 时和以前一样。 |

源码与版本提交：`57e12feabc159aab0023ab77b86f996eeaf610c1`；市场包：`477a40e6055021fdf7045d7f9a338324f31faad6`；市场索引：`971a351a285b3bdf1c68a188c585188956dcb7c5`。main 与 market 已原子推送，远端分支 SHA 已核对。

### 依据

Mac mini 上有 102 个父进程为 launchd 的 `codebuddy --acp`（10 月 26 日至 11 月 10 日，约 3.5 GB），环境变量显示是 DSH 经 SSH 在 `/Volumes/data/code/dsh-plugins` 启动的；另有 10 月 27 日的 4 个 `dsh --profile acp`。macOS 权限服务卡住期间，它们每 5 秒重试一次读外置盘。本机复现：`codebuddy --acp` 输入关闭 9 秒后仍在运行；按旧写法经真实 SSH 启动并停止，留下 1 个父进程为 1 的孤儿。

### 验证

- 新增测试：`test/ssh-transport.test.ts` 4 项（不读输入的 CLI 在停止后约 2 秒被 TERM 结束；忽略 TERM 的 CLI 5 秒后被 KILL；输入原样送达、CLI 自己以 7 退出时会话立即结束并带回退出码；读到输入结束自行退出的 CLI 不收到信号；只有直接启动的 CLI 才带守护进程），`test/direct.test.ts` 1 项（CodeBuddy、Claude、Codex 的模型检查和不经 relay 的会话都带 `endWithSession`）。第一项在旧代码上失败。
- 经真实 SSH（本机 127.0.0.1）用新代码启动并完成 ACP/JSON-RPC 初始化后停止：`codebuddy --acp` 停止后 2.5 秒结束，`dsh --profile acp` 与 `codex app-server` 0.5 秒内自行退出，均无孤儿。
- 中途试过的 shell FIFO 方案被放弃：macOS 上 Node 从命名管道读不到输入结束，导致 relay 测试失败。最终方案不改变 relay 连接。
- 类型检查通过。整套测试 793 项：767 通过、24 跳过、2 失败；失败的 `shared-sessions` "a message names the DSH…" 单独重跑 3 次过 2 次（已知偶发），`terminal-holder` "SIGTERM ends what runs in the holder" 单独重跑 3 次全部通过，两者都不经过本次改动。
- 发布预演只列出本插件；Workspace Tags 0.3.0 的既有同版本差异继续跳过。公开市场索引（按提交读取）返回 0.2.126；市场包内 `lib/server/core/ssh.js` 含守护进程，`backend.js` 三处调用带 `endWithSession: true`。

没有在真实 DSH（桌面应用或隔离环境）里装上新版本观察；没有更新 Mac mini 中枢，没有重启任何 DSH。已经留下的孤儿进程不会被自动清理（本机的已手动清掉）。
