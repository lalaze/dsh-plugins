# 普通对话共享（`shared-native-v1`）

[English](native-sharing.md)

普通 DSH 对话通过**显式交接和关联续聊副本**跨设备继续，不转换成远程 CLI，也不覆盖 GUI 正在持有的原生日志。版本、市场发布及部署状态统一见[仓库发布记录](https://github.com/lalaze/dsh-plugins/blob/main/docs/releases/2026-11-09.md)。本轮隔离运行时验收已通过，使用 DSH **0.2.2-rc.1** 的真实原生服务、临时存储和替身模型；尚未进行两台实体 Mac、真实 GUI/账号的端到端验证，也未验证其他宿主版本。

## 支持的能力

- 明确映射的普通本地工作区，以及原有的已验证 SSH 远程工作区。
- 完整的用户/助手消息、工具调用/结果/流、已有压缩与被压缩的原始历史；续聊后可以继续产生新的手动或自动压缩、标题和普通命令。
- 原生文件及图片附件。图片传输实际内容，保持原始字节、SHA-256 ID 和引用，不把源机器临时路径当作附件。
- 接收端正常工具集，继续使用原生沙箱和审批；不再只允许 `remote_workspace`。
- goal、排队输入、定时任务及可继续的子会话树的持久状态。导入不执行任务，明确恢复后才继续。

不能迁移的是**正在运行的系统进程、终端、工具执行和进程内句柄**，不是一概拒绝自主任务。运行中的轮次、工具和后台 job 必须先到达安全边界、完成或停止；已结束 job 的历史可以保留。

## 启用与工作区映射

1. 两端添加同一个 SSH 主机和账号。在 **设置 → 远程智能体 → 普通 DSH 对话** 分别开启接收。只接收用户明确发布到该主机的普通对话，不扫描私人会话；CLI 共享开关独立。
2. 对普通本地工作区，两端都将**同一个来源项目标识**映射到各自明确确认过的本机目录。例如来源标识为 Air 的项目绝对路径，Air 映射到本机目录 A，Mini 映射到本机目录 B。确认的是解析后的真实目录；不根据同名文件夹猜测，不自动创建目录，不把远程 anchor 当作本地项目。
3. 已验证远程工作区继续使用已验证的 SSH 主机、账号与远程项目，不需要伪装成本地映射。缺少本地映射时可以保留/查看共享历史，但不能静默回退到远程目录执行。映射在导入前确定，活动副本不能随意换绑。
4. **代码文件不随对话同步。** 两台机器上的代码、依赖和工具环境由用户准备；对话中的文件附件另按附件协议迁移。接收端须自行配置可用的普通模型、提供方和必要插件，不复制源端凭据或 profile。

## 分享、续聊与交接

1. 打开目标对话，核对标题和 ID，选择共享并关闭当前对话续写。对话须有完整内容，正在执行的工作先完成或停止。源原生日志保留，并持久选择不可用模型以防误续写。
2. 选择 **在此继续** 时，先原子取得所有权，再导入**新的本地原生会话 ID**，绑定已确认的接收端目录。整个 lineage 的共享 ID 保持不变；不会用相同 session ID 覆盖两端日志。
3. 只读历史以冷导入方式显示，不创建活 Agent，不调用模型或工具。同步轮询约每 30 秒进行；已有视图在明确打开最新历史时刷新，旧视图保留并归档。
4. 完整轮次结束并空闲后发布增量检查点；通常约 1 秒触发，轮询会重试。交接时冻结可恢复状态、发布最终检查点并关闭此副本，再由另一端取得所有权。关闭面板或浏览器不释放所有权。

每个导入 Agent 使用**接收端默认 preset**，重新组装 system、runtime-context 和工具声明。在 `agent/created`、首条输入前应用只读沙箱与 `ask` 审批；子会话冷恢复也受约束。源历史中的高权限配置不会自动成为接收端执行权限。用户可以通过 DSH 原生控件明确调整本机权限，导入器不自动提权。

## 自主状态与子会话

- **Goal：** 保留原 goal ID 和持久状态，不迁移进程内的自动续行资格。冷导入不调用 create/resume，不自动续轮；用户明确恢复后才重新启用续行。源端活跃 goal 在冻结时暂停。
- **排队输入：** 冻结前先持久备份，再清理原队列；接收端保留为待恢复输入，不因打开历史而消费。冷子会话尚未恢复时明确报告“未接收”；按原生方式恢复子会话后，用户可以显式重试。
- **定时任务：** 源端按 revision/更新时间检查后暂停；接收端先保存待恢复描述，明确恢复才创建或启用。原本暂停的任务不自动启用；过期一次性任务保留原时间并标为过期，不改成“立即运行”。
- **子会话树：** 冷导入 root、child 和 grandchild 的完整日志与附件，只重建 header 和父自身 catalog 中的结构化身份。历史消息、工具原文、descriptor 和署名不全局替换。旧 ID 通过当前树作用域内的控制工具别名解析，仍执行原生父子邻接和授权检查；旧展示链接不保证都能定位新副本。
- **接收回执：** 区分确定未接收、结果未知、已接收及冲突。队列/goal 以持久日志边界、消息 ID 与完整 envelope、goal ID/revision 和原生事件对账；定时任务按保存的请求、目标、已有任务基线和创建区间核对。没有充分证据时保持未知，不按相似文本猜测，不自动重发。确认状态后再由用户明确重试。

完整自主状态包随检查点保存，不能只同步 root 的事件后缀。续聊中新建的子节点也绑定同一个写者；多轮往返发布前会归一化结构化 ID，而不修改用户原文。

## 单写者、故障与恢复

SSH 账号的私有目录 `~/.dsh-remote-agents/shared-native-v1` 与 CLI `shared-v1` 分离。记录包括稳定 UUID、单调版本、摘要、去重回执和**不自动过期的 owner/token**。多进程排他锁串行执行 CAS，私有临时文件经 fsync、原子 rename、目录 fsync 发布。没有超时抢占或离线双写；登记锁异常时拒绝操作，不自动删除可能仍有效的锁。

根及所有子会话在步骤、请求/重试、模型流和工具派发前检查同一根所有权；命令、标题及压缩也受约束。失联拒绝新的生成和工具派发，已开始的生成可能本机结束，但另一端不能接管仍被持有的记录。检查点校验 owner/version/digest 和既有事件前缀；无变化不重复发布。

冻结过程先落盘备份。归档或最终检查点失败后，稳定的 `pendingFreeze` 跨重启保留并阻止继续写入；用户可重试原操作或明确回滚，不能靠新版本号绕过并丢弃已清空的队列。回滚保留输入和原任务状态，恢复执行仍需明确操作。

重启不自动继续原 active 副本。恢复最后已确认共享检查点时对账待确认操作、封闭旧副本，再创建新的续聊副本；本地未发布尾部、原件及被拒绝输入保留，不自动合并或丢弃。原生 pre-step 发生在 inbox claim 之后，无法回滚 claim，因此拒绝前会保留确切输入供人工恢复，不自动重发。

release/archive/withdraw/delete 已提交但丢回包时，通过持久回执完成对账并清除旧 token，不重复 release 或越权新 owner。失败加入的取消先由远端写入墓碑，隔离延迟 create；确认取消后才能恢复原对话。失联或已被 claim 时保持关闭。取消加入和回滚不会悄悄重启原自主任务。

归档保留共享历史；停止共享/删除共享历史将远端载荷替换为墓碑，但不擦除其他设备已经保存的原生副本。要独立私聊，明确创建私人分支并选择普通模型，新 ID 不自动加入共享。关闭接收或移除 SSH 主机前，须先处理本端 owned/pending 状态。管理员检查登记锁时必须核对确切进程并保留记录，不能仅凭 PID 或时间推断锁已失效。

## 内容与兼容边界

- 每会话最多 32 个附件引用；单文件 2 MiB、单图片 4 MiB，图片支持 PNG/JPEG/WebP/GIF。整棵树附件合计 6 MiB，单快照/请求 12 MiB；自主状态最多 64 个子会话、256 个定时任务。超限明确报错，不静默截断上下文。
- 附件只经宿主登记引用和 AttachmentStore 读取，校验规范 base64、SHA-256、长度及元数据。图片通过经过审查的无损发布适配器导入，不能随意再次编码并改变 ID。
- 只解析真实消息/stream 的内容块。工具 `meta`、schema 以及文本中的路径是不透明历史；不会因为字段叫 `resource` 或 `spillPath` 就读取文件或拒绝普通数据。未知的真实内容块、事件/格式或必需宿主能力仍明确拒绝。
- 外部 spill/cache 对象及第三方活资源句柄尚无已验证的可移植导出能力；不会按路径猜读。已落入原生日志的完整工具输出按原样迁移。认证、账号存储、机器配置和代码目录不复制。
- 用户明确共享的文字、工具输出及附件会完整复制；能登录该 SSH 账号的人也可能读取。两端应保留插件安装；插件不能控制卸载后人工改日志或明确创建的私人分支。
