# DSH Remote Agents 更新日志

[English](CHANGELOG.md) | **简体中文**

按版本从新到旧列出变化及升级后需要做的事。

**从 0.2.59 升级：** 远程工作区的文件改用 VS Code 的编辑器 Monaco 打开，取代原来的代码编辑器：缩略图、查找与替换、多光标、基于单词的补全、命令面板（F1）、⌥/Alt+Z 切换自动换行、JSON 错误检查，以及显示光标位置、缩进、换行符和语言的状态栏。编辑器菜单跟随 DSH 的语言。编辑器在第一次打开文件时从插件加载，客户端本身因此更小。更新后请重启 DSH 并刷新客户端。

**从 0.2.58 升级：** 远程工作区中的图片可以正常加载，不再报 `Unexpected end of JSON input`；「下载」也恢复可用。DSH 无法把下载请求交给插件的上传路由处理，因此自远程工作区面板推出以来，这两项在 DSH 中一直无法使用；现在下载有了独立的路由。在到达插件之前就失败的传输会显示 HTTP 状态码。在右侧栏的「工作区文件」中选择文件时，会像 DSH 自带的文件浏览器一样，在列表旁新开一个标签页打开，而不是显示在列表下方；这样的标签页和对话中的文件链接一样只显示该文件，并跳到链接指定的行。更新后请重启 DSH 并刷新客户端。

**从 0.2.57 升级：** 远程工作区的文件改用代码编辑器打开，支持语法高亮、行号、搜索（⌘/Ctrl+F）和括号匹配，不再是纯文本框。图片直接显示为图片，不再提示“二进制文件”；点击图片可在适应窗格和实际大小之间切换。Markdown 和 SVG 文件可在「编辑 / 预览」间切换。使用 CRLF 换行的文件保存后仍保持 CRLF，原来的文本框做不到这一点。本地工作区可安装新插件 `dsh-file-editor` 获得同样的编辑器。更新后请刷新客户端。

**从 0.2.56 升级：** 模型菜单的提供方分组折叠拆分为独立插件 `dsh-model-groups`，安装它即可继续折叠。已保存的折叠选择会保留；如果仍在使用自带折叠功能的旧版 Remote Agents，`dsh-model-groups` 会让给它处理。本地隧道的「打开」链接和「启动远程 DSH」改用浏览器访问 DSH 时所用的地址，不再使用插件内写死的地址。更新前启动的托管远程 DSH 仍信任旧地址；如果它拒绝新地址，请停止托管实例后重新启动。更新后请重启 DSH 并刷新客户端。

**从 0.2.52 升级：** 设置中移除了「从 dsh-remote 导入机器」，请通过「添加机器」添加。dsh-remote 创建的工作区可继续使用。机器卡片更紧凑：共享说明改为悬停提示，修改 CLI 后才显示 **应用选择**。更新后刷新客户端。

**从 0.2.50 升级：** 会话和远程工作区会与连接同一个 SSH 账号的所有 DSH 共享，见[多个 DSH 共享会话](#多个-dsh-共享会话)。更新并重启 DSH 后，DSH 第一次连上机器时会把已有会话连同历史发布到这台机器。某台机器的会话只想留在当前 DSH 时，在机器卡片中关闭共享。

**从 0.2.41 升级：** 使用量统计中，Claude Code 的轮次按实际作答的模型记录：以别名选择的模型（如 `opus`）在「按模型」中显示为完整的模型 ID（如 `claude-opus-5-5`）。更新前记录的轮次仍显示别名。更新后重启 DSH。

**从 0.2.40 升级：** 在设置中打开的「远程工作区」窗口里，在文件搜索框按 Esc 只清除搜索，不再关闭整个窗口。

**从 0.2.39 升级：** 远程工作区面板去掉了「命令」页，请改用「新建终端」，在远程对话中它会直接打开远程 Shell。在远程对话中，侧栏「远程工作区」现在只有同步、隧道和远程 DSH，文件在「工作区文件」里。文件编辑器支持 ⌘/Ctrl+S 保存，可以关闭文件；新建的文件会直接打开，有未保存修改时也能浏览文件夹。「添加并启动」会立即启动新隧道，「启动远程 DSH」会一并完成连接。面板较窄时，没打开文件的情况下文件列表占满整个面板。

**从 0.2.38 升级：** 远程模型回复过程中退出 DSH 或重新加载插件，不会再把这条回复标记为**失败**并显示 `The operation was aborted`，而是正常结束，并注明远程 CLI 仍在运行。再次打开该对话时会自动同步：先出现一条 **Remote CLI output produced while DSH was disconnected** 提示，随后显示断开期间的输出，并跟随远程回合直到结束。不会再向远程 CLI 发送任何内容。更新前被截断的回复仍显示为失败，但同样会自动同步。更新后重启 DSH。

**从 0.2.37 升级：** 在远程对话中，「新建终端」及其快捷键现在直接打开远程工作区的 SSH 终端，不再打开本地 Shell，也无需在 Shell 菜单中选择 **Remote workspace**。回到本地对话后，仍打开你原来使用的 Shell。更新后重启 DSH 并刷新客户端。

**从 0.2.36 升级：** 「新建终端」在所有对话中沿用上次选择的 Shell，因此选过一次 **Remote workspace** 后，本地对话会报错 `Select a verified remote workspace before using this shell.`。现在不在远程工作区时，它会改为打开本地 Shell，并在第一行注明；标签标题仍显示 **Remote workspace**。更新后重启 DSH。

**从 0.2.35 升级：** 远程工作区的文件、搜索、同步和命令不再需要 SSH 主机上有 Node.js，改用主机的 shell 和常用命令行工具（另需 `sha256sum`、`shasum` 或 `openssl`）。没有 Node.js 的主机（例如使用独立 Codex 的 Docker 主机）不会再报 `node: not found`。DSH 模型的 `remote_workspace` 工具改为遵循对话的 DSH 权限：**完全权限**和**自动审查**时直接修改文件、执行命令，不再询问（此前完全权限会拒绝每一次修改），**工作区内修改**时只在执行命令前询问。命令超时后会停止它启动的所有进程。远程 CLI 和远程 DSH 仍需要 Node.js 18+。更新后重启 DSH 并刷新客户端。

**从 0.2.34 升级：** 「远程工作区」面板改用新布局：工具改为标签页，控件统一放在卡片中，隧道列表带状态圆点和图标操作，文件浏览器带图标和可点击的路径。功能不变。更新后刷新客户端。

**从 0.2.33 升级：** Codex 快速模式改为输入框工具栏上的闪电按钮，模型菜单里不再有单独的 **Fast** 条目。开关按会话保存，新会话默认关闭；仍停留在旧 **Fast** 条目上的会话会换到该模型的条目，并点亮闪电。每个远程模型还会记住上一条消息使用的推理等级，切换模型或重启后依然保留。更新后刷新客户端。

**从 0.2.32 升级：** 上下文用量环与模型选择之间的间距收紧了。更新后刷新客户端。

**从 0.2.31 升级：** Codex 新增「工作区可写 · 自动审查」模式，DSH 的「自动」权限现在会选中它：需要越过沙箱的操作由 Codex 的审查子 agent 决定放行或拒绝，不再询问你。没有自动审查功能的旧版远程 Codex 会忽略这个设置，仍然询问你。已保存的 Codex 模型目录无需刷新即可使用该模式。

**从 0.2.30 升级：** 模型菜单的分组标题现在和模型行一样高，带有展开时会旋转的箭头、数量标记和悬停高亮。分组折叠或展开后，Codex 订阅菜单会重新定位。更新后刷新客户端。

**从 0.2.29 升级：** 远程 CLI 在回复中按工作区路径引用的图片，现在可以在原生聊天中显示。每张图片会复制到 DSH 主机上插件状态目录下的 `chat-images/`。更新前已保存的回复仍显示替代文本。

**从 0.2.28 升级：** 当 Codex 订阅插件（`dsh-codex-subscription`）接管模型菜单时，提供商分组重新可以折叠。该菜单不显示提供商 ID，因此这些分组按提供商名称记住折叠状态。更新后刷新客户端。

**从 0.2.27 升级：** 在远程工作区的对话中，右侧栏的「工作区文件」和 ⌘P 会打开远程文件，「远程工作区」也只在远程对话中列出。本地对话仍使用 DSH 自带的「工作区文件」。更新后刷新客户端。

**从 0.2.26 升级：** 新增集成的**远程工作区**面板（文件、命令、同步、隧道和远程 DSH），并为 DSH 模型提供 `remote_workspace` 工具，详见[集成的工作区工具](#集成的工作区工具)。可在**设置 → 远程智能体**中导入 dsh-remote 保存的机器。更新后重启 DSH 并刷新客户端。

**从 0.2.25 升级：** 在模型行不带模型 ID 的 DSH 版本（例如桌面版）中，模型菜单的提供商分组重新可以折叠，这些分组按提供商名称记住折叠状态。原本可折叠的分组保留已保存的选择。更新后刷新客户端。

**从 0.2.24 升级：** 远程 CLI 启动失败的对话（例如 SSH 主机缺少 Node.js），在主机修复后不再一直提示“智能体仍在运行”：下一条消息会以该消息启动 CLI，并保留之前的消息作为上下文。更新后重启 DSH。

**从 0.2.23 升级：** SSH 主机无法运行后台中继时（登录 PATH 中没有 Node.js 18 或更新版本，或无法安装中继），不再启动远程 CLI：回复会直接失败并说明原因，而不是悄悄改用随 DSH 结束的 SSH 直连。请在这类主机上安装 Node.js 18 或更新版本。新对话的标题取自你的第一条消息，而不是 DSH 的标题生成指令；已有标题不会改变。更新后重启 DSH。

**从 0.2.22 升级：** 主对话中的 Claude 和 Codex 改为跟随对话的 DSH 权限（输入框或 `/permission`），不再总是沿用远端 CLI 设置：工作区内修改时 Claude 使用“自动允许文件编辑”，完全权限时不再逐项审批，自动审查时 Claude 使用 Auto。从下一条消息起，DSH 权限覆盖“打开会话”中选择的模式。更新后请重启 DSH。

**从 0.2.21 升级：** 包括主对话在内，每轮用量都通过 `remote-agents/usage` 事件发送给 `dsh-usage-stats`，并附带主机名和远端目录，可按主机和工作区拆分。主对话不再把整轮合计作为模型用量报告给 DSH，因为它包含多次模型调用，会让 DSH 误判对话的上下文大小。请将 `dsh-usage-stats` 同时更新到 0.1.5，否则主对话轮次会被重复计数。更新后请重启 DSH。

**从 0.2.20 升级：** 每轮结束时会记录本轮使用的 Token（Claude Code、Codex 及上报用量的 ACP CLI）。配合 `dsh-usage-stats` 0.1.3 或更新版本，可在**设置 → 使用量统计**的“远程智能体”来源中查看：主对话轮次经由 DSH 模型调用记录，DSH 分派的智能体和在“打开会话”中发送的轮次通过 `remote-agents/usage` 事件上报。更新前的轮次不会补录。更新后请重启 DSH。

**从 0.2.19 升级：** **添加工作区**新增“远程机器”页签，可将已保存机器上的目录添加为 DSH 工作区。Codex 也新增“沿用远端 CLI 设置”，审批策略和沙箱改由远端 `~/.codex/config.toml` 决定；新的主对话以及 DSH 未指定模式启动的智能体，Claude 和 Codex 均默认使用该模式。已有会话保留原模式。更新后重启 DSH，并点击各机器旁的 **刷新模型**。

**从 0.2.18 升级：** 远程 CLI 现在会在 DSH 退出或 SSH 断开后继续运行，DSH 会自动重连并补齐输出。这需要 SSH 主机上有 Node.js 18 或更新版本。更新后重启 DSH；之前创建的会话会在下次启动 CLI 时改用中继。

**从 0.2.17 升级：** 远程会话改为双栏阅读界面，增加进行中与历史分类、按时间分组、批量归档、Markdown 回复及工具操作折叠。权限模式和重命名移至标题栏的「会话选项」。历史记录与原生 CLI 会话继续保留；重启 DSH 并刷新客户端后生效。

**从 0.2.12 升级：** 新增主对话图片和文件传输。更新后重启 DSH 并刷新客户端；刷新机器模型可更新各 CLI 报告的图片能力。

**从 0.2.11 升级：** Claude 默认沿用远端权限设置；“打开会话”中可切换权限模式，并在 CLI 提供建议规则时选择会话或项目持续授权。已有会话保留原显式模式；运行中请先停止，再选择“沿用远端 CLI 设置”。

**从 0.2.10 升级：** 修复远端登录脚本关闭文件描述符时出现 `3: Bad file descriptor`、无法检测模型或启动 CLI 的问题。更新后重启 DSH，再刷新机器的模型。

**从 0.2.9 升级：** 修复 SSH 报错后机器因关联会话而无法移除的问题。现在可确认一并删除插件会话与输出，无需连接远程机器。

**从 0.2.8 升级：** 远程 CLI 会加载交互式登录 shell 环境，修复因缺少环境配置导致“终端正常、SSH 调用 Claude 报认证错误”的情况。更新并重启 DSH，刷新该机器的模型后重试对话。

**从 0.2.7 升级：** 移除侧栏的“远程会话”入口，仅保留设置中的“打开会话”。更新插件并刷新客户端后生效。

**从 0.2.6 升级：** 主对话的远程模型按工作区所属机器过滤，发送时也会验证；已有会话只有在机器和目录匹配时才能续聊。更新服务端插件并刷新客户端，无需迁移机器或模型缓存。

**从 0.2.5 升级：** 修复上一版重复声明已有子插槽，导致实际 DSH 客户端无法启用分组折叠的问题。现在保留原生模型菜单。重启 DSH 并刷新客户端后生效，已保存的折叠偏好继续保留。

**从 0.2.4 升级：** 输入框模型菜单中的提供方标题支持展开和收起。升级后刷新客户端即可，无需迁移机器或会话。

**从 0.2.3 升级：** 新增每台机器的 CLI 启用选择，并修复多版本 nvm 环境误选旧 Node 的问题。已有机器可直接调整勾选项后点击 **应用选择**。

**从 0.2.2 升级：** 在机器旁点击 **刷新模型**，即可获得不依赖项目的模型入口。原有项目绑定的会话仍按其保存的目录续聊，旧路由不再显示在新模型菜单中。

**从 0.2.1 升级：** 远程模型直接按 CLI 提供方分组，输入框保持原生。侧栏新增统一的“远程会话”入口。已保存的机器、项目、会话和输出均保留；旧的汇总模型路由仍可供已有对话使用，但不会在模型选择器中展示。

**从 0.2.0 升级：** 现在可以通过各 CLI 提供方直接使用主对话。添加机器或刷新其模型即可，现有独立智能体及输出会保留。

**从 0.1.x 升级：** 内置 Claude SSH 引擎仍已移除；本插件通过统一的原生 CLI 后端接入 Claude Code。独立 `dsh-claude-ssh` 插件及其数据不受影响。旧主聊天项目和绑定不会自动导入，请在设置入口刷新机器的模型。机器、独立智能体及其输出会保留。
