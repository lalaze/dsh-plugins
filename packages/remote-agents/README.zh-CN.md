# DSH Remote Agents

[English](README.md) | **简体中文**

在 DSH 原生模型选择器和主对话中直接使用远程 Claude Code、Codex、DSH、Grok、CodeBuddy 和反重力。DSH 通过系统 OpenSSH 直连每个 CLI 的原生协议，**不需要 Paseo daemon、SDK 或任何远端服务**。

远程 Claude 主聊天提供默认关闭的原生 DSH goal 桥，需通过 `claudeGoalSessions` 按会话启用（启用后每轮重启 CLI，结束进程内后台任务）：[Claude goal 用法](docs/claude-goal.zh-CN.md)。这是不转发本地工具 schema 的明确例外，不会转发本地 system prompt。

## 在 DSH 主对话中使用

每种远程 CLI 都作为独立提供方出现在 DSH 原生模型选择器中：

1. 打开 **设置 → 远程智能体**，添加 SSH 机器，勾选要启用的 CLI。保存后只检测所选 CLI 的模型，**无需填写项目名称或项目路径**；也可以先保存机器，稍后再勾选。
2. 在 DSH 中选择远程工作区（见[远程工作区](#远程工作区)），回到普通对话的模型菜单，选择 **Claude**、**Codex** 等分组下带机器名的模型。菜单和 `/model` 只显示当前工作区对应机器的模型；本地工作区、未选择工作区或无法验证归属时隐藏远程模型。工作区已经确定了机器，所以输入框的模型按钮和菜单中的**模型**一行只显示模型名，如 **Opus 5.5**；模型列表在名称后用浅色文字显示机器名，按钮的悬停提示显示完整名称。
3. 直接使用原来的输入框发消息。会话在 **当前工作区对应的远端目录** 执行，自动转换 dsh-remote 镜像目录和 Claude SSH 占位目录。发送和续聊时再次检查机器及目录；切换工作区后，旧模型不能把消息发往其他机器。远端目录不存在时明确报错。

在机器卡片中勾选或取消勾选 CLI，再点 **应用选择**。未启用的 CLI 不会启动检测，也不会出现在模型菜单；取消勾选不会中断已有任务。新机器默认不启用任何 CLI，旧机器升级后保留原有选择范围。

**模型分组折叠**自 0.2.57 起拆分为独立插件 `dsh-model-groups`。安装它即可在模型菜单中折叠提供方分组；之前版本保存的折叠选择会保留。

模型目录按机器保存在 DSH 服务端，多个客户端共享。同一个机器模型入口可以用于该机器上的不同工作区，不按项目重复生成。模型列表读取缓存，并按工作区的 SSH 主机、用户和端口过滤；通过 DSH 进程服务路由的工作区会验证实际机器身份。CLI 或账号变化后点击机器旁的 **刷新模型**。已有机器升级后也通过这个按钮完成首次机器级检测。发现模型在远程账号主目录中进行，实际执行使用会话的工作区目录；项目配置造成的模型差异会在启动时校验。

- 每个 DSH 对话及其选择的机器、CLI 使用独立的原生 CLI 会话，工作目录在首次发送时绑定，后续消息继续该会话。同一 CLI 内切换模型时，支持恢复的 CLI 会保留原生会话和历史；不支持时明确提示新建对话。已有的多个模型独立会话保持可用。切换机器或 CLI 时，会把可用的对话文本作为上下文带过去，不会传入 DSH 本地的系统提示、注入的工作区指令或工具定义。CLI 支持恢复时，DSH 重启后也能继续。
- 回复和思考过程直接流入主对话。远程工具调用在回复结束时显示为原生 DSH 工具卡片，操作在远程机器执行；记录时不会让 DSH 再执行一次。在 Claude 对话里，Claude 在工具之间写的简短进度说明会显示在回复中；工具运行时，回复底部有一行显示它的名字，这一行不会被保存。子智能体和团队成员的回复就是它们的结果，所以进度说明仍然折叠。授权和问题通过 DSH 原生提示处理。
- DSH 的思考强度选择器使用 CLI 检测到的选项。Claude 和 Codex 跟随对话的 DSH 权限（输入框或 `/permission`）：**仅可查看**时 Claude 使用 `default`（执行工具前询问）、Codex 使用只读，**工作区内修改**时 Claude 使用“自动允许文件编辑”、Codex 使用 workspace-write，**完全权限**时两者都不再逐项审批，**自动审查**时 Claude 使用 **Auto**、Codex 使用 workspace-write。切换从下一条消息起生效，并覆盖“打开会话”中选择的模式。DSH 权限为自定义时保留会话当前模式；新对话则沿用远端 CLI 设置。点击 DSH **停止**或取消响应，会中断远程 CLI 的当前回合。退出 DSH 或重载插件不会中断，见[持久化与恢复](#持久化与恢复)。
- **Codex 快速模式：**会话当前的 Codex 模型提供更快的服务档位时，输入框工具栏的权限控制后面会出现闪电按钮。点亮后，该会话之后的消息使用 Fast；关闭则恢复远端 Codex 配置，包括其中设置的 `service_tier`。开关按会话保存，切换时沿用同一个 Codex 线程。快速模式会消耗更多远端账号额度。每个模型在选择器中只有一个条目；仍停留在旧 **Fast** 条目上的会话会自动换到该模型的条目，并点亮闪电。
- **用量圆环：**发送按钮前的圆环显示远程会话上下文窗口的占用。悬停或点击圆环，可查看 Claude、Codex 远端账号的套餐限额，例如会话和每周额度。这些数据由 SSH 主机上的 CLI 提供，凭据不会离开远端。打开面板时读取限额并缓存五分钟，回合结束后会重新读取；点击刷新按钮可立即检查。
- **提示缓存：**同一面板显示 Claude、Codex 最近一次报告的模型请求的输入和输出 tokens、缓存读取和写入量，以及输入 tokens 中由缓存提供的比例。该区域默认折叠，只显示命中比例，点击即可展开明细，展开状态在之后打开面板时保留。统计按模型请求计算，一个包含工具调用的回合可能更新多次。Codex 还可展开查看会话累计值。数据随会话保存，断开或重启后仍可查看。未报告的字段显示**未知**，明确返回零则显示 **0**。缓存 tokens 仍占用上下文窗口；这些是 CLI 报告的 token 数量，不代表费用估算。
- 响应丢失时，按消息身份重放已保存输出，不重复投递任务。未确认送达或断线前未完成的响应会明确报错；发送新消息可以继续已保存的会话。
- **Claude 自行进行的轮次。** Claude Code 跑的后台任务（例如放在后台运行的命令或子智能体）完成后，或到了它自己定的唤醒时间，它会在没有新消息的情况下接着做。这样的一轮一开始，对话就会实时显示它的输出，标题为 **Claude 自行继续了 1 轮**，并附上 Claude 收到的通知；进行期间会话显示为运行中，按停止会中断这一轮。期间发的消息会像在 Claude 终端里输入那样等这一轮结束再发；如果中途按了停止，这条消息就不发了。**打开会话**里同样显示这一轮和通知。
- **Claude 自动换模型的提示。** Claude 的安全机制拦截一次请求时，Claude Code 会换一个模型重试，这段会话后面的轮次也继续用它，模型选择器不会跟着变。回复和**打开会话**会在发生的位置写明换成了哪个模型。要换模型，选另一个模型，发下一条消息时生效；要回到原来的模型，先换到别的模型发一条消息，再选回来。
- 主对话支持**文字、上传的图片和文件**。Claude、Codex 使用原生图片协议；ACP CLI 只有在初始化明确报告支持图片时才开放图片入口。普通文件通过 SSH 流式传到已验证的远程工作区，以只读路径交给 CLI 的文件工具读取。仅传输对话中明确添加的附件。CLI 使用自己的凭据、工具、指令和上下文管理；DSH 摘要使用独立的一次性 CLI 会话。

原生模型名称扩展可与其他插件的名称渲染共存。对于 Codex 风格的自定义输入框选择器，匹配已保存远程模型目录的按钮名称也会省略主机名，保留完整悬停信息、思考强度和选择操作。模型目录和已保存选择的名称、ID 保持原值。

## 远程工作区

使用 DSH 的**添加工作区**即可在已保存机器的目录中工作。保存了机器后，它会打开一个对话框：**本机**与以前一样使用系统文件夹选择器，**远程机器**通过 SSH 浏览所选机器的目录，**基于项目**则从你的某个 Git 项目新建一个工作区（见[基于项目新建工作区](#基于项目新建工作区)）。选好文件夹后点击**使用此文件夹**即可添加，之后该工作区的对话可以使用这台机器的远程模型。既没有保存机器、也没有 Git 项目时，**添加工作区**会直接打开系统文件夹选择器。

- 对话框会记住上次使用的标签页，以及每台机器上次打开的文件夹。路径可以用 `~/` 开头。勾选**显示隐藏文件夹**后会列出隐藏文件夹。
- 文件保留在远程机器上。DSH 在 `$DSH_HOME/remote-workspaces/` 下用本地占位目录记录工作区，格式与 dsh-remote 插件相同。使用「远程工作区」面板访问实时文件，并在原生终端的 Shell 菜单选择 **Remote workspace** 打开交互式 SSH 终端。在远程对话中直接点「新建终端」就会打开它：插件在远程对话显示时把它设为 DSH 记住的 Shell，离开后换回你原来用的 Shell。在本地对话中选择它会打开本地 Shell，但标签标题仍显示 **Remote workspace**。默认本地文件视图和本地 Shell 仍指向占位目录。
- 如果同时安装了 dsh-remote，将优先使用它的**添加工作区**对话框。

### 基于项目新建工作区

**添加工作区 › 基于项目**会为项目再建一个工作区，放在独立的分支上，在那里的改动不会碰到项目本身的文件夹，和 Paseo 新建 worktree 工作区一样。先选项目（工作区里每个 Git 仓库列一项，本机或已保存的机器均可），然后选**新建分支**：从你选的分支开始（默认是仓库的默认分支），分支名自己填或自动生成，例如 `swift-otter`；或选**已有分支**：检出本地分支或只在远程的分支，后者会跟踪远程分支。点击**创建工作区**会创建 Git 工作树，以「项目 · 分支」为名添加到 DSH、排在项目后面、带上项目的 Workspace Tags 标签，然后打开它。起点是远程分支时会先拉取它（最多 15 秒，失败则用机器上已有的版本），新分支不会跟踪它的起点分支。如果工作区是仓库里的某个子文件夹，新工作区会打开工作树里的同一个子文件夹。

- **工作树的位置：**放在仓库之外，本机为 `~/.dsh/worktrees/<仓库>-<hash>/<分支>`，已保存的机器上为 `~/.dsh-remote-agents/worktrees/<仓库>-<hash>/<分支>`。只有这些文件夹下的工作树才能由本插件归档。远程工作树只需要机器上有 Git 和 POSIX shell，不需要 Node.js。
- **初始化与清理命令：**在仓库中提交 `.dsh/worktree.json`，用来准备新的工作树，例如安装依赖、复制 `.env` 这类不受版本管理的文件：`{ "setup": ["pnpm install", "cp \"$DSH_SOURCE_CHECKOUT_PATH/.env\" ."], "teardown": ["docker compose down"] }`。优先使用工作树里的这个文件，分支中没有时用项目里的。命令在工作树顶层依次运行，使用该机器的登录环境，并提供 `DSH_SOURCE_CHECKOUT_PATH`（仓库的主检出目录）、`DSH_WORKTREE_PATH` 和 `DSH_BRANCH_NAME`。创建前对话框会列出项目中的初始化命令，运行时实时显示输出，期间可以关闭窗口。分支里的命令和列出的不同时，工作区会先建好，但这些命令不会自动运行：先在日志中列出，由你选择**运行这些命令**、**跳过剩余的初始化命令**或**删除这个工作树**。归档前的确认页同样列出清理命令。某条命令失败或被停止时，工作区已经在 DSH 中：**重试**再次运行它，**跳过剩余的初始化命令**直接完成，**删除这个工作树**会删除工作树、它新建的分支以及对应的 DSH 工作区。不读取 `paseo.json`。
- **归档：**表单下方列出该项目的工作树，可以打开或归档。归档前会先列出会丢失的内容（已修改或未跟踪的文件、未推送到任何远程的提交），然后归档该工作区中的会话，停止在其中运行的远程 CLI 会话，运行清理命令，删除工作树，再把工作区从 DSH 中移除。分支默认保留；只有分支已合并到仓库的默认分支时，才提供**同时删除分支**。
- 尚未支持：检出 Pull Request、在工作区行菜单（Workspace Tags）中直接新建，以及让模型创建工作树工作区的工具。

### 集成的工作区工具

在远程工作区的对话中，右侧栏的「工作区文件」（及其快捷键，macOS 上为 ⌘P）打开远程文件，而不是本地的空锚点目录，在其中选择的文件会像 DSH 自带的文件浏览器一样，在列表旁新开一个标签页打开；「远程工作区」打开同步、隧道和远程 DSH；对话中的文件链接只打开该文件。本地对话中，「工作区文件」仍是 DSH 自带的功能，也不会列出「远程工作区」。包括文件在内的全部工具也在 **设置 → 远程智能体 → 远程工作区** 中。它们跟随当前对话的已验证机器和目录，共用智能体的 SSH 配置，无需另装 dsh-remote。

- **文件**：浏览、新建文件/目录、搜索文本、在 VS Code 的编辑器（Monaco，支持语法高亮、缩略图、查找与替换、命令面板和状态栏）中编辑 UTF-8 文件、预览图片、Markdown 和 SVG 文件可在源码与渲染视图间切换、重命名/删除文件，以及上传/下载二进制文件。CRLF 换行的文件保存后仍是 CRLF。新建的文件会直接打开；⌘/Ctrl+S 保存，关闭按钮关闭文件，清除按钮或 Esc 结束搜索。有未保存修改时不能打开其他文件，但可以继续浏览文件夹。保存检查 SHA-256 版本，拒绝覆盖并发修改；「重新读取文件」获取最新内容。编辑上限 256 KiB，单文件传输上限 50 MiB。文件操作限制在远程工作区内，拒绝越界符号链接；活动工作区验证后，对话文件链接会打开远程编辑器。
- **终端**：在远程对话中点「新建终端」即可打开远程工作区的交互式 SSH 终端，也可以在原生终端的 Shell 菜单选择 **Remote workspace**。面板里不再单独提供执行命令。终端使用远程账户的正常权限；绑定失效时明确报错。
- **终端不随 DSH 结束**：关掉 DSH、电脑休眠或断网时，远程终端里的 shell 或 CLI 会继续在远程机器上运行。断线会自动重连，侧栏的终端标签在重启后也会自己回来，看到的还是同一个进程，屏幕和滚动记录都在。关闭标签、`exit` 或归档 TUI 对话会结束它；一直没人回来的 7 天后结束，远程机器重启也会全部结束。这要求远程机器有 Python 3 和 Node.js 22，没有时终端里会提示，并改用普通连接，断线就结束。这些连接还关掉了 OpenSSH 的按键节奏保护（`ObscureKeystrokeTiming`），让打字在丢包的线路上不被拖住。
- **在终端里直接用 Claude 或 Codex**：在原生终端的 Shell 菜单选择 **Remote Claude** 或 **Remote Codex**，会在同一个远程工作区启动交互式 `claude` 或 `codex`，退出后留在远程 shell。这个会话归远程的 CLI 所有：不会显示在 DSH 对话里，用不到 DSH 共享的 MCP 服务和技能，之后在远程目录运行 `claude --resume` 或 `codex resume` 继续。留在远程对话之间切换时，「新建终端」会继续打开它；离开远程对话会还原你自己的 shell，再回来时恢复为 **Remote workspace**。
- **TUI 对话**：在远程工作区新建对话，选一个远程 Claude 或 Codex 模型，点输入框左下角的图标（Claude 是吉祥物，Codex 是它的云朵图标，选了其他模型时不显示），这个对话的「对话」标签页就变成交互式 CLI，用你选的模型和思考强度启动，输入框隐藏。终端收在中间列，半透明背景透出壁纸，中文按系统字体放大填满两格，字距不再发散；灰条、边框这些由 Claude Code 自己绘制的颜色，可以在远程机器上用 `/theme` 或 `~/.claude/themes/` 调整。终端默认用 WebGL 绘制，打字和输出比网页自带的渲染更跟手；右下角的按钮可以切换 WebGL 渲染和背景模糊，浏览器用不了 WebGL 时仍用网页自带的渲染。它在工作区列表里是一行，选中哪行就显示哪个 TUI，切走时 CLI 继续运行。最近用过的 6 个终端切走后不关闭，切回来立刻显示。标题优先用在 TUI 里 `/rename` 改的名字，其次是 Claude Code 自己起的标题（Codex 这里不会自己起），再其次是第一条消息，只在这一行显示在主区域时更新；在 DSH 里手动改名后不再覆盖。重启 DSH、刷新页面或 SSH 断开时，CLI 继续在远程运行，正在跑的那一轮不会中断；再选中这一行就接回同一个进程。远程机器重启后再选中，会接回同一个会话（`claude --resume` 或 `codex resume`）。归档这一行会结束它的 CLI，撤销归档后再选中会接回。在 Claude Code 里拖选文字，松开鼠标就已复制，不用再按 Cmd+C；Codex 里和普通终端一样，选中后按 Cmd+C。把文件拖到窗口里或粘贴进来（Cmd+V；图片也可以用 Ctrl+V），文件会上传到远程项目的 `.dsh-remote-agents/attachments/tui/`，路径填入输入框，图片显示为 `[Image #1]`。每个文件不超过 50 MB，不支持文件夹；Git 会忽略这个目录，传上去的文件不会自动清理。对话内容只在远程的 CLI 里，DSH 的对话记录和搜索都看不到；启动后模型由 TUI 自己管，权限也用远程 CLI 自己的设置。Codex 不用它自己的全屏模式，这样滚轮能翻看对话；也不显示启动时的更新提示，因为第一个回车就会直接安装，要更新请在远程单独运行 `codex update`。已有的对话不能转成 TUI。 CLI 的状态和其他对话一样显示在侧栏：干活时显示运行中，弹出权限确认或提问时显示等待你处理，干完且你没在看时显示已完成。状态来自 CLI 的终端标题和屏幕，不额外连接远程机器；只有终端开着才知道，DSH 重启后要等你重新打开这一行。
- **同步**：先预览「拉取远程 → 本地镜像」或「推送本地镜像 → 远程」，再应用预览。三方内容比较将两端均修改的文件保留为冲突。预览列出复制和删除；文件变化导致计划不同则须重新预览。跳过 Git、依赖/构建目录、插件元数据、符号链接和名称含换行符的文件，不自动后台同步。
- **隧道**：「添加并启动」保存本地/反向 SSH 转发并立即启动；可在列表中停止、启动或移除。本地转发监听本机回环，再加上启动它的浏览器访问 DSH 时所用的地址（如果是这台机器自己的地址；看不出来时用 Tailscale 地址），不再监听所有网卡，实际地址显示在列表中。「打开」使用同一个地址。从另一个地址打开时，先停止再启动隧道。反向转发仅监听远程回环。配置重启后保留，需手动重新启动。退出 DSH 会停止隧道，不影响持久智能体。
- **远程 DSH**：启动独立的远程 `dsh web`，或输入已有实例的远程回环登录地址，再通过 SSH 打开。「启动远程 DSH」会同时完成连接，一步出现「打开远程 DSH」链接。启动要求远程登录 PATH 中已有兼容 dsh，不自动安装。托管数据位于 `~/.dsh-remote-agents/web-ui/<port>/home`；「停止托管实例」仅停止本工作区记录的进程。关闭隧道不会停止远程实例，登录令牌不写入隧道配置。

普通 DSH 模型同时获得 **`remote_workspace`** 工具及读取远程 `AGENTS.md` 的提示，用于会话绑定的文件和命令操作。它的修改与 DSH 自带工具一样遵循对话的 DSH 权限：**完全权限**和**自动审查**时直接修改文件、执行命令，不再询问；**工作区内修改**时直接编辑工作区内的文件，执行命令前询问；**仅可查看**或自定义权限时每次修改前都会询问。远程 CLI 模型继续使用自身工具与审批模式。

### 支持的主机

dsh-remote 创建的工作区可继续使用。

目前支持 **Linux/macOS 远程机器、系统 OpenSSH 密钥/SSH agent 认证**。文件、搜索、同步和命令只需要 POSIX shell、常用命令行工具以及 `sha256sum`、`shasum` 或 `openssl`，没有 Node.js 的主机（例如使用独立 Codex 的 Docker 主机）同样可用。不随 DSH 结束的远程 CLI 和远程 DSH 仍需要登录 PATH 中有 Node.js 18+。认证和跳板机配置请写在 `~/.ssh/config` 中，并将加密私钥载入 SSH agent。未包含原生 Windows 远程工作区、密码/OTP 认证及远程 DSH 自动安装。

请保留 `$DSH_HOME/remote-workspaces/` 及其元数据。

## 统一远程会话

通过 **设置 → 远程智能体 → 打开会话** 进入，侧栏不显示远程会话入口。同一个列表展示主对话绑定的会话和后台分派任务，支持按标题、CLI、机器或路径搜索，并按 **进行中 / 历史记录 / 已归档** 分类。默认展示运行中、待审批和异常任务；空闲会话进入历史记录，仍可继续。双栏界面按时间分组展示会话，列表显示项目、机器和更新时间。右侧直接阅读对话，权限模式和重命名收在标题栏的「会话选项」中；「已归档的会话」入口位于列表底部。智能体回复支持 Markdown，连续工具操作默认折叠展示。

新建会话时或已有会话空闲时，可以选择**权限模式**，从下一条消息起生效。主对话的下一条消息会改用 DSH 权限对应的模式。Claude 默认**沿用远端 CLI 设置**，保留远端账号和项目的权限配置，不再强制指定 `default`。已有会话保留原来的显式模式，可切回“沿用远端 CLI 设置”。DSH 工作区授权与远端 CLI 权限独立；“自动允许文件编辑”仍会询问需要审批的命令，“完全访问”会自动允许执行命令和编辑文件。

**以 root 连接的机器：** Claude Code 默认不允许 root 跳过权限检查，会直接报错退出。插件在“完全访问”和“沿用远端 CLI 设置”启动 Claude 时，如果发现账户是 root，会设置 `IS_SANDBOX=1` 让它正常启动；选其他权限模式时不设置。这样 Claude 能以 root 身份不经询问执行任何命令，所以请只在你能接受这一点的机器上选“完全访问”。TUI 对话不设置这个变量：如果 root 账户的 Claude 设置把默认模式设成了 `bypassPermissions`，TUI 里的 Claude 仍会报这个错。

**Claude Auto：**选择 **Auto（自动安全审查）**，启动或恢复时会明确传入 `--permission-mode auto`，升级前保存的已有会话也可选择。该模式保留 Claude 自身的分类器审查。“沿用远端 CLI 设置”使用非交互 `claude -p` 的默认值，可能与交互终端不同：Claude Code 2.1.302 起，未指定权限模式的 `-p` 默认进入手动审批，即使终端默认是 Auto。插件不会自动改变已保存的模式。Auto 需要远端 CLI、模型和账号支持。参见 [Claude 权限模式说明](https://code.claude.com/docs/en/permission-modes#tool-calls-denied-in-claude--p-and-agent-sdk-runs)。

DSH 原生审批仍是“允许一次”。当 Claude 返回匹配规则建议时，本面板的待审批请求还会提供会话或项目授权选项。选择前可在**详情**中查看规则；项目授权只将这些原生规则写入远端 `.claude/settings.local.json`，以后匹配的请求可自动通过。插件不会生成全局放行规则，也不会将单次审批保存为持续授权。没有合适规则建议的请求仍只提供单次授权。

- **新建会话**：先选择远程 DSH 工作区，再选择该机器的 CLI 和模型、输入任务。会话使用经过验证的远程目录，自动转换本地工作区占位路径；创建时会重新核对工作区，避免目录或机器切换后沿用旧选择。
- **历史与续聊**：打开会话查看流式输出、思考过程和工具详情，按需加载更早的历史。后台会话可以直接续聊；主对话会话通过 **在主对话打开** 继续，避免产生两份不同步的对话。
- **审批**：侧栏显示待处理会话数量；会话内展示 CLI 提供的授权选项和提问。关闭 DSH 原生审批提示后，请求仍保持待处理，可在此处回答。只有明确点击 **停止** 才中断当前回合。面板中的授权范围按 CLI 原生选项执行。
- **管理**：可以重命名远程记录、归档和恢复。在历史记录中可通过 **归档当前列表** 批量归档搜索结果，归档前会再次检查状态，跳过刚开始运行或等待审批的会话。归档保留历史并结束远程 CLI 进程；这些操作针对远程记录，不改变 DSH 主对话自身的标题或归档状态。
- **发送**：运行中需等待或先停止再发送。响应丢失后通过 **检查送达情况** 检查同一条消息，不重复投递；该浏览器标签页保存待确认消息，刷新或重新打开会话后仍可检查。

关闭会话面板不会停止后台任务，退出 DSH 或 SSH 断开也不会，见[持久化与恢复](#持久化与恢复)。DSH 重新建立 SSH 连接期间，会话显示 **正在重连**。

## 多个 DSH 共享会话

连接同一个 SSH 账号的每个 DSH 都能看到这台机器上的同一批**远程 CLI 会话**：历史记录、进行中的任务、待答复的授权，以及在这台机器上添加过的远程工作区。此开关不共享普通模型对话。每个 DSH 需要各自添加这台机器，SSH 密钥和设置不会共享。每台机器默认开启 CLI 共享；在机器卡片中取消勾选 **与其他 DSH 共享会话和工作区**，这台机器的 CLI 会话就只留在当前 DSH。

- **保存位置。** SSH 主机在 `~/.dsh-remote-agents/shared-v1` 中保存共享登记：每个会话一份记录和历史，以及共享的远程工作区列表。文件只有该 SSH 账号能访问（`0700`/`0600`）；能以这个账号登录的人都能读取，和各 CLI 自己保存的历史一样。密钥、共享令牌、上传的图片数据、用量计数都不会写进去，首条提示只保存前 2000 个字符。和中继一样，需要主机上有 Node.js 18 或更新版本。
- **历史按需复制。** 其他 DSH 发起的会话会立即出现在列表中；它的历史在第一次打开时才复制到当前 DSH，之后跟随更新。主机离线时，只能查看已经打开过的会话。
- **每个 CLI 同一时间由一个 DSH 驱动。** 最后发消息、答复授权或停止回合的 DSH 驱动 CLI 并记录历史；其他 DSH 跟随显示，并标出是哪个 DSH 在用（**… 正在使用**）。在任意 DSH 发消息、答复或停止，都会接管这个会话，不重启 CLI：接管的 DSH 从共享历史接着处理，不重复也不丢失，原来的 DSH 改为跟随。回合在别处运行时，和只有一个 DSH 时一样，需要等它结束或先停止再发送。
- **DSH 离开时。** 驱动 CLI 的 DSH 退出或断网后，大约三到四分钟后另一个开着的 DSH 会接手，记录回合剩下的部分。原来的 DSH 回来后不会抢回，而是跟随。
- **主对话。** 其他 DSH 在共享机器上开的对话，也会在这里自动成为主对话：放在它所在的远程工作区，标题、CLI、模型和权限都沿用原来的。打开时先用一整块显示会话已保存的历史，不会给 CLI 发任何内容；在这里发消息会接着同一个 CLI 会话聊，已显示的历史不会再发回给它。另一个 DSH 中仍在运行的回合会接在历史下面继续显示。每个会话只建一次对话，删除后不会重建；已归档的会话和 DSH 智能体分派的后台任务不会建对话。两边的 **打开会话** 里也都仍然有这个会话。
- **在别处进行的轮次。** 之后另一个 DSH 在同一个 CLI 会话里进行的轮次（例如通过另一个 DSH 从手机发的消息），也会在这里的对话中补成一块，标题写明在哪里进行（**在 lalazedeMac-mini.local 上进行的 1 轮**），不会向 CLI 发送任何内容。那边还在运行的一轮会在这里实时显示，对话显示为运行中，在这里点停止会停掉这一轮。那边的 DSH 中途掉线时，等另一个 DSH 接管 CLI 后继续显示。DSH 启动后进行过回合的对话，在那边这一轮结束后马上补上；其他对话在下一条消息的回复前面补上。在 **打开会话** 里给这个会话发的消息也同样补上。0.2.75 起消息会记录是哪个 DSH 发的；更早的消息，或来自多处的几轮，显示为“在别处”。
- **重命名、归档和删除** 对所有 DSH 生效。删除会停止 CLI，并在所有 DSH 中移除这个会话；主机不可达时删除的会话，会在 DSH 下次连上主机时从主机移除。
- **移除共享的机器** 时可以选：**仅从当前 DSH 移除**，会话留在主机上供其他 DSH 使用，CLI 继续运行；或 **在所有 DSH 中删除会话**，同时停止这些 CLI。
- **远程工作区** 在共享机器上添加后，会在连接这台机器的其他 DSH 侧栏中出现一次。从侧栏移除的工作区不会再自动加回来。
- **工作区标签**（[Workspace Tags](../workspace-tags/README.zh-CN.md)）：共享机器上的远程工作区，在连接这台机器的每个 DSH 里标签都一样。在一个 DSH 里加上或去掉标签，几秒内其他 DSH 也会跟着变；对方还没有的标签会用同样的颜色新建。标签按名称对应，不区分大小写；改名后其他 DSH 会多出新名字的标签，旧标签保留。两个 DSH 第一次对同一个工作区比对时，两边的标签都会保留。本机工作区的标签不同步。
- **已读状态** 也会同步。在一个 DSH 里打开对话，几秒内连接这台机器的其他 DSH 上的 **已完成** 标记就会消失。DSH 窗口在前台且有焦点时才算看过，所以你离开时跑完的回合仍会标记。每个会话读到哪里保存在共享登记的 `read.json` 中。
- **关闭共享** 时，当前 DSH 先补齐自己发起的会话，再把它们从共享登记中撤回：其他 DSH 不再显示，当前 DSH 继续保留并可正常使用。其他 DSH 发起的会话副本会从当前 DSH 删除。关闭共享需要能连上这台机器（主机上从未成功共享过时除外）。重新开启后，撤回的会话会再次共享。

## 普通 DSH 对话

两端在 **设置 → 远程智能体 → 普通 DSH 对话** 中选择已验证的远程主机并启用普通共享。核对显示的标题和 ID，确认 **共享并关闭当前对话续写**，通过原生日志复制用户、assistant、工具结果及已有压缩历史，导入不调用模型或工具。点 **在此继续** 原子取得单写者并创建关联的原生续聊副本；此前持有端须先点 **交接并关闭此副本续写**。空闲完整轮次发布增量检查点，接收端每 30 秒轮询元数据并首次冷导入只读视图；已有视图通过 **打开原生历史** 按需刷新。

此功能默认关闭，独立使用 `shared-native-v1`，不改变 CLI `shared-v1`。支持明确映射的普通本地工作区和已验证远程工作区、原生文件与图片、接收端普通工具，以及新的压缩和标题。目标、排队输入、定时任务和可继续的子会话树以不执行的方式导入，须明确恢复。接收副本初始为只读沙箱并要求审批，保留原生权限检查。不复制代码或凭据；运行中进程和 job 须先完成或停止再交接。版本、市场发布及部署状态统一见[仓库发布记录](https://github.com/lalaze/dsh-plugins/blob/main/docs/releases/2026-11-09.md)。隔离运行时验收已通过，尚未进行双实体 Mac 的真实 GUI/账号验收。启用、所有权、恢复及验证边界见[普通对话共享](docs/native-sharing.zh-CN.md)。

## 由 DSH 分派任务

DSH 自己的智能体会获得 6 个工具，用来把任务交给远程 CLI，对应 Paseo 的 `create_agent` 和 `send_agent_prompt`：

| 工具 | 作用 |
| --- | --- |
| `remote_agent_list` | 列出机器、最近的项目及智能体状态 |
| `remote_agent_providers` | 查看远程项目中可用的 CLI、模型、模式、思考强度和速度 |
| `remote_agent_create` | 用自包含的任务启动智能体，默认等待它回复 |
| `remote_agent_send` | 给智能体（ID 或前缀）发后续消息；智能体运行中时默认拒绝，`interrupt: true` 才会中断 |
| `remote_agent_wait` | 等待一个或多个智能体完成并返回回复；超时不会停止它们 |
| `remote_agent_stop` | 中断智能体当前回合 |

可以直接对 DSH 说：“让 build-box 上的 Codex 修好 /srv/app 里失败的测试，同时让 Claude 审查 /srv/web”。通过 `remote_agent_list` 查看状态，通过 `remote_agent_send` 在对话中发送后续指令。

- 工具等待期间，远程智能体的授权请求和问题会以 **DSH 原生提示** 显示在对话中。DSH 的“允许一次”绝不会选成 CLI 的整个会话授权。如果你关闭提示，请求会保持待处理并由工具报告；再次调用 `remote_agent_wait` 可以重新显示提示。
- 以不先询问的模式（完全访问、跳过权限）启动智能体，需要你明确批准。
- 停止 DSH 的回复只会停止等待，**不会**停止远程智能体，与 Paseo 中智能体彼此独立一致。可以用 `remote_agent_stop` 停止它们。
- 会话启动的远程 CLI 会出现在该会话顶部原生的 **子智能体** 列表中，与原生子智能体合并显示。点击远程条目会打开只读、实时更新的远程对话窗口；继续、停止或处理授权仍使用上述工具或会话管理页面。只列出该会话直接启动的任务，查看时不会发送提示或启动 CLI。需要 DSH 的 Slot 注册器提供 `entries` 与 `subscribe`，否则列表保持原样。
- 这些工具在 DSH 提供智能体工具和授权服务时加载；没有分派工具注册器时，原生模型入口和设置照常可用。

## 共享 DSH 的 MCP 与 skill

**设置 → 远程智能体 → 共享给远程 CLI** 列出 DSH 里配置的 MCP 服务器和个人 skill。勾选的内容会提供给之后启动的远程 CLI，已经在运行的 CLI 保持原样。

- **MCP 服务器（默认关闭）。**工具在本机的 DSH 里执行，远程 CLI 只拿到一个代理。调用以启动该 CLI 的 DSH 对话的身份运行：主对话会话归属它自己的对话，分派任务归属分派它的对话。所以 DSH 的权限规则、审批和 hooks 照常生效，MCP 凭据不会离开本机。CLI 那边预先放行这些代理工具，只由 DSH 决定是否询问。远程 CLI 看到的服务器名为 `dsh-<名称>`，例如 `mcp__dsh-github__create_issue`。从会话面板直接新建、不属于任何 DSH 对话的会话不会收到 MCP 服务器。
- **Skill（默认开启）。**个人、DSH 自带和插件提供的 skill 会复制到每台机器的 `~/.dsh-remote-agents/shared`，包括 `scripts/` 等资源文件，未改动的不会重复传输。项目 skill 不复制：远程项目自己的 skill 由远程 CLI 直接发现。Claude Code 把它们作为 `dsh` 插件加载（如 `dsh:release-notes`）；Codex、DSH、Grok 和 CodeBuddy 通过名为 `dsh` 的 MCP 服务器提供的 `load_skill` 工具加载，这个服务器在远程运行，不依赖 DSH 连接。
- **连接方式。**每台机器使用一条 SSH 反向转发，远端是 `~/.dsh-remote-agents/bridge` 下仅本人可访问的 Unix socket；每个任务带独立令牌，多台电脑上的 DSH 可共用同一个远程账号。DSH 未连接时，代理仍列出上次看到的工具，调用会返回 DSH 未连接的说明；重新连上后自动恢复。服务器若禁止 Unix socket 转发（`AllowStreamLocalForwarding no`），设置页会显示错误，skill 不受影响。
- **各 CLI 的接入方式：**Claude Code 使用 `--plugin-dir`、`--mcp-config` 和 `--allowedTools`；Codex 使用 `-c mcp_servers.<名称>…` 覆盖配置，并设置 `default_tools_approval_mode = "approve"`；ACP CLI（DSH、Grok、CodeBuddy）使用 `session/new` 的 `mcpServers`。这些只是本次启动的参数，不修改远程 CLI 的配置文件。Antigravity 没有按启动传入 MCP 或 skill 的方式，因此不支持。

## 智能体团队

装了 NanmiCoder 的 [`dsh-agent-teams`](https://github.com/NanmiCoder/dsh-agent-teams)（0.1.28 起）后，团队成员可以用远程 CLI 当模型，队长仍是 DSH 模型（比如 DeepSeek）。在 `/agent-teams` 的目标里写明成员用哪个模型即可，例如“reviewer 用这台机器上的 Codex”；也可以在团队模板里给成员填 `provider: remote-cli-codex` 和模型菜单里那个模型的 ID。团队在远程工作区里工作时：

- **DSH 模型成员**（例如 DeepSeek）用 `remote_workspace` 读写远程文件。成员沿用队长的权限：队长是 **工作区内修改** 时，成员直接修改工作区里的文件；远程命令没有沙箱，需要审批，而成员会话没有人能批准，所以会被拒绝，成员会把它当作阻碍报告给队长。要让这类成员也能运行远程命令，请给队长 **完全权限**。
- **远程 CLI 成员**在工作区对应的远程目录里运行，每个成员是一个独立的 CLI 会话。队长分配的任务和协调消息会作为提示发给 CLI；CLI 通过名为 `dsh-agent-teams` 的 MCP 服务器拿到四个成员工具（`agent_teams_claim_task`、`agent_teams_update_task`、`agent_teams_send_message`、`agent_teams_status`），按任务领取、更新状态并汇报。这些工具在 DSH 里以该成员的身份执行，队长专用的工具不会交给 CLI。不需要在 **共享给远程 CLI** 里打开任何 MCP 服务器，但和共享 MCP 一样，需要远程机器上有 Node.js 并允许 SSH 反向转发；拿不到这些工具时，CLI 用最后一条回复说明结果，队长同样能收到。
- **没有人审批。**成员会话不询问任何人：Codex 在 DSH 权限对应的沙箱里工作，不再请求授权；Claude Code 在 **工作区内修改** 时自动允许编辑文件，命令在 Claude Code 自带的沙箱里自动运行，只能写工作区（主机不支持该沙箱时，命令会被拒绝）。仍需审批的请求直接被拒绝，CLI 继续工作，把做不到的事报告给队长，不会停下来等待。
- **要让 CLI 本身当成员，就把成员的模型设成这个 CLI。**确认团队计划前，检查每个成员的模型，例如 coder 应是 Codex 分组下这台机器的模型。如果成员仍是 DSH 模型，它可能用 `remote_agent_create` 把活转给远程 CLI：被转包的 CLI 拿不到团队工具，只是替成员干活；它按成员的权限运行、同样不询问任何人（没有指定模式时，用成员沙箱对应的模式，而不是远程 CLI 自己可能只读的设置）。超出成员权限的模式（例如成员只有工作区内修改时的完全访问）仍需审批，在成员会话里会被拒绝。
- 成员的 CLI 会话也会出现在 **打开会话** 中，可以查看它做了什么。

## 远程机器

机器离线或 SSH 报错后仍可点击 **移除**。若有关联会话，会先显示确认；选择 **移除机器并删除会话** 后会停止已连接的 CLI 进程，永久删除该机器的插件会话（包括已归档会话）、输出记录和模型缓存，无需重新连接 SSH。开启共享的机器可以选择只从当前 DSH 移除，让会话留在主机上，见[多个 DSH 共享会话](#多个-dsh-共享会话)。

在 **设置 → 远程智能体** 中添加。可以从运行 DSH 的机器的 `~/.ssh/config`（含 `Include` 文件）中选择 `Host` 别名，也可以手动输入 `build-box`、`user@build-box` 或 `ssh://user@build-box:2222`。保存的是原始别名，连接时由 OpenSSH 解析 `HostName`、`User`、`Port`、`IdentityFile` 和 `ProxyJump`。选择列表不会展开通配符、执行 `Match exec` 或建立连接。

运行 DSH 的机器需要能以密钥或 SSH agent 非交互登录，且主机密钥已验证（`BatchMode=yes`、`StrictHostKeyChecking=yes`），不保存密码。远程机器只需要 SSH 和已登录的 CLI，无需安装本插件。每台机器都会锁定 SSH 机器身份；身份变化时请重新添加。

发往同一台机器的命令共用一条 SSH 连接（OpenSSH `ControlMaster`），只有第一条需要 SSH 握手；最后一条命令结束一分钟后连接关闭。连接的 socket 放在插件状态目录旁的私有目录 `ssh/` 中。超过服务器的会话上限（`MaxSessions`，默认 10）时，或无法使用 socket 时（Windows、状态目录路径过长或含空格），命令照旧各自建立连接。每条连接每 15 秒确认一次机器仍有响应，45 秒无响应即断开，电脑睡眠或切换网络后断掉的连接会重新建立，而不是一直挂着。

检测模型、启动 CLI 和运行工作区命令前，会先加载远端用户的 Bash、Zsh 或 Fish 交互式登录环境，继承终端中配置的代理、认证和配置目录变量。启动配置输出与 CLI 协议输出隔离，启动脚本不会读取 CLI 的输入消息；其他登录 shell 保留原有 POSIX 启动方式。Node.js 优先使用已配置的 ≥22 版本；若当前版本过旧，会从已安装的 nvm 和 Homebrew 运行时中选择可用的新版本。没有符合要求的版本时会保留原环境并报告 CLI 自己的错误，不自动安装或升级 Node。浏览、读写和搜索工作区文件，以及只读取仓库的 Git 请求不加载登录环境：它们用不到其中的任何设置，而加载登录环境往往比请求本身还慢。

### 上传附件

直接在 DSH 原生输入框粘贴或上传图片、文件，也支持只发送附件。远程副本保存在工作区的 `.dsh-remote-agents/attachments/<任务>/<消息>/` 下，目录仅当前用户可访问，文件只读并经过 SHA-256 校验。副本会保留供续聊及恢复会话使用，不再需要时可手动清理远程附件目录；删除插件会话会清理本地暂存副本。

普通文件采用流式传输，不会一次性载入内存。图片使用 DSH 的规范化请求版本（最长边 1568 像素、目标 4 MiB），单张需符合 CLI 的 5 MB 限制，每次最多 20 张、总计 32 MiB。上传失败不会启动 CLI 对话；已经记录的消息重试时不会重复上传或发送。

### 回复中的图片

DSH 对话只能显示 DSH 所在机器上的文件，所以远程机器上的图片会复制到插件状态目录下的 `chat-images/` 中，同一张图只存一份。

- **CLI 看过或生成的图片。** Claude 或 Codex 用工具用到的图片会显示在回复里它用到的位置，同一次回复中每张图只显示一次：Claude 截的屏和用 Read 打开的图片、Codex 用 `view_image` 看的或生成的图片，以及 MCP 工具返回的图片。CLI 输出里带有图片本身的（Claude、MCP 工具和生成的图片），副本就取自输出，所以即使文件后来改了或不在工作区内，显示的也是 CLI 当时看到的那张；图片数据不写进共享历史。Codex 的 `view_image` 只给出文件路径，显示回复时会从远程机器取这个文件（SSH 账号能读取、不超过 20 MB 的图片文件）。跟随共享会话的其他 DSH 没有这些副本：有文件路径的图片它同样从远程机器取，只存在于 CLI 输出中的图片（例如 MCP 截图）只在驱动该回合的 DSH 上显示。暂不支持 ACP CLI。
- **CLI 链接的图片。** 回复中以 Markdown 图片引用远程工作区内文件的，例如 `![截图](shots/a.png)`，会下载后显示。工作区外的路径和超过 20 MB 的图片仍显示为替代文本。

## 持久化与恢复

状态保存在 `$DSH_HOME/storages/dsh-remote-agents/state.json`（默认 `~/.dsh`），输出保存在同目录的 `events/*.jsonl`。开启共享的机器还会在主机上保存每个会话的记录和历史，见[多个 DSH 共享会话](#多个-dsh-共享会话)。文件权限为 `0600`，可用 `stateDir` 修改目录。机器离线时仍可查看已保存的输出。

- 创建时先保存请求 ID，再进行远程操作；发送提示前先保存原生会话 ID。因此响应丢失后重试不会启动第二个智能体。被 DSH 重启打断的启动仍会保存，重试响应时可继续完成启动。
- 每条消息在发送前按 ID 记录，绝不会自动重发。只有 CLI 自己的确认才会标记为已送达，否则显示 **未确认送达**。
- **远程 CLI 不随 DSH 结束。** 在装有 Node.js 18 或更新版本的 SSH 主机上，每个 CLI 都在一个小型中继中运行，中继安装在该主机的 `~/.dsh-remote-agents`。中继持有 CLI 进程并把输出追加到私有日志，因此 DSH 退出、崩溃、重载插件或 SSH 断开后，CLI 仍会继续工作。没有 Node.js 18 或无法安装中继时，不会启动 CLI：回复或会话会说明原因和解决方法，修复后重试即会在中继中启动。
- **自动恢复。** DSH 启动时会重新接上所有中继，从上次保存的字节位置读取离开期间产生的输出，不丢失也不重复记录。运行中的回合、工具调用和未答复的授权都会恢复；已答复的授权不会再次询问。SSH 连接断开后会自动重试（间隔逐步增加到每 30 秒），会话显示 **正在重连**；只有 CLI 真正退出才会使回合失败。
- **输入不重复。** 提示、授权答复和中断都带有 ID，中继只投递一次，重连不会重复发送。主机不可达时给出的授权答复会先保存，重连后送达。
- **停止与终止。** **停止**只中断当前回合，保留 CLI 进程。归档、删除、更改模式或模型，以及为新会话释放空闲会话，会结束中继。主机不可达时，删除和归档仍会立即完成；DSH 下次连上该主机时再停止并删除中继。
- **中继限制。** 每个 SSH 账号最多 32 个中继，每个最多 512 MB 输出，单行输入最多 128 MB。没有 DSH 连接且 24 小时无活动的 CLI 会被停止，输出保留。已结束的中继在 DSH 读取后删除，最迟保留 14 天。
- **主对话。** 退出 DSH 或重新加载插件时，当前回复会正常结束，并注明远程 CLI 仍在运行，不再标记为失败；未完成的工具调用显示为仍在运行。DSH 再次打开该对话并重新连上 CLI 后会自动同步：出现一条 **Remote CLI output produced while DSH was disconnected** 提示，随后的回复显示断开期间的输出，并跟随远程回合直到结束。这个过程不会向远程 CLI 发送任何内容。只有对话仍在使用该远程模型时才会自动同步；否则，或者你先发了新消息，下一条消息会先显示错过的输出，再发送新请求。你手动停止的回复不需要同步；除非停止指令没能送达远程 CLI，此时 CLI 之后写出的内容会按同样的方式显示。对被截断的回复点击**重试**则会完整重放。以上方式都不会重新发送原始提示。因崩溃或强制退出而中断的回复仍由 DSH 显示为已中断，同样会自动同步。
- 无法恢复原生会话的 CLI（不支持 `loadSession` 或 `session/resume` 的 ACP）同样在中继中继续运行，但进程结束后显示 **已结束**，输出保留。
- 每台机器最多保持 8 个 CLI 进程。满了之后会释放最久未用、且能恢复的空闲智能体；运行中的智能体、待处理的授权和发送中的消息绝不会被释放。

早期基于 Paseo 的任务记录仍可查看，但不会转换。

## 开发

```sh
pnpm --filter dsh-remote-agents check     # 类型检查、协议与集成测试、构建
pnpm --filter dsh-remote-agents test:ui   # 会话、审批、设置、SSH 选择器与模型菜单浏览器回归
pnpm --filter dsh-remote-agents preview:ui
```
