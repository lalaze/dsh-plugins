# DSH Remote Agents changelog

**English** | [简体中文](CHANGELOG.zh-CN.md)

What changed in each version and what to do after upgrading, newest first.

**Upgrading from 0.2.111:** When a turn Claude started by itself begins to show, the sentence it is still writing no longer breaks in two. Nothing to do after upgrading.

**Upgrading from 0.2.110:** Nothing changes in DSH. The `remoteAgentsTasks` service, which only `dsh-mobile` used, is gone along with that plugin, which is no longer on the market. If you still have `dsh-mobile` installed, its **Background tasks** list stays empty, so remove it.

**Upgrading from 0.2.109:** A turn Claude starts by itself, as after a background task finished, now shows in the conversation as it runs rather than only once it ends, and Stop really stops it. A message you send meanwhile still waits for that turn; if you press Stop while it waits, it is not sent. A TUI conversation no longer reads as finished because Claude Code compacted by itself while idle: about 53 minutes after a turn it compacts on its own, with a title and footer that look just like a turn, so a run no longer starts while its spinner says `Compacting conversation…`. A TUI row therefore reads as running about a second later, and a `/compact` you type no longer shows as running and finished. Nothing to do after upgrading.

**Upgrading from 0.2.108:** Text you select in a Claude Code TUI now reaches your clipboard. Claude Code draws its own selection and copies it by asking the terminal to set the clipboard, which DSH's terminal ignored, so nothing was copied and Cmd+C did nothing. It is now copied when you release the mouse, with no Cmd+C needed, including Chinese text and several lines. Pressing on text after the mouse has rested for a while also no longer copies only the first few characters. The terminal can write the clipboard but never read it, and a TUI out of view or a window without focus leaves it alone. Remote Claude opened in a sidebar terminal does not have this yet.

**Upgrading from 0.2.107:** On hosts you connect to as root, Claude no longer fails to start with `--dangerously-skip-permissions cannot be used with root/sudo privileges`. In **Full access** or **Remote CLI settings** the plugin sets `IS_SANDBOX=1` on a root account so that Claude starts normally; other permission modes do not set it. Claude can then run any command as root without asking, so choose **Full access** only on machines where you accept that. TUI conversations do not set it: if the root account's Claude settings make `bypassPermissions` the default, Claude in a TUI still shows this error.

**Upgrading from 0.2.106:** The model name in the composer no longer shows the machine when another plugin that labels models, such as WorkBuddy, is installed. DSH's own model picker showed `Opus 5.5 · macmini` in that case; it now reads `Opus 5.5`, and hovering over it still shows the machine.

**Upgrading from 0.2.105:** You can now click an image to enlarge it while the turn is still running, not only after it ends. It opens the same preview as DSH's own: Escape, the close button or a click outside the image closes it, and Escape there does not stop the turn. Right-clicking or dragging an image out of the preview still waits until the turn ends on DSH 0.2.2.

**Upgrading from 0.2.104:** Images a remote CLI reads or writes during a turn now appear right away, instead of showing as a file name in italics until the whole turn ends. DSH loads a local image only once its message has finished, and a remote CLI's whole turn is one message, so this plugin now draws those images while the turn runs. They stay after you switch conversations or reload the page, and DSH takes over when the turn ends. Clicking to enlarge still works only after the turn ends.

**Upgrading from 0.2.103:** A new conversation that inherits a remote model its workspace cannot run now starts on one it can, instead of failing on the first message. In a local workspace that is the last local model you chose. On another machine it is the same CLI and model there. Only that conversation changes: your default stays what you last chose.

**Upgrading from 0.2.102:** The line naming the tool Claude is running now looks like DSH's own tool rows, with the same gray and sparkle icon, instead of a quote with a bar. It reads like `Tool call · Run the tests`, and names the tool only when there is nothing else to show. A long line is cut to one row. Update `dsh-mobile` to 0.3.7 at the same time: an older phone app shows this line as a link to a page that does not exist.

**Upgrading from 0.2.101:** `/team`, its settings section **Team presets** and a TUI conversation as team captain are gone, because arranging a team belongs to AgentTeams. Start teams with `/agent-teams`; remote CLIs still work as its members, and saved presets are dropped. A finished subagent no longer leaves its CLI running on the remote machine, which could use up the account's 32 slots until no CLI could start; a later message to that subagent resumes it. Local tunnels no longer listen on every network: they listen on this machine, plus the address your browser used to reach DSH, and a tunnel started from this computer does not open from a phone until you stop it and start it again from there. Setup commands a new worktree brings that the form did not show now wait for your choice instead of running. Only a failed connection now marks a host as failed.

**Upgrading from 0.2.100:** What you have read now carries across devices. Opening a conversation in one DSH clears its **Completed** mark within seconds in the other DSH instances sharing that machine, and on the phone with `dsh-mobile` 0.3.6. A DSH counts a conversation as read only while its window is in front and focused, so a turn that ends while you are away stays marked for your phone. Each DSH needs this version for its reads to count, and a conversation you opened before upgrading stays marked until you open it once more. No action is needed.

**Upgrading from 0.2.99:** A TUI conversation has a small new button in its bottom-right corner with two switches, for when the terminal feels slow. **WebGL rendering** draws the terminal with the GPU, which used about a quarter of the CPU during a full-screen redraw on an M4 Mac mini. **Background blur** turns off the blur behind the terminal, which used 8 to 9% of that GPU. Each applies at once to every TUI in this browser and is remembered. Nothing changes until you use them: WebGL starts off and blur on. With WebGL on, text is about 4% narrower, so a row fits a few more characters. If WebGL is not available or stops working, the terminal goes on with the standard rendering and the menu says so. No action needed.

**Upgrading from 0.2.98:** Team presets under **Settings → Remote agents** are easier to follow, and you can now pick each member's thinking level. The field was there but cut off, because the settings column is narrower than the form. Model and thinking level are now dropdowns, and the levels show even while the model is left on its default. The page lists the three steps from preset to running team, and the editor shows how the team will run: which task comes first, who does it on which model, and what waits for what. It warns about a member with no task, who would never start, and offers to add one, and about tasks waiting on each other. Renaming or removing a task now updates the tasks waiting on it; removing one used to leave a preset that could not be saved. Existing presets keep working. No action is needed.

**Upgrading from 0.2.97:** The line naming the tool Claude is running is shorter and easier to read. A Bash command now shows Claude's one-sentence description of it, such as `Running Bash · Push branch and run market release`, instead of the start of the command. A long script used to fill the line with its text, squashed and cut off, and often moved to a line of its own. When Claude gives no description, the line shows the command's first line, and a long file path keeps its end, which names the file. The whole command is in the tool card when the response ends, as before. No action is needed.

**Upgrading from 0.2.96:** Coming back to a TUI conversation no longer reloads it. The terminal used to be rebuilt each time, after a round trip to the remote machine, and showed a blank moment; the six you used most recently now stay open and keep following their CLI while out of view. Any others open again with that blank moment but without the round trip. The first return after DSH restarts or the connection drops still shows a short start. A file that finishes uploading after you leave its conversation now goes to that conversation's prompt right away instead of waiting for you to return.

**Upgrading from 0.2.95:** Remote terminals and TUI conversations now keep running on the remote machine when DSH closes, your computer sleeps or the connection drops. A reply carries on while DSH is away; when DSH reopens, or the connection returns, the terminal shows the same process with its screen and scrollback, and a lost connection reconnects by itself. A sidebar terminal's tab comes back by itself after a restart. Closing a tab, `exit`, or archiving a TUI conversation still ends what runs in it; one nobody returns to ends after 7 days. This needs Python 3 and Node.js 22 on the remote machine and installs nothing else; a machine without them gets a plain connection as before, and says so in the terminal. Terminals already open keep their old connection until they are next opened. Typing is also lighter: these connections turn off OpenSSH's keystroke-timing protection, which sent about 9 times the data per key (327 instead of 36 bytes) and stalled typing on links that drop packets. A network observer can then read typing rhythm from packet timing, as with OpenSSH before 9.5.
**Upgrading from 0.2.94:** Claude conversations show more while a turn runs. The short progress sentences Claude writes between tool calls used to be folded under **Analysis completed**. They now appear in the reply as they arrive, and stay in the finished reply, so long replies get a little longer. The reply also ends with a line naming the tool Claude is running, such as `Running Bash · npm run build`. The line goes away when the tool finishes and is never saved. Tool cards still appear when the response ends. Delegated subagents and team members keep their progress sentences folded, because their reply is their result. Codex and other CLIs do not change. If you use dsh-mobile, update it to 0.3.5 too: on 0.3.4 these lines pile up on the phone until the reply finishes.

**Upgrading from 0.2.93:** TUI conversations now show what their CLI is doing in the sidebar: running while it works, waiting when it asks for a permission or a question, and finished when it is done and you are not looking. No setup is needed. It comes from Claude Code's and Codex's terminal title, status reports and screen, with no extra connection to the remote machine, so it is known only while the terminal is open; after restarting DSH a row shows it again once you open it. To see finished tasks grouped at the top, also update dsh-workspace-tags to 0.2.2 and group by Status.

**Upgrading from 0.2.92:** A TUI conversation can now lead a team, on Claude Code and on Codex. With `dsh-agent-teams` installed, type `/team …` in the terminal, as in a chat, or tell the CLI to split the work, which it does with a new `start_team` tool. Members' reports reach the CLI by themselves as messages in the terminal, and the CLI can check the team, message members, change tasks and delete the team. A report waits while the prompt holds a draft or the CLI is asking you something, as Enter there would answer it, and the top right says so. A TUI already running gets the team tools in its next terminal; typing `/team` and receiving reports work before that. Attachments and everything else are unchanged. No action is needed.

**Upgrading from 0.2.91:** The button that starts a Codex TUI, and the notice shown while dragging files onto one, now use Codex's logo instead of a plain `>_`. No action is needed.

**Upgrading from 0.2.90:** TUI conversations now run Codex too. In a new conversation of a remote workspace, select a remote Codex model and click `>_` at the bottom left of the composer. Dropping and pasting files work as with Claude Code, and after a DSH restart the row resumes the same Codex thread with its model. Its title is a `/rename` in the TUI, then the first message, as Codex does not title these threads itself. Codex runs without its full-screen mode, so the wheel scrolls through the conversation, and without its update prompt at launch, where the first Enter would install; run `codex update` on the remote machine to update it. **Remote Codex** is also in the native terminal's shell menu. No action is needed.

**Upgrading from 0.2.89:** TUI conversations now take files. Drag files onto the window or paste them (Cmd+V, or Ctrl+V for an image): they are uploaded to `.dsh-remote-agents/attachments/tui/` in the remote project and their paths go into Claude Code's prompt, where an image shows as `[Image #1]`. Each file can be up to 50 MB, folders are not supported, and uploaded files are not cleaned up. A file dropped on a TUI conversation used to go into a hidden composer, and Claude Code never received it. Attachments uploaded to a remote project, a chat's included, are also kept out of Git now, by a `.gitignore` in `.dsh-remote-agents/`. No action is needed.

**Upgrading from 0.2.88:** Fixes a turn shown as it goes stopping early when the DSH running it goes away, such as a laptop going to sleep. The conversation used to end the turn after about a minute and never show the rest. It now waits until another DSH takes the CLI over and shows the turn to its end. If nobody takes over within two minutes of that DSH's status lapsing, the reply says so, and later output still appears. No action is needed.

**Upgrading from 0.2.87:** A turn another DSH is running in a conversation's CLI session now shows in that conversation as it goes, instead of all at once when it ends. The conversation reads as running, and Stop there stops the turn. This also works for a conversation unused for a while or with no agent since DSH restarted. Tool rows still appear when the turn ends. On a phone, install `dsh-mobile` 0.3.4 on the DSH it connects to. No action is needed otherwise.

**Upgrading from 0.2.86:** TUI conversations look calmer. The font is back to DSH's default of 13px, and a size you set in DSH's settings still applies. The column narrows to about 900px. The background goes from 0.62 to 0.92 opacity, leaving a faint trace of the wallpaper, so a busy image no longer turns it muddy. Chinese text no longer reads spaced out: with no font to install, the system's CJK font is scaled 12% to fill its two cells.

**Upgrading from 0.2.85:** Stopping a response no longer makes the next message start with `Output from the previous response, completed while DSH was disconnected:` and nothing after it. That line now appears only when DSH really was disconnected and there is output to show, and reopening a stopped conversation no longer shows a catch-up notice. Two related fixes: a turn stopped right after sending is no longer shown later as `1 turn sent elsewhere`, and a remote CLI error you already saw is no longer repeated under that line. What the CLI wrote between the last update and your Stop is no longer added to the next response; it stays in **Open sessions**. A conversation stopped before this update may show the notice once when reopened, or that line once if some text was still unread. Restart DSH after updating.

**Upgrading from 0.2.84:** TUI conversations look better, and their icon in the workspace list is fixed. The terminal sits in a column about as wide as the chat over a translucent background that shows your wallpaper. Its font is at least 14px, and a larger size set in DSH's settings is kept. Claude Code now uses true color, so the mascot and accents no longer turn pink. A TUI already open needs ending and reopening to get true color. Fixes a TUI conversation having no model icon when it only used the composer's remembered model: the model is now recorded when it starts, and existing TUI conversations get it when selected.

**Upgrading from 0.2.83:** Fixes TUI conversations staying titled `Claude Code`. Claude Code does not always write a title, and a short message such as `hello` usually gets none. A conversation without one now shows its first message, like other conversations; a title from Claude replaces it later, a `/rename` in the TUI wins, and a name you set in DSH is kept. Existing TUI conversations update when selected.

**Upgrading from 0.2.82:** When Claude's safeguards refuse a request, Claude Code retries it on another model and stays there for later turns, while the model picker keeps showing your selection. DSH used to say nothing about this. The reply and **Open sessions** now say where it happened, which model took over and how to change it; background tasks on the phone show it too, with `dsh-mobile` 0.3.3. Usage statistics also count each model separately: a turn that used several models used to count entirely as the last one, so what Fable 5.1 used before falling back showed as Opus 4.8. Usage by Claude's subagents now counts too, so totals and call counts can read slightly higher than before; existing records do not change. Claude Code versions that do not report per-model usage are counted as before. Restart DSH and refresh the client after updating.

**Upgrading from 0.2.81:** TUI conversations are easier to use. The start button is now the Claude mascot and shows only while a remote Claude model is selected; Claude Code starts with the model and effort you selected. Titles are no longer fixed at `Claude TUI HH:MM`: a conversation shows `Claude Code`, then follows the title Claude Code gives it (a `/rename` in the TUI wins). Existing TUI conversations update when selected, and a name you set in DSH is kept.

**Upgrading from 0.2.80:** New TUI conversations. In a new conversation of a remote workspace, click **Start in TUI** at the bottom left of the composer: the Chat tab becomes the interactive Claude Code, the conversation gets a row in the workspace list, and selecting a row shows its TUI. Claude keeps running while you are elsewhere. After a DSH restart, selecting it again resumes the same Claude session, but a turn that was running stops. Archiving the row ends its Claude. The conversation lives only in the remote Claude Code, so DSH's history and phone app do not see it. Also fixes the Remote workspace and Remote Claude terminals falling back to a local shell when `DSH_HOME` is not the default directory.

**Upgrading from 0.2.79:** The native terminal's shell menu has a new **Remote Claude** item. It starts the interactive `claude` directly in the current remote workspace, with the full Claude Code terminal interface, and leaves you in the remote shell when it exits. The session does not appear in a DSH conversation and does not get DSH's shared MCP servers and skills. Run `claude --resume` in the remote directory to continue it.

**Upgrading from 0.2.78:** The Remote agents settings page is easier to operate, with no change in function. The machine list is collapsed by default: each machine is one row showing its name, connection, status, whether it is shared and its model count, with a one-line summary of which CLIs are enabled; its sharing switch and per-CLI checkboxes appear when you expand it. Each machine's Test connection, Refresh models and Remove move into a ⋯ menu on the right. Once a machine exists the Add-machine form tucks away behind a button and opens on demand; an empty list still shows it. Team-preset members and tasks are collapsible cards: editing a saved preset starts with them collapsed to a summary, while a new preset or a newly added member or task opens expanded. Restart DSH and reload the client after updating.

**Upgrading from 0.2.77:** New `/team` command: one line in a remote workspace conversation, such as `/team pair coder=codex reviewer=claude/opus fix the login timeout`, starts a team with NanmiCoder's dsh-agent-teams whose members are remote CLIs, and runs it at once. Before, the captain first planned for a turn, every member's model was picked in the plan page, and approving woke the captain for another turn; now the plugin creates the team for the conversation itself, the members get their tasks as soon as you press Enter, and the captain joins when they report. Members are written `name=cli[/model][@thinking]`, the model found on the workspace's machine by id or name; `coder=captain` keeps the captain's model. Two presets are built in, `solo` and `pair`; **Settings → Remote agents → Team presets** saves your own rosters and task templates. `--plan` still stages the plan for review in the team panel. See [Start a team with one line](README.md#start-a-team-with-one-line). Restart DSH and reload the client after updating.

**Upgrading from 0.2.76:** A remote Claude Code conversation now shows the turns Claude runs by itself: the one it starts when a background task it ran finishes, such as a command or subagent left running in the background, or at a wake-up it scheduled. Before, Claude did go on, but DSH took the session for idle: the output was saved and never shown, the session read as **Ready** while Claude worked, and a message sent meanwhile could end with another turn's output. Such a turn now appears once it ends, in one block headed **Claude continued on its own: 1 turn** with the notice Claude got; the session shows as running meanwhile, and a message sent during it waits for it to end, as in Claude's terminal, then follows it. **Open sessions** shows the turn with the same notice. See [Main conversation](README.md#main-conversation). Restart DSH after updating.

**Upgrading from 0.2.75:** Remote CLI work is faster and uses less memory, with no change to what it does. The machine-identity and home-directory checks that run before every operation no longer load the remote login shell, so the first action after a short idle is quick again. Starting a conversation probes only the CLI you chose, instead of launching every enabled CLI to list its models. A command's login-shell environment is cached on the host for about a minute, so a burst of commands pays that startup once; a value you change in your shell profile takes up to that long to apply. A remote CLI running under a relay now streams its output as the relay signals new bytes rather than polling for them. Session histories opened on screen are freed from memory once nothing has read them for a while, and reloaded from disk on demand. The background relay script changed and reinstalls itself on the next connection; restart DSH after updating.

**Upgrading from 0.2.74:** A remote CLI conversation now shows the turns another DSH ran in the same CLI session, such as messages you sent from the phone through another DSH. Before, each DSH showed only its own turns, so a turn sent from the phone never appeared on the desktop, although the CLI had it. They appear in one block headed by where they ran, for example **1 turn on lalazedeMac-mini.local**, and nothing is sent to the CLI. A conversation that has run a turn since DSH started shows them as soon as the turn ends; any other conversation shows them ahead of the reply to its next message. Turns sent from **Open sessions** appear the same way. Update every DSH sharing the machine: messages name the DSH that sent them only from 0.2.75 on, and earlier ones read as sent elsewhere. See [Sessions shared between DSH instances](README.md#sessions-shared-between-dsh-instances). Restart DSH after updating.

**Upgrading from 0.2.73:** When an agent-team member that is still a DSH model, such as DeepSeek, hands work to a remote CLI with `remote_agent_create`, that CLI now runs with the member's permission and asks no one: without a mode it gets the mode of the member's sandbox. Before, it used the remote CLI's own settings, so a read-only Codex could not write files and its approval requests were all rejected in the member's session. A member with full access may start its matching mode without approval. Team tools go only to the member's own CLI, no longer to CLIs it delegates to, so they cannot claim or update tasks for it. To make Codex or Claude Code the member itself, set the member's model to it before confirming the team's plan. See [Agent teams](README.md#agent-teams). Restart DSH after updating.

**Upgrading from 0.2.72:** **Add workspace** has a new **From a project** tab that starts a workspace of its own from one of your Git projects, on this computer or a saved machine, as Paseo's new worktree workspaces do: pick a new branch from a starting branch, or an existing one, and the plugin creates a Git worktree outside the repository, adds it to DSH next to the project with its tags, and opens it. A committed `.dsh/worktree.json` lists setup commands to run in a new worktree and teardown commands to run before one is removed; their output shows live. The project's worktrees are listed there to open or archive; archiving warns about uncommitted and unpushed work, keeps the branch unless you choose to delete a merged one, and removes the workspace from DSH. Without saved machines, **Add workspace** now opens this dialog whenever you have a Git project, instead of the system folder picker directly. See [New workspaces from a project](README.md#new-workspaces-from-a-project). Restart DSH and refresh the client after updating.

**Upgrading from 0.2.71:** With NanmiCoder's `dsh-agent-teams` installed, agent teams can use remote CLIs such as Claude Code and Codex as their members' models: the captain's assignments reach the CLI, which claims tasks, updates them and reports to the captain through the `dsh-agent-teams` MCP server. Before, those messages were skipped as context DSH injects, so the CLI kept repeating its first task, and it asked for approvals nobody in a member's session could give, which ended its turn. A CLI in a member's session now asks no one: Codex works in the sandbox matching the DSH permission, and Claude Code with **Workspace write** runs commands in its own sandbox; a request that still needs approval is denied, and the CLI goes on and reports it. DSH model members such as DeepSeek edit files in a remote workspace directly under the captain's **Workspace write**; before, every change asked for approval and was rejected in a member's session. Denying one Codex request in a conversation now picks Codex's decline instead of cancel, so the turn goes on. See [Agent teams](README.md#agent-teams). Restart DSH after updating.

**Upgrading from 0.2.70:** Images a remote Claude or Codex looks at or makes with its tools now appear in the reply where it used them, each once per reply: screenshots and pictures Claude opens with Read, images Codex looks at with `view_image`, images Codex generates, and screenshots an MCP tool returns. Before, they went only to the model and the conversation showed none of them. Where the CLI's output holds the image, as for Claude, MCP tools and generated images, it is the one the CLI saw even if the file was replaced later or lies outside the remote workspace. Codex's `view_image` names only a file, so the chat fetches it from the remote machine when it shows the reply. Copies are kept in `chat-images/` beside the plugin's state on the DSH computer; image bytes are not written to the shared history. Another DSH following a shared session fetches the images that name a file on the remote machine; images known only from the CLI's output, such as MCP screenshots, show only on the DSH that drove the turn. Images from before updating are not added. ACP CLIs are not covered yet. See [Images in replies](README.md#images-in-replies). Restart DSH after updating.

**Upgrading from 0.2.69:** Remote workspaces respond much faster. Commands to a machine share one SSH connection instead of opening one each, and browsing, reading, writing and searching files, and Git requests that only read the repository, no longer load the remote login shell first: listing a folder took about 0.7 s and now takes a few tens of milliseconds, and the Git panel's status refreshes likewise. Commands, CLIs and Git requests that may reach a remote or run hooks still load it. SSH connections now notice within 45 seconds that a machine stopped answering, as after the computer slept or changed networks, and reconnect; before, a remote CLI or shared sessions could hang until the operating system gave up on the connection. Directory listings and error messages with non-ASCII names, such as Chinese folder names, are no longer garbled when a character arrives split between two reads. Tags another DSH sets on a shared workspace arrive within a second instead of up to five. The usage card no longer switches a Max account to Pro, with older numbers, when the Claude CLI answers from its cache: it keeps the plan it showed last until a full answer decides again. See [Hosts](README.md#hosts). Restart DSH after updating.

**Upgrading from 0.2.68:** Editing or resending a message in a remote CLI conversation no longer sends the CLI the conversation's whole history again, with its files uploaded again. What is sent as context now starts after the CLI's latest reply, which it already has. Restart DSH after updating.

**Upgrading from 0.2.67:** Workspace tags of remote workspaces on a shared machine are kept the same in every DSH connected to it; see [Sessions shared between DSH instances](README.md#sessions-shared-between-dsh-instances). Update every DSH sharing the machine: one that runs 0.2.67 or earlier neither sends nor receives tags. The first time a workspace is compared, the tags both sides have are combined. Requires Workspace Tags 0.2.0. Restart DSH after updating.

**Upgrading from 0.2.66:** Conversations started in another DSH on a shared machine become main conversations here, so they can be continued from either DSH. Each is added to the remote workspace it runs in, with its title, CLI, model and permission, and opens with the session's saved history in one block; the latest turns are shown when the history is long, and the full record stays under **Open sessions**. Nothing is sent to the CLI until you write. A message continues the same CLI session and takes it over, as sending from **Open sessions** does; the history shown is not sent back to the CLI as context. A turn still running in the other DSH streams on below the history. Archived sessions and tasks delegated by DSH's agent are left out, and a conversation you delete is not added again. A message in a remote CLI conversation no longer sends the CLI its own previous reply as context: the reply is already in its session, so every message paid for it twice. Messages and replies of other models since the CLI's last message are still sent. The new `remoteAgentsTasks` service lists the sessions that have no DSH conversation, such as delegated tasks, and reads, steers, stops and answers them; `dsh-mobile` 0.2.0 shows them on the phone under **Background tasks**. Restart DSH after updating; the conversations appear within a minute once the machine is connected.

**Upgrading from 0.2.63:** The `remoteAgentsWorkspaces` service also lists a remote workspace folder and deletes a file read at a given revision, for the Git panel of `dsh-git-view` 0.2.0: its file browser, its file sizes and times, and discarding untracked files in remote workspaces. Nothing else changes. Restart DSH after updating.

**Upgrading from 0.2.62:** Files dragged, picked or pasted into a remote CLI conversation reach the remote CLI. DSH Desktop sends a non-image file as an `@path` reference to the file on your computer rather than uploading it, so the remote CLI was given a path that does not exist on its machine. Each referenced file that exists on the DSH machine is now uploaded to the remote workspace with the message, and the message points at the uploaded copy; references to paths in the remote workspace are left alone. Folders are still sent as paths. Clicking such a file reference opens DSH's own preview of the file on your computer instead of failing with “Path is outside the remote workspace”. Restart DSH and refresh the client after updating.

**0.2.62 — Git workspace integration:** Adds the versioned `remoteAgentsWorkspaces` service used by `dsh-git-view`: bounded Git batches, cancellation and revision-checked file transfers on the verified SSH target. Requests reject a switched target; cancellation remains bound to the original active session/job, even if its conversation changes workspace. Remote file rows expose stable markers for Git status decorations. Install this release together with Git view for remote repositories; restart DSH and refresh the client.
