# DSH 模型分工

[English](README.md)

DeepSeek Harness 的模型分工：一条命令，一个模型做计划，一个模型实现，一个模型审核，审核不通过就打回继续改。

打回由插件代码控制，模型跳不过审核，也不能给自己放行。

## 使用

先在 **设置 → 模型分工** 选好三个模型和思考强度（计划可以跳过），然后在任意对话里输入：

```text
/flow 给导出加 CSV
```

也可以临时换模型：

```text
/flow plan=off impl=codex/gpt-6.1-sol review=claude/opus@high rounds=2 给导出加 CSV
```

| 写法 | 含义 |
|---|---|
| `plan=` `impl=` `review=` | 这一次用的模型：`codex`、`claude/haiku`、`qwen`，后面可以加 `@思考强度` |
| `plan=off` | 跳过计划 |
| `rounds=n` | 最多审核几轮，默认 3 轮，最多 10 轮 |
| `wt=on` `wt=off` | 这一次在独立的 worktree 里运行，或者在当前对话里运行，不管设置里选的是什么 |
| `repo=` `branch=` | 用于 worktree：哪个仓库，从哪个分支开出（名字带空格时加引号） |
| `/flow stop` | 结束这个对话里正在运行的流程，和卡片上的“停止”按钮一样 |
| `/flow` | 查看当前的模型设置 |

一个流程在对话里是一张卡片。运行时卡片顶部写着正在做什么、已用多久，以及“停止”按钮；进度条排满流程还可能走的每一步（计划，加上每一轮的实现和审核）；时间线列出每一步的模型和用时、正在跑的那一步最新在做什么，以及审核打回时意见的第一句。结束后卡片显示结果（第几轮通过、打回了几次，或者为什么停下），步骤收起，报告是卡片的一部分：改了什么、审核发现了什么。在卡片上可以重新展开步骤，点某一步看它的完整结果，点“打开”在旁边看这一步的完整对话。通过是绿色，打回是橙色，失败是红色。

`/flow` 可以带图片和文件，也可以只发附件、不写目标。每一步都会收到附件，包括后续轮次和审核缺结论时的重问。如果选中的任一模型声明不支持图片，带图片的流程就不会启动。

## 在独立的 worktree 里运行

默认情况下，流程直接改对话所在工作区的文件，审核通过就结束。加上 `wt=on`，或者在设置里把 **输入 /flow 时在哪里运行** 选成 **独立的 worktree**，它就变成[自动修复](../autofix/README.zh-CN.md)的一个任务：

```text
/flow wt=on 给导出加 CSV
```

- 任务在这条对话所在的仓库里新建自己的 worktree、分支（`feat/<编号>`）和对话。这个仓库要先加到 **设置 → 自动修复 → 仓库** 里。
- 它跑的还是计划、实现、审核，模型和轮数用命令里写的或设置里选的。审核通过后跑仓库的检查并在本地提交；你验收之前不会合并或推送，验收后卡片会问要不要删除 worktree。
- 这条命令留下的卡片跟随任务的进度；任务对话里的流程卡片就是任务的卡片：和普通流程是同一张卡片，进度条末尾多出 **检查** 和 **验收**，报告下面是“通过验收”和“打回”。
- 只能附带图片。在任务自己的对话里输入 `/flow <还有什么问题>` 是打回，和在那里输入 `/fix` 一样。
- 需要 dsh-autofix 0.1.4 或更新版本；没有时命令会说明，加 `wt=off` 可以在当前对话里运行。

## 常用组合

**设置 → 模型分工** 里可以存几组常用的模型、思考强度和轮数，点一下就切换。**保存当前组合** 会把现在选好的存下来，用已有的名字就是覆盖。卡片上的铅笔可以给组合改名，不能和别的组合重名。第一次打开时会根据你现有的模型放几个现成的组合，不需要可以删掉。

## 流程

1. **计划**（只读）：写出步骤和验收标准。
2. **实现**：在工作区里改代码。
3. **审核**（只读）：对照目标和验收标准检查，最后一行给出 `pass` 或 `needs_revision`。
4. 不通过时，问题交给新一轮实现，改完再审。用完轮数还没通过，就停下来交给你决定。

审核没给出结论时会重问一次，再没有就停止，不会当作通过。

## 需要知道的

- 每一轮的实现和审核都是新会话，靠提示词和工作区里的改动接上一轮，不会带上上一轮的对话上下文。
- 流程不在对话模型里运行。你发下一条消息时，对话模型会一并收到流程的结果，所以“发布吧”这样的话它听得懂。
- DSH 重启后流程不会继续，卡片会说明这一点，并保留已经完成的步骤。
- 只读靠 DSH 的沙箱强制执行。Codex 审核时可以跑测试；Claude Code 审核时只能看代码和 git 状态，测试命令会被拒绝。
- 用远程 Claude Code 或 Codex 做计划和审核时可以联网搜索，Claude Code 还能读取网页，所以模型可能把工作区里的内容放进搜索词或网址发到外部。
- 停止时，这一步的模型立刻中断，它在这一步启动的命令也会一起结束。例外是 Linux 上 Codex 0.164 的工作区沙箱：命令会继续跑到结束。
- 远程 CLI 只能在它所在机器的工作区里用。工作区在哪台已保存的机器上，就自动换成那台机器上的同一个模型，不管当初是在哪台机器上选的（需要 dsh-remote-agents 0.2.130 或更新版本）。那台机器上没有这个模型时，流程不会开始，并说明缺哪个模型、那台机器上有哪些。
- 使用远程 CLI 时，每一步都会向远程工作区上传一份附件副本，这些副本不会自动清理。
- 需要 DSH 0.2.1-rc.3 或更新版本（在 rc.5、0.2.2-rc.1 和 0.2.2-rc.2 上测过；DSH 0.2.2-rc.2 需要 0.1.12 或更新版本）。使用远程 CLI 时，请用 dsh-remote-agents 0.2.114 或更新版本：更旧的版本停止时不会结束 Codex 启动的命令，Claude Code 做计划和审核时也不能联网；0.2.113 之前的版本不会把流程结果交给远程 CLI 对话，也看不到委派的 Codex 正在运行什么工具，0.2.102 之前的版本还会让每个结束的子会话在远程机器上留下一个进程。

## 给其他插件用

服务 `modelFlow`（版本 2）在一个对话里运行流程，和输入 `/flow` 一样，并告诉调用方它如何结束：`start(agent, { goal, rounds?, models?, attachments?, tag? })` 返回 `{ done, stop, progress, stepBody }`，`done` 给出结局、报告和各步骤，`progress()` 是流程卡片此刻的样子，`stepBody(index)` 是某个已完成步骤的完整结果。`tag` 是发起流程的插件给它起的名字，形如 `<插件>:<它自己的内容>`，卡片会带着它。流程里有模型读不了附带的图片时会被拒绝，错误码是 `flow/images-unsupported`。

在页面里，客户端服务 `modelFlowSettings`（版本 1）提供 React 组件 `Models`，包含常用组合和各项工作的模型，供把自己的工作作为流程运行的其他插件放进它的设置页。它读写的就是本插件自己的那份选择，`/flow` 用的也是它。

客户端服务 `modelFlowCard`（版本 1）提供卡片本身：`View` 按 `{ card, active, report?, stop?, stepBody? }` 画出一个流程，周围可以加 `head`（顶部用它代替流程自己的文字）、`stages`（流程之后的步骤，排在进度条末尾）、`caption` 和子内容。`extend(prefix, { Card, claims, Row })` 让插件自己画带这个前缀标记的流程卡片，以及它的服务端回应被转交的 `/flow` 命令时留下的行。自动修复的任务就是这样画的。
