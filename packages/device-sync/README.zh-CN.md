# DSH Device Sync

[English](README.md) | **简体中文**

支持英文和简体中文，跟随 DSH 的语言设置实时切换。

`dsh-device-sync` 通过 Tailscale 配对两台 DeepSeek Harness 机器（例如笔记本和 Mac mini）。两台机器共享工作区分组和对话记录，并可以互相指挥会话。记录可以同步，任务不会重复执行：每个会话只在所属机器上执行，另一台机器保存只读副本。

## 同步内容

- **分组**：[Workspace Tags](../workspace-tags/README.zh-CN.md) 的标签（名称、颜色）以及两台机器上各工作区的分组归属。修改按字段合并，几秒内到达另一台机器。两台机器在同步前改了同一项时，两边都采用较晚的值，另一个值作为冲突保留在 **设置 → 设备同步** 中，直到你选择其一。两边各自新建的同名分组都会保留，较晚的一个改名为“名称 (2)”。
- **工作区**：每台机器的工作区，包括稳定标识、名称、路径和排序。路径只作展示，不会在另一台机器上使用；同名目录不会被当成同一个项目。
- **对话**：标题、所属工作区、归档状态、用户消息、助手回复、工具调用及结果、分叉关系、审批的请求和结果。系统提示、请求头和模型的逐字输出流不离开所属机器。图片按内容去重存储；小图片随会话下载，较大的附件首次打开时再下载。

副本保存在本插件的存储目录中，不进入 DSH 的会话库，因此同步来的内容不会启动任何智能体。所属机器上删除的会话，在本机仍可查看。

不同步：项目文件、Git 工作区、依赖、环境变量、密码、API Key、OAuth 令牌、浏览器 Cookie 和 SSH 私钥。被远程指挥的机器使用它自己的文件和模型登录状态。

## 远程指挥

获得授权后（见下文），主机接口可以接收针对另一台机器会话的以下请求，并在那台机器上执行：

- 发送消息、停止正在运行的任务；
- 回答它正在等待的工具审批或提问；
- 在它的某个工作区新建会话，并关联到所接续的会话。

每个请求带唯一标识，断线重试不会重复执行。另一台机器离线时，请求会暂存，需要你再次确认后才发送，绝不会改到本机执行。

在 **设置 → 设备同步 → 已同步会话** 中点击标题，即可查看镜像时间线、附件及实时草稿。会话按机器和工作区分组。每台机器的卡片默认收起并显示会话数；每个工作区先显示最近 5 个会话，其余的可点击 **展开** 查看。搜索可匹配标题、会话 ID、工作区名称和文件夹，并自动展开所有匹配项。已隐藏会话、子智能体会话默认不显示，可通过开关显示。隐藏和恢复仅影响本机。已归档或对方删除的会话仍可阅读。

查看器打开且对方在线、允许共享历史时，实时流中断会在 3 秒后重连，每个查看器仅维持一个实时流。关闭或切换查看器、对方离线、撤销历史授权或删除远端会话时，会取消实时请求与重试计时并清除草稿。403/404 等确定性 HTTP 拒绝会停止重试，需重新打开查看器或等待访问条件变化。历史轮询错误与实时流错误分别显示，历史读取成功不会掩盖实时连接失败。

**远端工作区** 按机器收在可折叠的卡片中。点击分组标签即可将工作区加入或移出该分组，变化显示在对方机器的侧栏中。不会在本机映射或打开对方路径。**暂存的请求** 可手动发送或丢弃请求，并显示失败原因；已送达与仍暂存会明确区分。

查看器支持发送文字（默认排队，也可选择引导）、停止在线任务，以及在对方授权远程指挥后回答在线审批与提问。不可远程回答的审批必须在所属机器处理。界面不允许操作已暂停、未配对、已归档或已删除的会话。离线消息仅暂存，绝不自动补发。浏览器响应不确定时，重试保留原请求 ID 并先检查暂存列表，避免响应丢失后创建新的执行请求。

查看器嵌入设置页，也可通过已有顶栏标记进入。此次不提供新建/接续会话按钮或图片上传；后端接口仍保留，已有镜像图片和文件附件可以查看。自动化测试不代表已经完成真实双机或登录态 DSH GUI 验收。

## 环境要求

- 两台机器都使用 DSH 0.2.1-rc.3 或更新的 0.2 版本。
- 两台机器都已连接 Tailscale。插件在本机 Tailscale 地址的 47630 端口监听，默认只接受 Tailscale 和本机回环地址。
- 分组同步需要 [Workspace Tags](../workspace-tags/README.zh-CN.md) 0.1.10 或更新版本。
- 两台机器的时间相差不超过 5 分钟。

## 配对

1. 在两台机器上安装插件并重启 DSH。
2. 在其中一台机器打开 **设置 → 设备同步**，“本机”一栏会显示它的地址，例如 `100.96.195.115:47630`。
3. 在另一台机器的“配对机器”中输入该地址，选择授权内容，点击 **配对**。
4. 两台机器会显示相同的 6 位配对码。核对一致后在两边分别确认；两边都确认后才完成配对。

每台机器各自决定允许对方做什么：

- **共享历史**：本机的工作区、分组和对话。默认开启。
- **允许远程指挥**：在本机会话中发消息、停止任务、回答确认。默认关闭。

配对后，对话顶栏会显示对方机器的名称和在线状态，同步失败时显示警示圆点；点击即可在弹窗中打开这些设置。

授权可随时在对应机器的卡片中修改。卡片还显示在线状态、最近同步时间、待同步的会话和请求数量、最近一次失败原因，以及 **立即同步**、**暂停同步** 和 **解除配对…**。解除配对后，对方不能再同步或发起操作；你也可以同时删除从对方同步来的历史。

与某台机器首次同步前，插件会把自身状态、Workspace Tags 的状态和现有副本备份到存储目录的 `backups/` 下，保留最近 10 份。

## 安全

每台机器在首次启动时生成自己的 Ed25519 设备密钥，设备标识由公钥派生，私钥不会离开本机。机器之间的每个请求都签名并指明目标设备，每个响应也签名并与对应请求绑定，重复的请求会被拒绝。配对码同时覆盖双方公钥和双方交换的随机数，中间人会导致两边显示不同的配对码。Tailscale 负责加密传输。配对不依赖浏览器登录链接，解除配对立即吊销对方的设备密钥。

## 配置

| 选项 | 默认值 | 含义 |
| --- | --- | --- |
| `port` | `47630` | 已配对机器连接的端口 |
| `listenHost` | Tailscale IPv4 | 改用此地址监听 |
| `advertise` | `地址:端口` | 已配对机器访问本机所用的地址，例如 MagicDNS 名称 |
| `anyNetwork` | `false` | 接受 Tailscale 以外的网络 |
| `stateDir` | `~/.dsh/storages/dsh-device-sync` | 存储目录（设置了 `DSH_HOME` 时位于其下） |

## 与 DSH 的对接

- 会话通过 DSH 会话控制器的 `list`、`inspect`、`follow` 读取，这些接口读取日志而不启动智能体；通过 `prompt`、`cancel` 指挥。提问通过 DSH 的 `userQuestions` 服务回答。
- DSH 没有供其他主机回答工具审批的接口。插件在执行会话的机器上加入 DSH 的 `approval/request` 处理链：有获准指挥的已配对机器在线时，审批会同时发给它和本机的浏览器，先回答的一方生效，另一方的提示随即撤回。出现任何错误时，DSH 原有流程不受影响。
- 分组通过 Workspace Tags 0.1.10 的 `workspaceTags` 服务读写。

DSH 若补充两处小接口，实现会更简单：导入只读会话，让副本直接显示在 DSH 自己的侧边栏和对话界面；以及供主机使用的审批接口。

在两台机器上构建并安装：

```sh
pnpm --filter dsh-device-sync check
pnpm --filter dsh-device-sync pack:plugin
dsh plugin --profile web add "$PWD/dist/dsh-device-sync-0.1.4.tgz"
```

## 0.1.4 更新说明
