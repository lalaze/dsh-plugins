# DSH 游戏素材

[English](README.md) | **简体中文**

给游戏项目用的**素材**标签页，位于对话旁边：把对话工作区里的所有图片列成缩略图，并回答一个素材文件夹自己回答不了的问题。

- **这张图还在用吗？** 插件读取项目代码，把每张图标为“在用”“可能在用”或“未引用”，并列出引用它的代码行。
- **哪个版本在生效？** 只差版本号的文件夹（`cast-v5`、`cast-v9`、`cast-v9-pilot`）并排对比：每个版本还有多少图片被代码引用。
- **这张图是从哪来的？** 详情里列出其他位置的同名文件（母版、发布副本、其他版本），并标出哪些内容完全相同。

看清之后还能动手：把图片**退役**到不碍事的地方并可恢复，给图片打**标签**、写备注，用你选的生图接口**重绘或生成**图片，以及把选中的图片**交给对话里的智能体**处理。

插件从不删除或覆盖文件。浏览是只读的；它能对工作区做的改动都列在[它会改什么](#它会改什么)里，而且只在你操作时才发生。

## 只在游戏项目里生效

标签页只出现在工作区是游戏项目的对话里，其他工作区不会被扫描。工作区声明了游戏引擎才算游戏项目：

- 工作区的 `package.json`（或其直接子文件夹里的 `package.json`）依赖了 Phaser、PixiJS、Kaboom/KAPLAY、Excalibur、melonJS、LittleJS、Kontra、PlayCanvas、Babylon.js 或 RPGJS；
- 有 Godot（`project.godot`）、Unity（`ProjectSettings/`）、Unreal（`*.uproject`）、Defold、GameMaker、RPG Maker 或 Cocos Creator 的工程文件；
- 清单文件里用了 LÖVE（`main.lua` 中出现 `love.`）、Bevy、macroquad、ggez、Ebitengine、pygame、Arcade、pyglet、libGDX 或 MonoGame。

在 **插件** 里本插件的页面上可以设置：标签页“仅游戏项目”显示（默认）或在“所有对话”显示，并为每个打开的工作区选择“自动”“始终显示”或“从不显示”。没用引擎写的游戏识别不出来，可以选“始终显示”。在标签页里，**扫描范围** 对话框有“在这个工作区隐藏标签页”。

DSH 的对话标签页是对所有对话统一注册的，所以插件的做法是：屏幕上有属于游戏项目的对话时才加上标签页，否则移除。两个对话并排显示时，非游戏项目那一侧也会有这个标签页，但它只会提示不是游戏项目，不会扫描。

## 界面

| | |
| --- | --- |
| **浏览** | 带数量的文件夹树和缩略图网格。可按文件名或路径搜索，按使用情况或重复筛选，按文件大小或图片尺寸排序。小尺寸像素图按整数倍放大，保持锐利。 |
| **详情** | 大图预览、像素尺寸、文件大小、所属版本、全部引用（文件、行号和附近代码，点击可在对话旁打开该文件），以及其他位置的同名文件。 |
| **版本** | 每组带版本号的文件夹，按版本列出图片数以及在用、可能在用、未引用的数量。没有任何引用的版本会标为“无引用”。 |
| **扫描范围** | 按顶层文件夹设置：是否列出其中的图片，是否把其中的代码算作引用来源。退役文件夹也在这里设置。 |

复制按钮会把当前显示的图片路径复制到剪贴板，每行一个。

## 管理

勾选图片角上的方框即可选中；按住 Shift 连选，Ctrl/⌘ 加点击切换单张，工具栏上的勾选按钮选中当前显示的全部。选中后出现操作栏：

- **退役…**：把选中的图片移进退役文件夹，各自保留现在的路径。移动前会弹窗说明其中有多少张仍被代码引用。“已退役”筛选列出退役的图片，**恢复**把它们放回原处。版本视图里每一行可以退役整个版本，详情面板可以退役或恢复单张。
- **标签…**：给所有选中的图片加一个标签，或移除一个。详情面板里可以编辑单张图片的标签和备注。工具栏的标签菜单用来筛选，搜索也会查标签和备注。
- **生成…**：用[生图来源](#生图来源)生成一张图，选中的图片作为参考图一起发送（最多 4 张）。只选一张时就是重绘这张图；详情面板里的 **重绘…** 也是同样的操作。
- **交给智能体…**：把一条请求（检查并移除、查找使用位置、重绘，或你自己写的话）连同选中图片的路径填进当前对话的输入框。你点发送之前不会发出。在 [Remote Terminals](../remote-terminals/README.zh-CN.md) 0.1.4 或更新版本的 TUI 对话里，输入框的位置是终端，请求会改为填到 CLI 的输入行。宿主接不住这段文字时，改为复制到剪贴板。

## 生图来源

图片来自你在 **生图来源** 里添加的来源，可以在插件设置页或生成对话框里添加。支持三类：

| 类型 | 调用 | 例子 |
| --- | --- | --- |
| Codex | 在工作区所在的机器上运行 `codex exec`，用它自带的生图工具 | 那台机器上用 `codex login` 登录过的 Codex 命令行；不需要地址和密钥，消耗那个 ChatGPT 账号的额度。模型可不填，只决定驱动 Codex 的模型 |
| OpenAI 兼容 | 没有参考图时 `POST /images/generations`，有参考图时 `POST /images/edits` | OpenAI（`https://api.openai.com/v1`，`gpt-image-2`），或提供相同接口的中转服务 |
| Gemini | `POST /models/<模型>:generateContent`，要求返回图片 | Google（`https://generativelanguage.googleapis.com/v1beta`，`gemini-3.1-flash-image`），或提供该接口的中转服务 |

每个接口类来源有名称、地址、模型和 API 密钥，其中一个来源是默认来源。Codex 在工作区所在的机器上运行：本地工作区在 DSH 所在电脑上（通过登录 shell 启动，所以从程序坞打开的 DSH 也能找到它），远程工作区在那台远程机器上；它在一个空的临时目录里以只读沙箱运行，参考图按路径附上。密钥只保存在运行 DSH 的电脑上，即 DSH 主目录下的 `storages/dsh-game-assets/image-sources.json`，只有文件所有者可读。页面只显示密钥最后四位，拿不到密钥本身。请求也从那台电脑发出，远程工作区同样如此。Node.js 的 `fetch` 只有在 DSH 以 `NODE_USE_ENV_PROXY=1` 运行时才会使用 `HTTPS_PROXY`；网络访问不到接口时，也可以改用中转服务的地址。

对话框会发送描述、形状（方形、横向或纵向，取接口最接近的尺寸），对 OpenAI 兼容来源还会发送是否要透明背景。重绘时形状跟随原图；原图有透明像素时默认勾选透明背景。只有 PNG、WebP 和 JPEG 能作为参考图，GIF 和 SVG 会被略过。保存之前不会写入任何文件：

- 新图显示在原图旁边，并已缩放到原图的像素尺寸：小图（128 像素以内）默认 **保留像素锐利**，其他默认 **平滑缩放**，也可以选 **保持接口返回的尺寸**。透明的图完整放进原尺寸；不透明的图（比如背景）会裁切铺满。
- **另存为新文件**：写到一个空闲路径，默认是原图旁边的 `<文件名>-redraw.<扩展名>`，或当前查看的文件夹里的 `generated.png`。
- **替换原图**：先把原图退役（移到退役文件夹，已有同名旧图时自动编号），再把新图写到原路径，代码照常能找到它，标签也保留。旧图会出现在这张图的[历史版本](#历史版本)里。

生成过程中关闭对话框会停止请求。单次生成超过五分钟会放弃。

### 历史版本

每次替换都会留下前一版：图片详情里列出它的 **历史版本**，新的在前，每一版都标明用到什么时候、是怎么生成的。点 **回退** 会把那一版放回原路径，同时把当前的图退役；所以回退本身也成为一个可以再回去的版本，任何文件都不会被删除。单独打开某个已退役的版本时，也有 **回退到这个版本**。

从生成对话框或项目脚本保存的每张图，都会在 `.game-assets.json` 里按路径记下生成方式：来源、模型、提示词、时间，以及是不是 agent 生成的。这条记录跟着文件走（退役或回退时一起移动），标签和备注留在原路径。每个版本都是退役文件夹里的一份完整文件，不再需要的旧版本可以在那里自己清理。

### 项目里的 agent

生成对话框里还会显示**在项目里工作的 agent** 用哪个来源，点 **让它们用…** 会把当前选中的来源记录到项目里。之后项目里会有：

- `.game-assets/image-source.json`：来源的名称、类型、模型和地址，不含密钥；
- `.game-assets/generate-image.cjs`：只需要 Node.js 18 的生图脚本，以及说明用法的 `.game-assets/README.md`；
- `AGENTS.md` 和 `CLAUDE.md` 里一段夹在 `<!-- dsh-game-assets:image-source -->` 标记之间的说明（文件不存在就新建；一个链接到另一个时只写一次）。

不管 agent 由谁运行（DSH、远程 Claude Code 或 Codex、终端），都可以这样生图：

```sh
node .game-assets/generate-image.cjs --prompt "a blue slime, pixel art" --out assets/slime.png [--ref assets/hero.png] [--shape wide] [--transparent] [--replace]
```

脚本把一张图保存到项目里的空闲路径，从不覆盖文件；加 `--replace` 时会就地重绘 `--out` 指向的图，像 **替换原图** 一样先把旧图退役，所以它也会出现在那张图的历史版本里。图片尺寸是来源生成的尺寸，并以 JSON 输出路径和尺寸。接口类来源的密钥保存到项目所在机器的 `~/.dsh-game-assets/keys.json`，只有本人可读，远程工作区通过 Remote Agents 的上传通道送过去；也可以用 `DSH_IMAGE_API_KEY` 环境变量覆盖，比如在别的机器上。Codex 用运行脚本那台机器上的登录。**从项目中移除** 会删掉这些文件和说明段；之后在设置里修改来源，不会自动更新项目，需要重新写入。

### 它会改什么

| 工作区里的变化 | 什么时候 |
| --- | --- |
| 图片移到 `_retired/<原路径>`，或移回去 | 退役和恢复 |
| `_retired/retired.json` 记录每张退役图片的原位置 | 退役和恢复 |
| `.game-assets.json` 按图片路径保存标签、备注和每张图的生成方式 | 打标签、写备注、保存生成的图片 |
| 当前的图退役，选中的版本移回原路径 | 回退 |
| 生成的图片写到你选的空闲路径 | 另存为新文件 |
| 原图按上面的方式退役，新图写到原路径 | 替换原图 |
| 写入或删除 `.game-assets/`，以及 `AGENTS.md`、`CLAUDE.md` 里带标记的一段 | 记录项目的生图来源 |

两个文件都是普通 JSON，适合随项目一起提交，标签会跟着项目走，智能体也能读。退役文件夹可以按工作区改成别的（**扫描范围** → “退役的图片移到”），比如 `assets/art-retired`；它必须是工作区内的可见文件夹。移动之后空出来的文件夹会被删掉。

只有上次扫描列出的图片才能被移动、打标签或替换。移动从不覆盖文件：目标位置已有同名文件时，图片留在原处并给出提示。新图会先以隐藏文件名写在目标旁边，再链接到目标位置，所以要么完整出现、要么不出现，也不会覆盖已有文件；替换时如果原图已退役但新图没写成，原图会被移回去。退役的图片不参与代码匹配，所以不会算作在用；退役文件夹里原本就有、但清单里没有记录的图片会显示为已退役，但无法在这里恢复。

在工作区之外，插件只保存你的设置（标签页在哪里显示、每个工作区的扫描范围和退役文件夹）和生图来源，存放在 DSH 主目录下；项目记录了接口类来源时，它的密钥保存在那个项目所在机器的 `~/.dsh-game-assets/` 里。

## 如何判断是否在用

代码只当作文本读取，不会执行。引用分为：

| 引用 | 例子 | 结论 |
| --- | --- | --- |
| 路径 | `'art/cats/idle.png'`，或只有一张图叫这个名字的文件名 | 在用 |
| 拼接路径 | `` `cats/${breed}-walk.png` `` | 可能在用 |
| 文件夹 | `'art/props/'`，之后在它后面拼文件名 | 可能在用 |
| 仅名称 | 多张图共用的文件名，或不带扩展名的名字（如贴图 key） | 可能在用 |

没有任何引用的图片是“未引用”。路径按结尾匹配，且不区分图片扩展名，所以代码里的 `art/cats/idle.png` 会同时匹配 `public/art/cats/idle.gif` 和母版 `assets/masters/art/cats/idle.png`。

清单、图集和地图文件（`.json`、`.yaml`、`.xml`、`.atlas`、`.tmx` 等）只有在被代码或另一个已计入的文件提到时才算数。否则生成器留在图片旁边的元数据会把它列出的每张图都标成在用。

**哪些代码算数由你决定。** 默认情况下，除了构建产物（`dist`、`build`、`docs`、`artifacts` 等）和素材文件夹（几乎全是图片、只含极少代码的文件夹），所有顶层文件夹都当作代码读取。在**扫描范围**里，对构建脚本或工具目录关掉“代码”，就只看游戏本身加载了什么；默认被排除的文件夹也可以在这里打开。

### 局限

- 结论来自静态分析。“未引用”表示被读取的代码里没有提到这个文件；“可能在用”表示删除前要先确认。
- 不支持按 ID 而不是按路径引用素材的引擎（Unity 的 GUID、Cocos Creator 的 UUID）。按路径引用的项目可用：Phaser、PixiJS、Godot（`res://` 路径）、LÖVE、普通网页游戏。
- 只处理图片：PNG、GIF、WebP、JPEG 和 SVG。隐藏文件夹、`node_modules` 和符号链接会被跳过。

## 远程工作区

工作区在 [Remote Agents](../remote-agents/README.zh-CN.md) 保存的机器上的对话，用法完全一样：标签页、在用判断、退役、标签、生成图片和交给智能体都可用。要求 DSH 主机上装有 Remote Agents 0.2.130 或更新版本，远程机器上有 Node.js 18 或更新版本（Remote Agents 本身也要求这一点）。

活是在那台机器上干的。插件通过 Remote Agents 已有的连接，把一个小脚本交给远程的 `node`，在对话所在的文件夹里运行并读回结果；不会在那边安装任何东西。每次扫描都是一个新进程，所以它量过的内容（未改动文件的图片尺寸和哈希）会保存在远程机器的 `~/.dsh-remote-agents/game-assets/` 下，让下一次扫描更快。同时请求的缩略图会合并成一次往返取回。第一次扫描和第一屏缩略图会比本机文件夹慢一些。

远程工作区的设置按“机器 + 文件夹”保存。退役的图片、标签文件和保存的图片都写在远程机器上的那份项目里。图片通过 Remote Agents 的文件上传送到工作区的 `.dsh-remote-agents/attachments/game-assets/`，校验 SHA-256 后移到目标位置；无论成功与否，上传的临时文件都会删掉。

## 安装

```sh
pnpm --filter dsh-game-assets pack:plugin
dsh plugin --profile web add "$PWD/dist/dsh-game-assets-0.4.0.tgz"
```

重启对应 profile 并刷新浏览器。桌面版请先完全退出 DSH，再用它自带的 `dsh` 加 `--profile desktop` 安装。要求 DSH `>=0.2.1-rc.2 <0.3.0`。

## 开发

```sh
pnpm --filter dsh-game-assets check        # 类型检查、测试、构建
pnpm --filter dsh-game-assets preview:ui   # 在 DSH 之外预览标签页，扫描当前文件夹
node scripts/preview.mjs /path/to/game 4184
```

宿主端（`src/`）负责扫描，并通过 `/api/game-assets` 提供图片；`src/workspace.ts` 是它在一个文件夹里做的全部事情，本机工作区在宿主进程里运行，远程工作区在发到那台机器的脚本 `src/remote-agent.ts` 里运行；客户端（`src/client/`）是标签页界面。引用规则都在 `src/references.ts`，要让它识别新的引用写法就改这里；所有会改动工作区的操作都在 `src/manage.ts`；`src/sources.ts` 保存生图来源并调用接口，`src/codex.ts` 运行 Codex，`src/project.ts` 把来源记录到项目，`src/generate-image.ts` 是项目拿到的脚本，`src/client/generate.tsx` 是生成对话框；哪些引擎算游戏项目列在 `src/detect.ts`。
