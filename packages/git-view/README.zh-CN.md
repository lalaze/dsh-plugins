# Git 视图

[English](README.md) | **简体中文**

在 DeepSeek Harness 右侧栏中查看分支、提交图、改动和 Monaco 差异，并操作本地或 Remote Agents 远程工作区的 Git 仓库。包名：`dsh-git-view`。

## 要求与安装

- DSH `>=0.2.1-rc.2 <0.3.0`，需提供右侧栏与对话 UI 服务；Node.js ≥ 22.15.0。
- 仓库所在机器需安装 Git。macOS 的 `/usr/bin/git` 需要 Xcode Command Line Tools（`xcode-select --install`）。
- **远程工作区需要 `dsh-remote-agents` 0.2.62 或更新版本**，并提供 Git 工作区 API 第 1 版。请将两个插件安装到同一个 DSH profile。更早版本或未标记 API 版本的实验实现会明确拒绝请求，不会悄悄忽略工作区绑定。本地工作区不需要 Remote Agents。

在仓库根目录构建并安装压缩包：

```sh
pnpm --filter dsh-git-view pack:plugin
dsh plugin --profile web add "$PWD/dist/dsh-git-view-0.1.1.tgz"
```

使用远程功能时，还需在同一份 checkout 中执行 `pnpm --filter dsh-remote-agents pack:plugin`，将新构建的压缩包安装到**同一个 DSH profile**。文件名中的版本以 [Remote Agents 清单](../remote-agents/package.json)为准，不要使用之前下载的旧包。替换已安装插件时请遵循[仓库安装说明](../../README.zh-CN.md#安装插件)。

Web 端重启更新的 profile 并刷新浏览器。Desktop 端先完全退出 DSH，使用应用自带的 `dsh` 命令和 `--profile desktop` 安装，再重新打开；npm CLI 不能管理这个保留 profile。安装单个 `.tgz`，不要安装私有仓库根目录。共享编辑器与本地化工具已打入产物，无需另装公共包。

## 打开 Git 与自动识别运行位置

在 Git 项目中打开一个会话，从右侧栏选择 **Git**。

如果同时安装了 [`@xbzbing/dsh-git-panel`](https://www.npmjs.com/package/@xbzbing/dsh-git-panel)，在 Remote Agents 工作区中，它在“对话”旁的 **Git** 标签会显示 Git 视图。该插件只在 DSH 宿主机器上运行 Git，而远程工作区在宿主机上只是一个本地锚点目录，否则它读到的是这个目录里的仓库，而不是远程仓库。其他会话中，该标签仍显示它自己的界面。

无需切换本地/远程模式：

- 普通会话工作目录在 **DSH 宿主机器**上运行 Git，不一定是浏览器所在的机器。
- 位于 `remote-workspaces` 下的 Remote Agents 工作区锚点，通过 Remote Agents 在会话已验证的 SSH 主机和目录中运行 Git、传输文件；Git 标题栏显示主机名。
- 服务缺失或远程目标无法验证时会报错，**不会回退到本地锚点运行 Git**。请先在 Remote Agents 中配置并选择已验证的工作区。Git 操作不需要克隆或同步一份本地副本。

界面跟随 DSH 的英语/简体中文设置，并适配浅色与深色主题。

## 当前功能

| 区域 | 功能 |
| --- | --- |
| 分支 | 本地和远程分支、最新提交摘要与日期、上游领先/落后数量与已删除提示；按分支名或最新提交摘要搜索；复制分支名 |
| 切换 | 双击本地分支（或按 Enter）切换；激活当前分支执行拉取；激活远程分支创建对应的本地跟踪分支 |
| 分支菜单 | 拉取当前分支、获取全部远程并清理失效引用、重命名本地分支、将其他分支合并到当前分支、删除非当前的本地或远程分支 |
| 提交图 | 彩色轨道、提交摘要与分支标签；调整列宽并在浏览器中记住；选择提交查看哈希/作者/日期，执行 cherry-pick 或 revert |
| 改动 | 冲突、已暂存、未暂存分组；逐文件暂存、取消暂存、丢弃、复制路径与查看差异；提交、推送、同步、暂存工作进度与弹出最近工作进度 |
| 对话 | 将改动审查、提交说明、单文件审查、差异或冲突分析提示加入输入框草稿；**不会自动发送消息** |
| 文件列表 | 为本地工作区文件树、Remote Agents 远程文件列表添加改动字母、文件名颜色和目录改动圆点 |

操作显示进度、结果与错误；侧栏中运行的操作可点击**取消**。刷新/状态按钮重新读取仓库。页面可见时按缓存策略轮询工作区状态（本地状态有效期 3 秒，远程 10 秒）；分支和提交图在打开面板、面板操作完成或手动刷新时更新，并非实时 Git 事件流。

### 差异与冲突处理

有改动的受支持代码/文本文件可在对话旁打开差异。受支持的内置文件预览也会提供 **Git 差异**选项，但不替换默认预览器。**打开文件**可返回其他可用预览器。

Monaco 比较的是 **HEAD 与当前工作树文件**，包含已暂存和未暂存改动，而不是仅比较暂存区或暂存区与工作树。侧栏已暂存分组打开的内嵌补丁则比较暂存区与 HEAD（`git diff --cached`），只展示已暂存改动。其他内嵌差异使用 `git diff HEAD`，包含已暂存和未暂存改动。未跟踪文件没有内嵌 Git 补丁，但完整比较会将其与空文件比较；已删除文件则以空内容作为工作树版本。

可选择并排/行内模式、自动换行、折叠未改动区域、字号和编辑模式。**保存**或 ⌘/Ctrl+S 写入工作树文件；**暂存**操作处理磁盘上的文件，不包含编辑器尚未保存的文本，请先保存。本地文件 I/O 使用绑定到已验证目录的短生命周期 Node 子进程，并核对文件/目录身份、元数据及内容哈希。替换父目录不能把该进程的数据读写或临时文件清理重定向到替换后的目录。保存采用原子 rename，但没有跨进程的比较并交换（CAS）：不配合的外部写入者仍可能在最终检查到 rename 之间插入修改。这既不是沙箱，也不保证绝对不会丢失并发更新。会话切换工作区后，旧草稿仍然可见，但编辑、保存和暂存会被禁用，直到明确点击重新加载进入新工作区。重新加载会丢弃旧草稿，请先保留需要的改动。

冲突块支持**接受当前**、**接受传入**和**接受两者**（先当前、后传入），保留周围上下文并折叠较远的未改动行。支持普通和 diff3 冲突标记。检查结果后点击**保存并解决冲突**，写入并暂存该文件。仍有冲突标记时此操作禁用；暂存前会核对保存后的文件版本。若保存成功但暂存失败，界面会明确报告部分成功并保留新的已保存版本：请检查错误并重试暂存，不要认为保存已被撤销。普通**保存**仍然只写文件，**暂存**仍是针对磁盘文件的独立操作。解决并暂存一个文件不会自动提交或完成 merge/rebase/cherry-pick；界面未提供的 continue/abort 操作需在终端执行。rebase 期间应按 Git 的冲突两侧语义理解当前/传入，不要直接当作原来的本地/远程分支。

## 凭据与安全

- 使用执行机器已有的 Git credential helper 和 SSH 密钥。Git 不等待交互式密码输入、编辑器或分页器；请预先配置凭据和提交者身份。
- **本地 HTTPS 认证失败**时，侧栏可保存用户名与密码/token 并重试。凭据以 Git store 格式**明文保存**到 `$DSH_HOME/storages/dsh-git-view/git-credentials`（默认 `~/.dsh/storages/dsh-git-view/git-credentials`），文件权限为 `0600`。该文件及其备份均应视为敏感信息，不是系统钥匙串。
- 保存的凭据按 HTTPS **主机**生效，不限单个仓库。仅此插件的 Git 命令会为该主机覆盖其他 credential helper；不会把系统钥匙串里的凭据复制到文件，也不修改终端 Git 配置。建议使用权限最小且可撤销的 token；目前需在界面外管理或移除已存条目。
- **Git 视图不保存远程凭据。** 请在远程机器上配置 credential helper 或 SSH 密钥；不会将本地凭据文件转发过去。
- **提交前会暂存整个仓库的所有改动**（先 `git add -A`，再 `git commit -m`），包括未被忽略的未跟踪文件，不限已暂存分组或会话所在的子目录。提交前请检查整个仓库。
- **暂存工作进度仅包含已跟踪文件的改动**（`git stash push`，不带 `-u`），未跟踪和被忽略的文件仍保留。弹出操作应用最近的一条 stash，可能发生冲突。
- **同步先获取最新上游状态，仅在落后时拉取，原先存在领先或落后时再推送。** 拉取使用 `git pull --no-rebase --ff --no-edit --no-autostash`：可快进则快进，否则合并，不改写提交，也不自动 stash。要求当前位于有上游的分支；正在进行的 rebase/merge/cherry-pick/revert 必须先完成或明确中止。落后时需先提交或 stash 已跟踪文件的改动；未跟踪文件冲突仍可能导致 Git 拒绝拉取。这里不是文件同步，独立的普通拉取操作使用 `git pull` 并遵循仓库配置。
- 丢弃已跟踪文件时从暂存区恢复工作树（已暂存改动保留）；未跟踪文件通过 `git clean -f` 删除。本地分支采用**强制删除**（`git branch -D`），即使存在未合并提交；删除远程分支会向服务器推送删除。丢弃和删除分支有确认步骤，但并非每种修改操作都有确认。
- 这些是用户直接点击的 Git 操作，不是经过智能体逐工具审批的模型工具调用。它们以执行账户的权限运行。Git 配置、hooks 和 filters 可以执行程序，只应对可信仓库操作；路径和版本检查并不构成通用 Git 沙箱。
- 取消或超时会尽可能终止当前命令，并跳过该批次后续命令，**不会撤销**已经发生的改动、提交、hooks 或网络操作。中断/失败后请检查仓库状态。

## 限制

- 提交图最多读取所有引用中的 **300 条提交**（`--all --date-order`），不提供更早历史的分页加载。
- 文本比较/编辑上限为每个文件 **4 MB（4 × 1024 × 1024 字节）**。二进制、含 NUL 的文件或非 UTF-8 的工作树文件不能作为文本编辑。编辑器只操作会话工作区内的已有文件；仓库级状态列表可能包含该目录之外的路径。
- 侧栏内嵌差异最多展示 30,000 个字符；将该差异加入消息草稿时最多包含 8,000 个字符。较大审查请使用完整文件比较或终端。
- 每条 Git 命令最多保留 8 MiB 标准输出和 64 KiB 标准错误。读取/快速修改通常限时 20 秒，可能运行 hooks 的修改 60 秒，网络操作 90 秒；更长操作可能需要终端。
- 不提供 clone/init、任意新建分支、按代码块暂存、stash 浏览器、强制推送或 merge/rebase continue/abort 界面。不是 Git CLI 的完整替代品，**未验证与 `dsh-git-panel` 的完整功能一致性**。

### 与 dsh-git-panel 的关系

[dsh-git-panel](https://github.com/a792883583/dsh-git-panel) 是 UI 参考，不是兼容性承诺。源码比较基准为 **0.1.20**，提交 [`661685f4dc53eae3ccf9d16358911024dcfcde9e`](https://github.com/a792883583/dsh-git-panel/tree/661685f4dc53eae3ccf9d16358911024dcfcde9e)。该版本源码的同步仍使用 pull-with-rebase，保存与暂存是独立操作；Git 视图的不变基同步及显式“保存并解决冲突”属于有意改进，并非行为完全一致的声明。

比较范围是本文描述的分支、提交图、改动、差异、冲突和对话操作，而非上游全部 API 或宿主环境。本仓库有意只提供英语/简体中文，不含上游的西班牙语；要求声明范围内的 DSH 0.2.1-rc.2 或更新版本，而非上游最低 0.1.5。本地文件子进程目前在 macOS 上完成过测试，不应据此推断跨平台兼容性已验证。上述限制和尚未测试的交互仍是限制或待验证项，不代表已验证完整一致性。

## 开发检查

使用仓库根目录的依赖和固定 pnpm 版本，约定见[开发指南](../../docs/development.md)。在仓库根目录执行：

```sh
pnpm --filter dsh-git-view typecheck
pnpm --filter dsh-git-view test
pnpm --filter dsh-git-view build
# 或一次运行上述三项：
pnpm --filter dsh-git-view check

# 共享编辑器和同 checkout 的远程集成：
pnpm --filter @dsh-plugins/file-view check
pnpm --filter dsh-remote-agents check
pnpm --filter dsh-git-view pack:plugin
```

测试脚本包含服务端/解析器测试及 React/jsdom 客户端测试；该包没有 `test:ui` 脚本。确定性的[本地文件安全测试](test/files-safety.test.ts)覆盖目录/根目录替换、文件身份与内容变化、临时文件篡改、取消与清理、别名并发保存、权限、编码和大小限制。这些检查无法消除上文所述最终检查到 rename 之间的竞争窗口。发布前检查压缩包中的服务端/客户端入口、按需编辑器及其声明、双语 README 和许可证。在可丢弃的本地仓库及已验证远程仓库中，手动检查分支切换、差异、冲突保存/暂存、文件标记、认证失败与取消操作，并覆盖两种语言和主题。这是应执行的检查清单，不代表已经验证全部宿主或流程。
