# DSH Remote Terminals 更新日志

[English](CHANGELOG.md) | **简体中文**

按版本从新到旧列出变化及升级后需要做的事。

## 0.1.6 — 切回对话时不再闪一下“正在连接…”

- 你在看别的对话时，DSH 不保留侧边栏终端的画面。每次切回来它都重新连接一次，终端上方会出现一行**正在连接…**，把画面往下顶一下，随即消失。
- 这一行，以及读取终端环境、启动时的那两行，现在持续超过 0.7 秒才显示，之前不占位置。终端还没连上时不显示光标。
- 需要你处理的状态和以前一样立即显示：**重新连接**、**重试**、**新建终端**、**接管输入**。
- 终端在每次切回时仍然是重建的，所以滚动位置不保留。本地终端和 TUI 对话同样生效。
- 升级后重启 DSH 即可。远程智能体不用动。

## 0.1.5 — 终端可以在 DSH 0.2.2-rc.2 上使用

- DSH 0.2.2-rc.2 改了启动终端的方式。在它上面装着 0.1.4 时，终端打不开，报“Cannot read properties of undefined (reading 'throwIfAborted')”：TUI 对话如此，侧边栏的终端走同一条路，本地终端也一样。
- 现在终端在 0.2.2-rc.2 上可以正常启动，DSH 关闭后继续运行，旧版本保存的终端也还能找到启动器。更早的 DSH 版本和以前一样。
- 先升级这个插件，再升级 DSH，然后重启 DSH。远程智能体不用动。

## 0.1.4 — 其他插件可以往 TUI 对话的输入行填字

- TUI 对话里，输入框的位置是终端，DSH 把原来的输入框藏在下面。往输入框填字的插件（比如游戏素材的**交给智能体…**）填进了那个看不见的输入框，所以界面上什么都没出现。
- 现在这类文字会以粘贴的方式填到 CLI 的输入行，不会替你发送。对话停在别的标签页或终端还在打开时，最多等 10 秒。
- Claude Code 和 Codex 能接收带换行的粘贴。终端里跑的程序不支持时，文字会合成一行，避免其中一部分被直接发出。
- 需要对方插件主动使用：游戏素材从 0.1.3 起支持。升级后重启 DSH，远程智能体 0.2.130 不用动。

## 0.1.3 — TUI 对话不再显示滚动条

- TUI 对话滚动时或鼠标靠近右边时，会出现一根灰色滚动条。现在去掉了，滚轮和触控板照常滚动。
- 文字顺带用上了滚动条原来占的那一条，仍然居中。
- 升级后重启 DSH 即可，远程智能体 0.2.130 不用动。

## 0.1.2 — 升级前打开的终端能重新启动

- 升级前在远程工作区里打开的侧边栏终端，DSH 重启后显示 **Selected shell is not available in this execution environment**，点**重试**也一样。浏览器记住的是启动时那个 Shell 的完整路径，而那还是远程智能体目录下的旧路径，DSH 已经不再提供。
- 现在这样的终端会启动同一个 Shell 现在所在的位置，并显示里面原来运行的内容，因为它在机器上一直没停。
- 升级后重启 DSH，在报错的终端里点**重试**。远程智能体 0.2.130 不用动。

## 0.1.1 — 重新认得远程智能体的拒绝

- 两个插件各带一份共用代码，0.1.0 认不出远程智能体返回的错误。于是机器上不存在的文件（例如 SSH 机器上的项目没有 `.dsh/worktree.json`）被当成失败而不是"没有"，远程智能体的每一次拒绝到页面上都变成了 502，而不是它本来的状态码。
- 在真实安装上看到的现象：给不在远程工作区的对话询问远程 Shell 时返回 502。现在会回答"没有"。
- 升级后重启 DSH 即可，远程智能体 0.2.130 不用动。

## 0.1.0 — 终端、TUI 对话和 worktree 工作区独立成插件

- 不随 DSH 结束的远程终端、终端 Shell 菜单里的 **Remote Claude** 和 **Remote Codex**、TUI 对话，以及「添加工作区 › 基于项目」，在 0.2.129 及以前属于远程智能体。现在它们是这个插件，用法不变。
- **把远程智能体升级到 0.2.130 后，请在它旁边安装本插件并重启 DSH**，每台用到这些功能的 DSH 都要装。不装的话这些功能就没有了，远程智能体的其他部分不受影响。
- 第一次启动时会接管你已有的 TUI 对话。远程机器上正在运行的终端和 CLI 继续运行，重新打开对话看到的还是同一个进程。
- 本插件自己不保存机器：它使用远程智能体里保存的机器和那里的连接。没有 0.2.130 或更新版本的远程智能体时，它会加载但什么都不做。
- 其他插件仍通过原来的服务名 `remoteAgentsWorktrees` 使用 worktree 工作区。
