# DSH Remote Terminals 更新日志

[English](CHANGELOG.md) | **简体中文**

按版本从新到旧列出变化及升级后需要做的事。

## 0.1.24 — 切换机器时 TUI 不再叠字

- 用互联切换机器时，TUI 对话可能有一瞬间文字叠成一团：同一个对话的好几屏画在一起，直到 CLI 下一次输出才恢复。互联把没在看的机器页面藏起来但仍保留布局，那里的 TUI 如果还在运行（回合、转圈、状态行），就会继续重画。默认的 WebGL 渲染下，为了透出窗口背景，终端背景是透明的，每次重画都叠在上一次上面；浏览器只在画面显示过之后才清空画布，所以切过去的第一帧会显示离开以后画过的每一屏。
- 现在每次重画都从空画布开始。不用 WebGL 的渲染一直不受影响。
- 可以单独升级，不需要重启；各设备刷新页面后生效。修复在 TUI 所在机器的页面里，所以通过互联打开的 TUI 在哪台机器上，那台机器就要更新。

## 0.1.23 — 一天没用的 TUI 会自己结束

- 以前只要某个 DSH 还开着 TUI 对话的终端，它的 CLI 就一直运行，所有设备都离开 7 天后才结束。对话开多了，闲着的 CLI 越积越多：一台机器上有 42 个，一共占 4.3 GB。现在 TUI 对话 24 小时没人打字、CLI 也没有任何输出，就会结束，不管有没有 DSH 连着。正在进行的回合会一直有输出，所以永远不算闲置。CLI 里还在跑的东西（比如后台命令）会一起结束。
- 再次打开对话会用同一个会话重新启动 CLI（`claude --resume`、`codex resume`、`agy --conversation`），历史都在，第一次要等几秒。升级前就打开的页面会显示一行说明，用 DSH 的重启也一样能继续。
- 侧栏终端不受影响：里面可能跑着几天都不输出的服务，仍然是所有设备离开 7 天后才结束。
- 可以单独升级，不需要重启；各设备刷新页面后生效。已经在运行的 TUI 对话在它的 CLI 下次启动前仍按旧规则。

## 0.1.22 — 手机上的 TUI 下面多了一排按键，两边留白变窄

- 手机键盘只有字母和回车，所以在手机上的 TUI 对话里切换不了 Claude Code 的模式（Shift+Tab），在它的菜单和历史记录里移动不了，也改不了输入里的光标位置。现在触屏上终端下面有一排按键：**Esc · Tab · ⇧Tab · ↑ · ↓ · ← · →**，回形针和滑杆按钮在这一排的最右边。每个键发出的内容和真实按键一样（方向键按 CLI 要求的光标键模式发送），按住方向键会连续触发；点按键不会抢走焦点，键盘开着还是收着都保持原样。这一排占自己的位置，不再浮在终端上面，所以最后一行不会被挡住；终端因此少两行左右。0.1.19 的 Esc 按钮现在是这一排的第一个键。
- 屏幕宽度不超过 600 px 时，终端两边的留白从 24 px 缩到 8 px：手机上从 46 列变成大约 49 列，Claude Code 的状态行也不那么快被截断。
- 触屏上的按钮（这排按键、回形针和滑杆）在浅色主题下几乎看不见，现在换成两种主题下都看得清的灰色。
- 电脑上不受影响。可以单独升级，不需要重启；手机上刷新页面后生效。

## 0.1.21 — 新开的 TUI 顶上不再出现 `^[[I^[[O`

- 刚打开的 TUI 对话，CLI 第一行前面可能出现 `^[[I^[[O`。这是页面用来告诉主机“你正在看哪台设备”的焦点报告（0.1.20 起不管哪个 CLI 都会发）；第一次发出时终端还在启动，会把收到的内容原样显示出来。只影响显示，CLI 并没有收到。
- 现在页面要等终端里画出内容后才认领画面。打开 TUI 的设备本来就会取得画面大小，不受影响。
- 可以单独升级，不需要重启；每台设备都刷新一下页面。

## 0.1.20 — Antigravity 的 TUI 会跟随你正在看的设备改变大小

- 在手机上用过的 Antigravity TUI 对话，回到电脑上还是手机的宽度：电脑窗口中间只显示窄窄一列，要在电脑上打字才会变回来。0.1.10 起画面靠“焦点报告”跟随你转向的设备，而 Antigravity 从不开启焦点报告（1.5.12 实测），所以切回电脑时它收不到任何通知。
- 现在不管是哪个 CLI，页面都会主动认领画面：对话出现在眼前、切回它的窗口或标签页、或点进它的终端，画面就改成这台设备的大小，Antigravity 会按新宽度把整个对话重新画一遍。Claude Code 和 Codex 的表现不变。没有开启焦点报告的 CLI 不会再收到焦点报告。
- 可以单独升级，不需要重启；每台设备都刷新一下页面。升级前就已打开终端的 TUI，在 DSH 重新打开它的终端之前，仍会把认领信号转给 CLI：Antigravity 1.5.12 会忽略它，CLI 退出后留下的 shell 只会响一声提示音。

## 0.1.19 — TUI 对话加了 Esc 按钮，方便手机操作

- 手机键盘没有 Esc 键，所以在手机上关不掉 CLI 里的弹窗（比如 Claude Code 的 `/usage`），也中断不了正在跑的一轮。现在触屏上的 TUI 对话右下角、回形针左边多了一个 **Esc** 按钮，点它给 CLI 发的 Esc 和按键完全一样；键盘开着还是收着，都保持原样。
- 电脑上不显示这个按钮。可以单独升级，不需要重启；手机上刷新页面后生效。

## 0.1.18 — 手机键盘弹出时 TUI 对话停在键盘上方

- 手机上在 TUI 对话里弹出键盘，会把整个页面往上推：对话标题移出屏幕，光标一动页面就跟着跳；键盘收起后页面还可能停在推上去的位置，底部留出一条空白。移除 DSH Web Mobile 之后，没有东西再把页面放回原处。
- 现在触屏上显示 TUI 时，页面保持不动，TUI 缩到键盘留下的可见区域里：终端行数变少（和终端 App 一样），CLI 的输入行和右下角的两个按钮停在键盘正上方；收起键盘后行数恢复。只改高度，Claude Code 不会重建历史。
- 电脑上没有变化。可以单独升级，不需要重启；手机上刷新页面后生效。

## 0.1.17 — TUI 对话加了文件按钮，方便手机上传

- TUI 对话右下角、渲染按钮旁边多了一个回形针按钮。点它打开设备自己的文件选择器，选中的文件会上传，路径填进 CLI 的输入行，和拖入、粘贴的文件一样（图片显示为 `[Image #1]`）。手机既不能把文件拖进终端，也不能粘贴文件，所以以前在手机上没有办法把图片或文件交给 CLI。
- 触屏上右下角的两个按钮都变大了（32 像素），也更显眼。
- 普通对话不需要改：DSH 0.2.2-rc.3 起，输入框的 **+** 菜单里有 **文件**，手机上同样会打开选择器。
- 可以单独升级，不需要重启；刷新页面（手机也要刷新）后能看到按钮。

## 0.1.16 — 统计 Antigravity TUI 对话的 Token 用量

- Antigravity TUI 对话的 Token 用量现在也计入 `dsh-usage-stats`，和 Claude Code、Codex 一样每轮每个模型一条。以前完全不计，用量面板里只有 Antigravity 聊天的轮次。
- Antigravity 不写用量日志，所以插件在它运行的机器上读这个对话自己的数据库（`~/.gemini/antigravity-cli/conversations/`），用 `sqlite3`，没有这个命令时用 Python 自带的。只取每次模型调用的用量和每一步的开始时间，不取对话内容。读出的数和 Antigravity 在聊天里为同样的轮次上报的用量逐个 Token 一致。
- 一轮在 Antigravity 把对话标为空闲时计入：终端开着时一轮结束几秒后，否则在下一次每 10 分钟的读取时。第一次读取会把这个对话以前的轮次一并补记，时间按它们实际运行的时间。
- 这个数据库的结构是 Antigravity 自己的、没有公开。以后的 Antigravity 版本可能改掉它，那时 TUI 的用量会暂时计不到，要等本插件更新。
- 可以单独升级，不需要重启。

## 0.1.15 — TUI 启动失败时说明原因；本机 Antigravity 的登录提示

- 在 TUI 里开始新对话的按钮启动失败时，以前只多了一圈红框，原因藏在悬停提示里，看起来像点了没反应。现在原因也会显示在按钮上方的卡片里。按 Esc 或点别处关闭，再点按钮就重试。
- 这台电脑上的文件夹里 Antigravity 没有登录时，提示现在会让你在这台电脑本机的终端里运行 `agy acp --login`，不要通过 SSH。Antigravity 在本机运行时从钥匙串读取登录，通过 SSH 登录的是另外一份。以前的提示只说明了 SSH 的情况。
- 可以单独升级，不需要重启。刷新 DSH 页面即可用上新按钮。

## 0.1.14 — 图形上下文恢复后 TUI 的文字完整重画；历史按新宽度重建得更稳

**回到 TUI 后文字缺失（多见于手机）：**

- 开着 WebGL 渲染时，TUI 有时回来后大部分文字不见了：没有英文和数字、没有分隔线，汉字只剩一部分，而且总是同样那些字，新输出的文字却正常。这发生在浏览器丢掉图形上下文之后，例如 Android 把放在后台的页面的图形资源收回。所有用 WebGL 绘制的 TUI 共用一套字形，上下文恢复后，之前画过的字形一直是空白。现在上下文一恢复，插件就为所有 TUI 重新绘制全部字形。

**TUI 的历史更常保持同一宽度：**

- 换宽度后用来按新宽度重新打印历史的那份 Claude Code 副本，以前只等它 1.5 秒开始输出；机器忙的时候它会更慢，于是这次重建就跳过了。现在最多等 10 秒；副本什么都没输出时，会在对话安静下来后再试一次。
- 自动模式下，工具调用下面的 "Allowed by auto mode" 这类提示只在真正运行它的会话里显示，个别标题还可能保持旧宽度。这些行会让屏幕和副本对不上，重建也就跳过了。现在会跳过这样的行。
- 和之前一样，这需要由新版本启动的 Claude Code：从旧版本起一直在运行的 TUI 对话，在重启之前仍会混着不同宽度，例如把这一行归档再恢复之后才会好。
- 可以单独升级，不需要重启。显示 TUI 的 DSH 页面（包括手机上的）刷新一次即可用上绘制修复。

## 0.1.13 — 本机文件夹里的 TUI 对话；换设备后 TUI 的历史保持同一宽度

**本机文件夹里的 TUI 对话**（需要 Remote Agents 0.2.142 或更新）：

- 在本机文件夹（用**添加工作区 › 本机**加入）的新对话里，选一个本机的 Claude、Codex 或 Antigravity 模型，点输入框左下角它的图标，和远程工作区里一样。CLI 直接在这台电脑上运行，不经 SSH，和经 SSH 时一样从新的登录环境启动。以前只有远程工作区里有这个图标。
- 它由和远程机器上相同的保持器托管，DSH 重启时继续运行，再点这一行看到的还是同一个进程。标题、侧边栏里的状态、用量统计、拖入和粘贴的文件、归档都和远程工作区一样。
- 在这样的文件夹里，终端的 shell 菜单里的 **Remote Claude**、**Remote Codex**、**Remote Antigravity** 现在会在本机启动对应的 CLI，而不是打开本地 shell。**Remote workspace** 仍打开本地 shell，DSH 自己的终端不变。
- 终端保持器现在启动时就和打开它的终端脱离。DSH 关闭一个终端时会结束它下面启动的所有进程，在本机会把保持器一起带走。

**换设备后 TUI 的历史保持同一宽度：**

- 开着「本地滚动」时，Claude Code 自己断行，宽度变化时只重画当前一屏，上面的内容保持写出时的宽度。于是在手机和电脑之间切换后，历史一段窄一段宽，交界处的文字还会出现两遍。
- 现在新宽度保持一秒后，远程机器会运行一个 Claude Code 副本，按这个宽度把对话重新打印一遍，用它替换当前一屏以上的全部内容，从切换到换好总共约四秒。副本是这个会话的 fork，不保存任何东西，不跑 hook、MCP 服务和自动更新，打印完就结束。Claude Code 正在干活时，历史会在它输出的间隙换上，或者等这一轮结束再换。当前一屏，以及你正在输入的内容，保持不动。
- 对话最近一次压缩之前的历史不会重新打印（Claude Code 接回会话时本来也不显示），重建后的历史最多保留 5000 行。
- 只对这个版本启动的 Claude Code 生效，所以 DSH 需要升级到这个版本；已经在运行的要重启一次才会生效，比如把这一行归档再撤销归档，会接回同一个会话。之后所有显示这个对话的设备看到的都是重建后的历史。

## 0.1.12 — Antigravity 也能做 TUI 对话

- 远程 Antigravity 模型也可以用 TUI：在远程工作区新建对话，选一个 Antigravity 模型，点输入框左下角蓝色的 A，这个对话的「对话」标签页就变成交互式 `agy`，用你选的模型和思考强度启动。终端的 Shell 菜单里，Remote Claude、Remote Codex 旁边多了 **Remote Antigravity**。
- Antigravity 不能给它新开的会话指定 ID，所以插件先经 Antigravity 的 ACP 服务建好会话，再用 `agy --conversation` 打开。它不给会话记住模型，所以每次启动都带上模型和思考强度；在里面用 `/model` 换的模型，到 CLI 下次启动前有效。
- 行标题先用 Antigravity 自己起的标题或 `/rename` 的名字，再用第一条消息，读自远程机器上它的会话摘要库（用 `sqlite3`，没有时用 `python3`）。侧栏状态只看它的屏幕，因为它不设终端标题。
- Antigravity 的 Token 用量不计入，因为它把每轮记在自己的数据库里而不是日志里。
- 通过 SSH 使用 Antigravity 需要单独登录（在那台机器上运行 `agy acp --login`），和远程智能体的对话一样；没登录时启动 TUI 会提示。它第一次打开某个目录时会问是否信任，默认选项是信任。
- 可以单独升级，不需要重启。

## 0.1.11 — TUI 对话不再出现在其他 DSH 里

- TUI 对话只留在发起它的 DSH 里，不再登记到机器上供其他 DSH 显示。要在另一台电脑或手机上用，直接打开那个 DSH，比如它的网页。同一个对话在两台设备上同时打开时，仍然共用一个终端，画面跟随你正在用的那台。
- 之前从其他 DSH 带过来的 TUI 对话会留下，照常打开同一个终端；它们的标题和归档不再跟随其他 DSH。
- 机器上的 `~/.dsh-remote-agents/tui-v1/` 不再使用，也不会删除，可以手动删掉。还在 0.1.10 的 DSH 仍会往里登记它自己的 TUI 对话，升级后的 DSH 不读。
- 可以单独升级，不要求远程智能体的版本。升级后重启 DSH。

## 0.1.10 — 两台设备同时打开的 TUI 跟随你正在看的那台；设备模式下文字不再过大

- 一个 TUI 对话在两台设备上同时打开（比如电脑和手机）时，两边共用一个画面、一个大小：跟随最后输入的那台。在另一台上输入之前，画面一直是不合适的大小，于是电脑上对话挤在左边窄窄一列，手机上则是按宽窗口排版的画面。
- 现在画面也会跟随你转向的那台设备：点进它的终端、切回它的窗口或标签页、或在那里打开这个对话，画面就改成那台设备的大小，粘贴也一样。画面刚换了大小的一秒内，焦点变化不算数，这样两个窗口不会互相来回抢。
- 在模拟屏幕缩放的浏览器里（例如电脑上 Chrome 开发者工具的设备模式），TUI 的字会大到两倍多，而且只显示画面左下角的一部分：WebGL 按模拟的缩放作画，画布却是按真实缩放定的大小。插件现在能识别这种情况，改用网页自带的渲染，并在渲染菜单里说明原因。真实手机上没有任何变化。
- 共用同一台机器的两个 DSH 都升级到这个版本后，画面才会两个方向都跟随：向机器要画面的是各自 DSH 的终端。

## 0.1.9 — 手机上可以滑动终端，Claude Code 的符号也正常显示了

- 在手机或平板上，终端和 TUI 对话无法滚动：手指滑动没有任何反应。DSH 用的终端只认鼠标滚轮，自己不处理触摸。
- 现在手指滑动就能滚动，和手机上滑动列表一样，快速一划还会继续滑一段再慢慢停下；随便点一下就停。Claude Code 用经典渲染（"本地滚动"，默认开）的对话和 shell 会滚动历史；全屏绘制的程序（例如全屏模式的 Claude Code）收到的是滚轮会发的内容。点一下仍会弹出键盘，滑动不会。横向滑动留给页面。
- 在手机上，Claude Code 每一步前面的 ⏺ 显示成橙色的表情方块，模式前面的 ⏵⏵（以及类似符号）显示成空方框：手机上没有含这些符号的文字字体。插件现在自带这些符号，每个正好一个终端格宽，取自 Noto Sans Symbols 2 字体（6 KB）。只在触屏设备上生效，电脑上没有任何变化。
- 手机上已经打开的对话，刷新页面后才会显示新的符号。

## 0.1.8 — 在手机或平板上的终端里可以打字了

- 在装了手机布局插件（dsh-web-mobile）的触屏设备上，点终端或 TUI 对话后无法输入：屏幕键盘不弹出，外接键盘打的字也不知去向。
- 原因：手指点到的是终端画面的某个绘制层，终端随后用代码把键盘焦点移到它隐藏的输入框上。那个插件只在手指确实按在输入框上、或按在包含它的元素上时才允许代码聚焦，于是每次都被拒绝。
- 现在，在以手指为主要指针的设备上，这些绘制层不再接收点击，点击落在画面本身，而画面包含那个输入框。侧边栏终端和 TUI 对话都生效；用鼠标时没有任何变化。
- 在这类设备上打开 TUI 对话仍然不会自动弹出键盘，这正是那个插件的用意：先点一下终端。
- 升级后刷新页面即可。远程智能体不用动。

## 0.1.7 — TUI 对话会出现在使用同一台机器的每个 DSH 里

- 以前 TUI 对话只有发起它的那个 DSH 知道。在一台电脑上发起后，DSH 网页、手机和其他 DSH 里都看不到，尽管它的 CLI 运行在大家都能连上的机器上。
- 现在大约半分钟内，它会出现在每个 DSH 里，放在对应目录的远程工作区（没有就自动添加）。各端打开的是机器上的同一个终端：画面相同，哪一端都能输入。画面只有一个大小：跟随最后打开或调整大小的那个窗口；在另一个窗口里输入，画面就改回那个窗口的大小，所以总是按正在使用的那一端排版。这一点需要由这个版本启动的终端；已经在运行的终端在重新启动之前，仍然只跟随最后连上的那一端。
- CLI 给对话起的标题会同步到其他 DSH，你在那边自己改过名的除外。在一个 DSH 里归档或恢复，其他 DSH 里也随之归档或恢复。归档和以前一样会结束它的 CLI。
- 你之前已归档的对话留在原处，只有未归档的才会登记。每个 DSH 从第一次显示这个对话起统计用量，之前的轮次不会在那边再算一遍。
- 在远程智能体里取消了 **与其他 DSH 共享会话和工作区** 的机器，它的 TUI 对话只留在发起它的 DSH。
- 升级后：每个 DSH 都安装这个版本并各自重启。你现在开着的 TUI 对话，会在发起它的那个 DSH 升级后登记出去。远程智能体不用动。

## 0.1.6 — 切回对话时不再闪一下“正在连接…”

- 你在看别的对话时，DSH 不保留侧边栏终端的画面。每次切回来它都重新连接一次，终端上方会出现一行**正在连接…**，把画面往下顶一下，随即消失。
- 这一行，以及读取终端环境、启动时的那两行，现在持续超过 0.7 秒才显示，之前不占位置。终端还没连上时不显示光标。
- 需要你处理的状态和以前一样立即显示：**重新连接**、**重试**、**新建终端**、**接管输入**。
- 终端在每次切回时仍然是重建的，所以滚动位置不保留。本地终端和 TUI 对话同样生效。
- 升级后重启 DSH 即可。远程智能体不用动。

## 0.1.5 — 终端可以在 DSH 0.2.2-rc.2 上使用

- DSH 0.2.2-rc.2 改了启动终端的方式。在它上面装着 0.1.4 时，终端打不开，报“Cannot read properties of undefined (reading 'throwIfAborted')”：TUI 对话如此，侧边栏的终端走同一条路，本地终端也一样。
- 现在终端在 0.2.2-rc.2 上可以正常启动，DSH 关闭后继续运行，旧版本保存的终端也还能找到启动器。更早的 DSH 版本和以前一样。
- 先升级这个插件，再升级 DSH，然后重启 DSH。远程智能体不用动。

## 0.1.4 — 其他插件可以往 TUI 对话的输入行填字

- TUI 对话里，输入框的位置是终端，DSH 把原来的输入框藏在下面。往输入框填字的插件（比如游戏素材的**交给智能体…**）填进了那个看不见的输入框，所以界面上什么都没出现。
- 现在这类文字会以粘贴的方式填到 CLI 的输入行，不会替你发送。对话停在别的标签页或终端还在打开时，最多等 10 秒。
- Claude Code 和 Codex 能接收带换行的粘贴。终端里跑的程序不支持时，文字会合成一行，避免其中一部分被直接发出。
- 需要对方插件主动使用：游戏素材从 0.1.3 起支持。升级后重启 DSH，远程智能体 0.2.130 不用动。

## 0.1.3 — TUI 对话不再显示滚动条

- TUI 对话滚动时或鼠标靠近右边时，会出现一根灰色滚动条。现在去掉了，滚轮和触控板照常滚动。
- 文字顺带用上了滚动条原来占的那一条，仍然居中。
- 升级后重启 DSH 即可，远程智能体 0.2.130 不用动。

## 0.1.2 — 升级前打开的终端能重新启动

- 升级前在远程工作区里打开的侧边栏终端，DSH 重启后显示 **Selected shell is not available in this execution environment**，点**重试**也一样。浏览器记住的是启动时那个 Shell 的完整路径，而那还是远程智能体目录下的旧路径，DSH 已经不再提供。
- 现在这样的终端会启动同一个 Shell 现在所在的位置，并显示里面原来运行的内容，因为它在机器上一直没停。
- 升级后重启 DSH，在报错的终端里点**重试**。远程智能体 0.2.130 不用动。

## 0.1.1 — 重新认得远程智能体的拒绝

- 两个插件各带一份共用代码，0.1.0 认不出远程智能体返回的错误。于是机器上不存在的文件（例如 SSH 机器上的项目没有 `.dsh/worktree.json`）被当成失败而不是"没有"，远程智能体的每一次拒绝到页面上都变成了 502，而不是它本来的状态码。
- 在真实安装上看到的现象：给不在远程工作区的对话询问远程 Shell 时返回 502。现在会回答"没有"。
- 升级后重启 DSH 即可，远程智能体 0.2.130 不用动。

## 0.1.0 — 终端、TUI 对话和 worktree 工作区独立成插件

- 不随 DSH 结束的远程终端、终端 Shell 菜单里的 **Remote Claude** 和 **Remote Codex**、TUI 对话，以及「添加工作区 › 基于项目」，在 0.2.129 及以前属于远程智能体。现在它们是这个插件，用法不变。
- **把远程智能体升级到 0.2.130 后，请在它旁边安装本插件并重启 DSH**，每台用到这些功能的 DSH 都要装。不装的话这些功能就没有了，远程智能体的其他部分不受影响。
- 第一次启动时会接管你已有的 TUI 对话。远程机器上正在运行的终端和 CLI 继续运行，重新打开对话看到的还是同一个进程。
- 本插件自己不保存机器：它使用远程智能体里保存的机器和那里的连接。没有 0.2.130 或更新版本的远程智能体时，它会加载但什么都不做。
- 其他插件仍通过原来的服务名 `remoteAgentsWorktrees` 使用 worktree 工作区。
