# DSH Remote Terminals

[English](README.md) | **简体中文**

远程工作区里的终端在 DSH 关闭后继续运行；Claude Code、Codex 与 Antigravity 可直接作为对话界面；还可以基于项目的 Git worktree 新建工作区。

**需要同一个 DSH 里装有[远程智能体](../remote-agents/README.zh-CN.md) 0.2.130 或更新版本。**机器、SSH 连接和远程工作区都保存在那里，本插件只在它们之上工作，自己不保存机器列表。没有远程智能体时，本插件会加载但什么都不做。0.2.129 及以前，这里的功能都在远程智能体里。

## 终端

- **终端**：在远程对话中点「新建终端」即可打开远程工作区的交互式 SSH 终端，也可以在原生终端的 Shell 菜单选择 **Remote workspace**。面板里不再单独提供执行命令。终端使用远程账户的正常权限；绑定失效时明确报错。
- **终端不随 DSH 结束**：关掉 DSH、电脑休眠或断网时，远程终端里的 shell 或 CLI 会继续在远程机器上运行。断线会自动重连，侧栏的终端标签在重启后也会自己回来，看到的还是同一个进程，屏幕和滚动记录都在。关闭标签、`exit` 或归档 TUI 对话会结束它；TUI 对话 24 小时没人用会结束，再打开时自动继续；其他终端一直没人回来的 7 天后结束，远程机器重启也会全部结束。这要求远程机器有 Python 3 和 Node.js 22，没有时终端里会提示，并改用普通连接，断线就结束。这些连接还关掉了 OpenSSH 的按键节奏保护（`ObscureKeystrokeTiming`），让打字在丢包的线路上不被拖住。
- **在终端里直接用 Claude、Codex 或 Antigravity**：在原生终端的 Shell 菜单选择 **Remote Claude**、**Remote Codex** 或 **Remote Antigravity**，会在同一个远程工作区启动交互式 `claude`、`codex` 或 `agy`，退出后留在远程 shell。这个会话归远程的 CLI 所有：不会显示在 DSH 对话里，用不到 DSH 共享的 MCP 服务和技能，之后在远程目录运行 `claude --resume`、`codex resume` 或 `agy --continue` 继续。留在远程对话之间切换时，「新建终端」会继续打开它；离开远程对话会还原你自己的 shell，再回来时恢复为 **Remote workspace**。

## TUI 对话

在远程工作区新建对话，选一个远程 Claude、Codex 或 Antigravity 模型，点输入框左下角的图标（Claude 是吉祥物，Codex 是它的云朵图标，Antigravity 是蓝色的 A，选了其他模型时不显示），这个对话的「对话」标签页就变成交互式 CLI，用你选的模型和思考强度启动，输入框隐藏。终端收在中间列，半透明背景透出壁纸，中文按系统字体放大填满两格，字距不再发散；灰条、边框这些由 Claude Code 自己绘制的颜色，可以在远程机器上用 `/theme` 或 `~/.claude/themes/` 调整。终端默认用 WebGL 绘制，打字和输出比网页自带的渲染更跟手；右下角的滑杆按钮可以切换 WebGL 渲染和背景模糊，浏览器用不了 WebGL 时仍用网页自带的渲染；浏览器在模拟屏幕缩放时（例如 Chrome 开发者工具的设备模式）也用网页自带的渲染，因为这时 WebGL 画出的字会过大或过小。同一个菜单里的「本地滚动」默认打开：Claude Code 用它的经典渲染启动，对话留在终端自己的回滚区（保留 10000 行），滚轮由终端直接滚动，不必每滚一步都让远程的 Claude Code 重画整屏，网络慢或丢包时也不卡；代价是 Claude Code 全屏模式的功能（点击展开、跳到底部）不可用。关掉它就回到全屏模式。经典渲染自己断行，宽度变化时只重画当前一屏，所以宽度变化几秒后（比如从电脑转到手机），远程机器上会用一个 Claude Code 副本按新宽度把对话重新打印一遍，替换当前一屏以上的历史（副本是会话的 fork，不保存任何东西，不跑 hook 和 MCP 服务，打印完就结束；最多 5000 行，从最近一次压缩开始）。开关对之后启动的 Claude Code 生效，正在运行的那个要重启，菜单里会给出「立即重启」，重启后接回同一个会话。它在工作区列表里是一行，选中哪行就显示哪个 TUI，切走时 CLI 继续运行。最近用过的 6 个终端切走后不关闭，切回来立刻显示。标题优先用在 TUI 里 `/rename` 改的名字，其次是 Claude Code 或 Antigravity 自己起的标题（Codex 这里不会自己起），再其次是第一条消息，只在这一行显示在主区域时更新；在 DSH 里手动改名后不再覆盖。重启 DSH、刷新页面或 SSH 断开时，CLI 继续在远程运行，正在跑的那一轮不会中断；再选中这一行就接回同一个进程。远程机器重启后再选中，会接回同一个会话（`claude --resume`、`codex resume` 或 `agy --conversation`）。归档这一行会结束它的 CLI，撤销归档后再选中会接回。选中文字后按 Cmd+C 复制，和普通终端一样；关掉本地滚动后，在 Claude Code 里拖选文字，松开鼠标就已复制，不用再按 Cmd+C。把文件拖到窗口里、粘贴进来（Cmd+V；图片也可以用 Ctrl+V），或点右下角的回形针按钮选择，文件会上传到远程项目的 `.dsh-remote-agents/attachments/tui/`，路径填入输入框，图片显示为 `[Image #1]`。手机上拖不了也粘贴不了文件，就用回形针：它打开手机自己的选择器，可以选相册、拍照或文件；手机上这两个按钮也会变大。手机键盘也没有 Esc、Tab 和方向键，所以触屏上终端下面有一排按键，回形针和滑杆按钮在这一排的最右边：**Esc** 关掉 Claude Code 的 `/usage` 这类弹窗或中断正在跑的一轮，**⇧Tab** 切换 Claude Code 的模式（manual、accept edits、plan），方向键在 CLI 的菜单、历史记录和输入框里移动，按住会连续触发，**Tab** 补全。它们发出的内容和真实按键一样，键盘开着还是收着都保持原样。屏幕宽度不超过 600 px 时，终端两边的留白缩到 8 px，手机上大约能显示 50 列。手机键盘弹出时，TUI 缩到屏幕上还露出的那部分，终端行数变少，CLI 的输入行停在键盘正上方；整个页面不再被推上去。每个文件不超过 50 MB，不支持文件夹；Git 会忽略这个目录，传上去的文件不会自动清理。其他往对话输入框里填字的插件（比如游戏素材的**交给智能体…**），在这里会把文字填到 CLI 的输入行，不会替你发送。对话内容只在远程的 CLI 里，DSH 的对话记录和搜索都看不到；启动后模型由 TUI 自己管，权限也用远程 CLI 自己的设置。Codex 不用它自己的全屏模式，这样滚轮能翻看对话；也不显示启动时的更新提示，因为第一个回车就会直接安装，要更新请在远程单独运行 `codex update`。Antigravity 不会给对话记住模型，所以每次启动都带上开始时选的模型和思考强度；在里面用 `/model` 换的模型，到 CLI 下次启动前有效。Antigravity 第一次在某个目录打开时会问是否信任这个目录，默认选项是信任。通过 SSH 使用 Antigravity 需要单独登录一次，和远程智能体的对话一样；没登录时，启动 TUI 会提示怎么登录。已有的对话不能转成 TUI。 CLI 的状态和其他对话一样显示在侧栏：干活时显示运行中，弹出权限确认或提问时显示等待你处理，干完且你没在看时显示已完成。状态来自 CLI 的终端标题和屏幕（Antigravity 不设标题，只看屏幕），不额外连接远程机器；只有终端开着才知道，DSH 重启后要等你重新打开这一行。Token 用量和普通对话一样计入 `dsh-usage-stats`，每轮每个模型一条，读自远程机器上 CLI 自己的记录：Claude Code 的会话文件及其子智能体文件，Codex 线程的文件及其子智能体的线程文件（例如替你审批权限请求的审查智能体，Codex 把它们放在各自的线程里），或 Antigravity 在 `~/.gemini/antigravity-cli/conversations/` 里这个对话的数据库（用 `sqlite3` 读，没有这个命令时用 Python 自带的）：终端开着时一轮结束几秒后读取，另外每 10 分钟读一遍所有 TUI 对话，DSH 关着时跑的轮次也会补上。只取带用量的行，不传消息正文；Antigravity 的数据库只取每次模型调用的用量和每一步的开始时间。第一次读取会把这个对话以前的轮次一并补记，时间按它们实际运行的时间。子智能体的用量计入当时正在跑的那一轮，模型记为子智能体自己的模型。按 Esc 中断的一轮立即计入；不过回复写到一半被打断时，日志里只留下这个回复开始时的用量，已经写出的输出 Token 计不到。日志里没有任何结束痕迹的一轮（比如 CLI 被强行结束），要等日志静默 30 分钟后才计入。Antigravity 的一轮在它把对话标为空闲时计入；通过它用的 Claude 或 GPT 模型和 Gemini 一样记在 Antigravity 下；它的数据库结构是 Antigravity 自己的、没有公开，所以 Antigravity 升级后可能暂时计不到用量，要等本插件更新。

**同一个对话在两台设备上打开。**同一个 DSH 可以同时在电脑和手机上打开，比如通过它的网页。两边打开的是机器上已经在运行的同一个终端，所以看到的画面相同，哪一端都可以输入。画面只有一个大小：跟随最后打开或调整大小的那个窗口。在另一个窗口里输入或粘贴、点进它的终端、切回那个窗口或标签页、或在那里打开这个对话，画面就改回那个窗口的大小。所以画面总是按正在使用的那一端排版，大小不同的另一端在你转过去之前可能显得偏窄或折行。

TUI 对话只在发起它的 DSH 里。0.1.10 及更早版本从其他 DSH 带过来的对话会留下，照常打开同一个终端；它们的标题和归档不再跟随其他 DSH。

### 本机文件夹里的 TUI 对话

配合 Remote Agents 0.2.142 或更新，用**添加工作区 › 本机**加入的本机文件夹，也能用本机的 Claude、Codex、Antigravity 模型开同样的 TUI 对话。CLI 在这台电脑上运行，不经 SSH，从新的登录环境启动，由同一种保持器托管（在本账号的 `~/.dsh-remote-agents/` 下），DSH 重启时继续运行。上面说的都适用，只是拖入、粘贴或选择的文件放在项目自己的 `.dsh-remote-agents/attachments/tui/` 里。在这样的文件夹里，shell 菜单里的 **Remote Claude**、**Remote Codex**、**Remote Antigravity** 会在本机启动对应的 CLI；**Remote workspace** 打开本地 shell。

## 基于项目新建工作区

**添加工作区 › 基于项目**会为项目再建一个工作区，放在独立的分支上，在那里的改动不会碰到项目本身的文件夹，和 Paseo 新建 worktree 工作区一样。先选项目（工作区里每个 Git 仓库列一项，本机或已保存的机器均可），然后选**新建分支**：从你选的分支开始（默认是仓库的默认分支），分支名自己填或自动生成，例如 `swift-otter`；或选**已有分支**：检出本地分支或只在远程的分支，后者会跟踪远程分支。点击**创建工作区**会创建 Git 工作树，以「项目 · 分支」为名添加到 DSH、排在项目后面、带上项目的 Workspace Tags 标签，然后打开它。起点是远程分支时会先拉取它（最多 15 秒，失败则用机器上已有的版本），新分支不会跟踪它的起点分支。如果工作区是仓库里的某个子文件夹，新工作区会打开工作树里的同一个子文件夹。

- **工作树的位置：**放在仓库之外，本机为 `~/.dsh/worktrees/<仓库>-<hash>/<分支>`，已保存的机器上为 `~/.dsh-remote-agents/worktrees/<仓库>-<hash>/<分支>`。只有这些文件夹下的工作树才能由本插件归档。远程工作树只需要机器上有 Git 和 POSIX shell，不需要 Node.js。
- **初始化与清理命令：**在仓库中提交 `.dsh/worktree.json`，用来准备新的工作树，例如安装依赖、复制 `.env` 这类不受版本管理的文件：`{ "setup": ["pnpm install", "cp \"$DSH_SOURCE_CHECKOUT_PATH/.env\" ."], "teardown": ["docker compose down"] }`。优先使用工作树里的这个文件，分支中没有时用项目里的。命令在工作树顶层依次运行，使用该机器的登录环境，并提供 `DSH_SOURCE_CHECKOUT_PATH`（仓库的主检出目录）、`DSH_WORKTREE_PATH` 和 `DSH_BRANCH_NAME`。创建前对话框会列出项目中的初始化命令，运行时实时显示输出，期间可以关闭窗口。分支里的命令和列出的不同时，工作区会先建好，但这些命令不会自动运行：先在日志中列出，由你选择**运行这些命令**、**跳过剩余的初始化命令**或**删除这个工作树**。归档前的确认页同样列出清理命令。某条命令失败或被停止时，工作区已经在 DSH 中：**重试**再次运行它，**跳过剩余的初始化命令**直接完成，**删除这个工作树**会删除工作树、它新建的分支以及对应的 DSH 工作区。不读取 `paseo.json`。
- **归档：**表单下方列出该项目的工作树，可以打开或归档。归档前会先列出会丢失的内容（已修改或未跟踪的文件、未推送到任何远程的提交），然后归档该工作区中的会话，停止在其中运行的远程 CLI 会话，运行清理命令，删除工作树，再把工作区从 DSH 中移除。分支默认保留；只有分支已合并到仓库的默认分支时，才提供**同时删除分支**。
- 尚未支持：检出 Pull Request、在工作区行菜单（Workspace Tags）中直接新建，以及让模型创建工作树工作区的工具。

## 给其他插件用

服务 `remoteAgentsWorktrees`（版本 1）让别的 DSH 插件能在用户对话所在的地方干活：列出 DSH 工作区里的 Git 项目、查看其中一个、像“新建工作区”对话框那样为它建一个 worktree 工作区，以及在某个工作区所在机器（本机或 SSH）的目录里执行 Git 或 shell 命令。只能到达 DSH 已列为工作区的目录。`dsh-autofix` 就建在它上面。

服务 `remoteTerminals`（版本 1）回答 `isTui(sessionId)`：某个 DSH 对话的界面是不是终端里的 CLI。远程智能体会来问，这样的对话由那个 CLI 自己回复。

## 安装与升级

在插件市场里把它装在远程智能体旁边，重启 DSH 即可，不需要任何设置。

- **从远程智能体 0.2.129 或更早版本升级：**第一次启动时会从远程智能体保存的状态里接管 TUI 对话，那份状态保持原样。远程机器上的终端和 CLI 继续运行：终端保持程序、附件目录和 worktree 仍在各机器的 `~/.dsh-remote-agents/` 下。
- **保存位置：**哪些对话是 TUI 对话、它们的详情和滚动方式保存在 `~/.dsh/storages/dsh-remote-terminals/state.json`，终端启动器在同目录的 `terminal/` 下。浏览器里的渲染与滚动选择仍使用原来的 `remote-agents.*` 键，所以会沿用。
- **终端启动器的位置随插件目录变了。**DSH 记住的旧位置的 Shell，会在下次显示远程对话时被替换。

```sh
pnpm --filter dsh-remote-terminals check
pnpm --filter dsh-remote-terminals pack:plugin
```
