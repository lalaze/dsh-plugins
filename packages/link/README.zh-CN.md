# 互联

[English](README.md) | **简体中文**

在面前这台电脑上打开其他电脑的完整 DSH。同一 Tailscale 账号下每台电脑的 DSH 都装上这个插件后，它们会互相发现；左侧栏底部的切换器可以就地打开任何一台：会话、审批、模型、设置、文件和终端都和坐在那台电脑前一样。

- **一个切换器。** 侧栏底部显示当前页面是哪台机器，圆点表示状态：绿色空闲，琥珀色有事等你处理，转动表示有对话在运行，红色连不上，灰色离线。菜单列出每台机器正在等待、运行或已完成的内容；删掉了 DSH 或本插件的电脑十分钟后自动移出列表。机器列表下方的「刷新页面」「重启 DSH…」作用于当前显示的机器。
- **即时切换。** 去过一次的机器，页面会留在窗口里，来回切换不用重新加载，还停在原来的位置。宽屏上启动几秒后会在后台先打开其他机器的页面，第一次切换也是即时的。可以在「设置 → 互联」里关掉。
- **其他机器上发生的事。** 其他机器上对话完成、失败，或者有审批、问题等你，会在页面里弹出提醒（点一下就切过去），切换器上也有数字，鼠标停在上面会写出是哪台机器；菜单里那台机器的这个数字和数字角标同色。页面不在前台时再发系统通知。TUI 对话（remote-terminals 在终端里跑的 Claude Code 或 Codex）也算在内。在「设置 → 互联」里选择要提醒哪些。
- **安全重启。** 可以重启当前页面所在机器的 DSH，经由另一台机器打开时也可以：「立即重启」，或者「空闲时重启」，等正在运行的对话和任务结束后再重启。DSH 会正常退出，由辅助进程重新拉起，页面会自己重连。支持 launchd 服务（Mac mini hub）、macOS 桌面 App，以及从终端启动的 `dsh web`。

- **全部机器的用量。** 配合使用量统计 0.1.20 或更新版本，对话标题栏的今日 Token 和统计窗口会把每台机器的用量加在一起（见该插件的说明）。
- **在其他机器上用浏览器（桌面 App）。** 另一台机器的页面右侧栏里也有 DSH 的「浏览器」，用的是桌面 App 自己的浏览器。那台机器的地址（`localhost`、它的内网、`.local` 名字、它的 tailnet 名字）经那台机器的网络打开，所以 `http://localhost:5173` 就是那台机器上跑着的开发服务器，地址栏也照原样显示。公网网站从你眼前这台电脑访问。

## 原理

每个装了插件的 DSH 都在本机的 Tailscale 地址上开放一个端口（默认 7390）。这个入口只接受 `tailscale whois` 认定与本机属于同一 Tailscale 用户的请求，并且只认本机自己的地址（其他网站的页面无法借它操作 DSH）。通过后，请求带着进程内部生成的登录信息转给本机的 DSH；不保存、也不发送任何 token 或密码。

你正在用的 DSH 会在自己的地址下用 `/dsh-link/peer/<id>/` 显示另一台机器：这个路径受它自己的登录保护，请求转发到那台机器的入口。每台机器的页面各用各的浏览器存储。经由另一台机器打开的页面不能再打开第三台。

所有流量都不经过 tailnet 以外的服务器。

浏览器面板：DSH 只在桌面 App 自己的配置里加载浏览器，Electron 也只在窗口的主页面里提供 webview，所以窗口框里另一台机器的页面两样都没有。那台机器的入口会把它自己 DSH 安装里的浏览器面板，加到它提供给其他机器的页面里（它自己的页面和手机都不加）。窗口这边的互联把桌面 App 的浏览器借给这个页面，并在窗口里替它创建 webview。那台机器的地址会从本机回环上一个类似 `p5173.x-http.localhost.<机器 id>.localhost:7389` 的名字打开。Chromium 不查 DNS、也不走代理，直接把所有 `*.localhost` 名字送到回环，并把它当作安全上下文。转发端口把请求交给那台机器的入口，由它经自己的网络去取：带着网站自己的 `Host`、`Origin`、`Referer`，也带着 cookie。回来时，跳转、CORS、CSP，以及页面和脚本里写死的回环地址（`http://localhost:3000`、`ws://127.0.0.1:24678`）都改指向这些名字；cookie 像在那台机器上一样，同一主机名的各个端口共用。一个 https 地址如果是普通 HTTP 服务在回应（DSH 的地址栏会把 `localhost:5173` 补成 https），会自动转到它的 http 地址。

本机 DSH 上的其他插件可以通过 `dshLink` 服务（版本 1）访问各机器：机器列表，以及经机器的监听端口向它的 DSH 发 GET 请求（用那台机器自己的登录）。使用量统计就用它。

## 设置

1. 在每台电脑上安装 **互联**（DSH Link）（插件市场或 `.tgz`），然后重启那台的 DSH。
2. 同一 Tailscale 账号下运行着本插件的其他电脑，半分钟内会出现在切换器里。

配置项（插件 → 互联）：

| 配置 | 默认 | |
| --- | --- | --- |
| `name` | Tailscale 机器名 | 其他机器上显示的名字 |
| `port` | `7390` | 各台机器必须一致才能自动发现 |
| `listen` | 开 | 允许其他机器打开本机的 DSH |
| `discover` | 开 | 从 `tailscale status` 里发现同一账号的电脑 |
| `peers` | 无 | 手动添加的机器地址，如 `http://100.96.195.115:7390` |
| `tailscale` | 自动查找 | `tailscale` 命令的路径（macOS App 把它放在 App 包里） |
| `refreshSeconds` | `30` | 多久检查一次其他机器 |
| `frameBrowser` | 开 | 给其他机器的页面提供浏览器面板，并转发它们的地址 |
| `browserPort` | `7389` | 浏览器面板在本机回环上用来打开其他机器地址的端口（被占用时依次往后找，最多 +10；用过的端口会记住） |

`allowSelf` 和 `listenHost` 只用于测试时在一台电脑上跑两个 DSH。

## 限制

- 任何登录了你 Tailscale 账号的设备都能完全控制装了本插件的 DSH。
- 在桌面 App 里，拖入、粘贴或用「+」选给另一台机器的文件会上传到那台机器（不然 DSH 写的是本机路径，那边读不到）。文件夹不能这样发送，拖入时会提示。
- 另一台机器页面上的插件访问的是那台机器：插件按绝对路径发的请求（`fetch('/api/…')`、XMLHttpRequest、EventSource、beacon）都经它的挂载转过去。DSH 自己的事件流以外的插件 WebSocket，以及插件按绝对路径加载的图片和脚本，仍来自本机。
- 手机页面关闭时收不到通知。
- 经普通 `http://` 地址（HTTP/1.1）打开时，除非在设置里打开，否则不保留页面：浏览器对一台主机最多开 6 个连接，两个 DSH 页面就会占满。
- 每台保留着的机器页面会像多开一个浏览器标签页那样占用内存；关掉窗口或关闭「在这个窗口里保留各机器的页面」就会释放。
- TUI 对话的状态只能从终端看出来：中途停止或失败的也算「已完成」，它的审批不会作为待处理出现在提醒里。
- 两台电脑都要装这个版本：切出去的那台负责保留各页面，被切到的那台页面里的切换也要靠新版。另一台还是旧版时也能用，只是从它切走时会重新加载一次。
- Windows 和 systemd 服务不能从页面重启。
- 另一台机器页面上的浏览器面板需要桌面 App，两台电脑也都要装 0.1.12 或更新版本。用浏览器或手机看另一台机器时，那里没有这个面板。
- 转发端口只监听本机回环，也只回应这些名字。来自其他网站的请求会被拒绝，除非那个网站本身也是这样的名字，所以本机浏览器里打开的网页没法借用它。任何登录了你 Tailscale 账号的设备，本来就能经各台机器的入口访问它们的网络。
- 这样打开的页面，看到自己的地址是那个很长的 `*.localhost` 名字：判断 `location.hostname === 'localhost'` 的代码会得到不同结果；页面脚本自己设的 cookie 只留在那个端口（服务端设的 cookie 各端口共用）。
- 页面用脚本拼出来的、指向那台机器另一个地址的链接，会先在本机试一下，再改从那台机器打开。
- 另一台机器页面里的浏览器打不开本机自己的 `localhost`，要用就回到本机自己的页面。
- 那里的面板是 DSH 自带的，改了三处来使用窗口的浏览器。如果 DSH 更新改动了这几处，那台机器上就不显示这个面板，DSH 日志里会写原因。

重启日志：`$DSH_HOME/storages/dsh-link/restart/restart.log`。

思路和桌面窗口的启动握手处理参考了 [Kivotos](https://github.com/dsh-labs/kivotos)（Apache-2.0），见 THIRD_PARTY_NOTICES.md。
